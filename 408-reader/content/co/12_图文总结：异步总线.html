我们知道同步定时适用于总线长度较短、各设备存取时间比较接近的情况，所以它有一定的局限性，不太灵活；而异步定时克服了同步定时的缺点，它允许总线上的设备存储时间不一致

异步定时不需要时钟信号的控制，它采用的是应答方式，也称握手方式，采用异步定时的总线，也就是异步总线

在异步总线中，后一个操作事件出现在总线上的时刻取决于前一个操作事件出现的时刻

假设主设备和从设备通过总线连接，现在主设备需要和从设备通信，并且已经拿到了总线的控制权，如下图：

主设备先将地址发送到地址线，等待地址信号稳定后，再通过请求控制线，发送读命令请求信号给从设备，从设备经过内部的一系列操作，将地址对应的数据放到数据线上，等待数据线上的信号稳定后，然后从设备通过一根应答控制线，给主设备发送确认信号，通知主设备数据有效

然后主设备读取数据线上的数据，一旦读完，就会撤销读命令信号从而引起从设备撤销确认信号和数据线上的数据，确认信号的撤销又使得主设备撤销地址信号，可以看出，异步定时中，后一个操作事件出现在总线上的时刻取决于前一个操作事件出现的时刻

异步总线的应答方式

异步总线的应答方式又可分为不互锁、半互锁和全互锁三种类型


1. 不互锁方式

主设备发送请求后，不用等待从设备的应答信号，而是等过一小段时间后，直接撤销请求信号，然后主设备就可以去干其他的事情了

从设备接收到请求信号后，根据请求做一些操作，可能是将主设备要的数据，放到数据线上，然后就给主设备发送应答信号，告诉主设备，数据准备好了，然后过一小段时间，就撤销掉应答信号，这时从设备就可以做其他的事情

所以，这个时候，你的从设备慢点无所谓，也就说异步定时允许不同速度的设备之间通信

主设备收到应答后，可以去数据线上读取数据，可以看出通信双方都没有互锁，意思就是当主设备给从设备发送请求，不用等到从设备的应答就可以去干其他的事情，而从设备给主设备发送完应答信息后，也可以去干其他的事情

这种不互锁方式是最宽松的，主设备和从设备各干各的，来看一个主设备读从设备数据的具体例子：

  1. 主设备发读请求信号（Req），同时启动10ms 定时器（约定延时）

  2. 定时器到（10ms 后），主设备直接撤销 Req，去处理其他任务（比如刷新屏幕），不管从设备有没有应答

  3. 从设备收到 Req 后，准备数据（比如从内存读 1 字节），准备好后发应答信号（Ack），同时启动8ms 定时器

  4. 定时器到（8ms 后），从设备直接撤销 Ack，去处理其他任务（比如更新传感器数据），不管主设备有没有读数据

  5. 主设备在 10ms 内若收到 Ack，就读数据；没收到就判定超时，后续重试

不互锁特点：速度快，但可靠性低，适合低速率、短距离、干扰小的简单场景（如简单单片机间的低速通信）

比如发送方将数据发送到总线上后，不管接收方是否已经接收并处理完数据，就会继续发送下一个数据

接收方也只是在自己方便的时候去总线上读取数据，不向发送方反馈任何信息，由于发送方不等待接收方的确认就继续发送数据，如果接收方因为某些原因（如忙于处理其他任务、接收缓冲区已满等）未能及时接收当前数据，那么该数据就可能会被覆盖或丢失，因此不（非）互锁方式的可靠性很差


2. 半互锁方式

在半互锁方式中，当主设备发出请求信号后，一定要等从设备发送了应答信号后，才可以撤销请求信号，而从设备不用等到主设备撤销请求信号，就可以撤销应答信号

这种半互锁方式就是主设备等从设备，从设备不等主设备，来看一个主设备往从设备中写数据的具体例子：

  1. 主设备把数据放到总线上，发写请求信号（Req），一直等待 Ack，不做其他事

  2. 从设备收到 Req，接收数据并写入寄存器，准备好后发应答信号（Ack），通知主设备 "写完成"

  3. 主设备收到 Ack，立即撤销 Req，去处理其他任务

  4. 从设备发完 Ack 后，不用等主设备撤销 Req，直接撤销 Ack，去处理其他任务（比如响应其他设备请求）

半互锁特点：可靠性比不互锁高，效率也不错，适合中等速率、对可靠性有一定要求的场景（如单片机与简单外设的通信）


3. 全互锁方式

在全互锁方式中，主设备发送请求信号，一定要等从设备发送了应答信号后，才可以撤销请求信号

并且一定要等主设备的请求信号撤销了，从设备才可以撤销应答信号

如果这时主设备没有撤销请求信号，从设备也不能撤销应答信号，它俩相当于互相锁住了，只有主设备撤销了请求信号，从设备才可以撤销应答信号

全互锁方式最严格，主从设备要相互等待，来看一个主设备与高速从设备传输数据的具体例子：

  1. 主设备发读请求信号（Req），一直等待 Ack，不做其他事

  2. 从设备收到 Req，准备数据（比如从高速缓存读数据），准备好后发应答信号（Ack），一直等待 Req 撤销，不做其他事

  3. 主设备收到 Ack，读取数据，确认无误后撤销 Req

  4. 从设备检测到 Req 撤销，才撤销 Ack，双方都回到空闲状态，再处理其他任务

全互锁特点：可靠性最高，时序最严谨，适合高速、长距离、干扰大的关键场景（如工业控制总线、高速外设通信），但效率最低（因为互相等待）

三种方式核心对比（一句话总结）

  • 不互锁：主从都不等，靠延时，快但不可靠

  • 半互锁：主等从，从不等主，平衡效率与可靠性

  • 全互锁：主从互相等，靠握手，可靠但效率低

异步总线两种传输方式

如果异步总线是并行传输数据的话，那么称为异步并行总线；如果异步总线是串行传输数据的话，那么称为异步串行总线


1. 异步并行总线

当两个设备的速度相差比较大的时候，那么连接这两个设备的总线一般会使用异步定时，在以前，CPU 和主存储器两个部件的速度相差非常大，所以，在以前，CPU 和主存储器之间的存储器总线就使用的是异步并行总线，如下图：

首先数据线就是并行传输的，一般一次性传输多位，然后 CPU 和主存储器之间采用应答方式的异步定时

CPU 要读取主存中的数据，首先将地址发送到地址线上，然后通过请求制线发送读请求命令信号，这个时候，请求信号不能撤销，也就是说 CPU 这个时候不能去执行其他的指令，必须在这里等待主存储器的应答，主存储器收到命令后，才是准备数据，经过一段时间，数据准备好，放到数据总线上，然后通过应答控制线给 CPU 发送应答信号，也就是发送 MFC 信号

MFC，是 Memory Function Completed 的缩写，意思是存储功能完成

注意，CPU 在未接收到主存储器的应答时，就是一直在检测这个 MFC 是否有效，如果 MFC 有效，就可以去数据线上读取数据，在 CPU 读取数据之前，主存储器的应答信号是可以撤销的，然后 CPU 再去读取数据，最后撤销请求信号

这里很明是半互锁的异步定时方式，不过在这种方式下，主存储器在准备数据的时候，CPU 需要等待，不能执行其他的指令，这影响了 CPU 的性能，后来，主存储器的速度提高了，然后 CPU 和主存储器之间就使用同步定时的方式了


2. 异步串行总线

再来看一个例子，CPU 和 I/O 设备通信，一般来说，CPU 执行指令的速度是非常非常快的，而 I/O 设备的读写速度相对慢很多的，那么对于这种速度相差很多的两个设备通信的话，那肯定要用异步通信了

比如现在 CPU 要读取硬盘中的一些数据，那么 CPU 首先通过请求控制线给硬盘发送读数据的请求命令，硬盘收到命令后，开始准备数据，这个时候 CPU 的读请求信号是可以撤销，CPU 去执行其他的指令

硬盘准备好数据后，通过应答控制线再给 CPU 发送一个应答信号，这个应答信号称为中断信号，CPU 收到中断信号后，就可以去硬盘中读取数据了，当然这里的应答信号在读数据之前就可以撤销的，所以这里采用就是不互锁的异步定时方式

现代的 I/O 总线一般使用串行传输数据（比如 USB 总线、PCIe 总线），所以，上面的场景就是异步串行通信了

PCI 总线是同步并行总线

异步串行通信中，不需要同步时钟，而是以字符为单位进行传输，字符有特定的格式，如下图：

一般而言，一个字符包含一个起始位，用低电平 0 来表示，包括 5 ~ 8 个数据位，1 个奇偶检验位，用于检错用，还包含 1 个或者 1.5 个或者 2 个终止位，终止位一般使用高电平 1 表示这一个字符格式，我们也可以将上面的格式称为一帧

来看一个例子：画图说明用异步串行传输方式发送十六进制数据 95H。要求字符格式为：1 位起始位、8 位数据位、1 位偶校验位、1 位终止位

我们可以将 95H 画成如下图格式：

首先 95H 对应的二进制是 10010101，这 8 个就是数据位了，然后一个起始位 0，这里使用偶检验，而数据位中有 4 个 1，是偶数，所以偶检验位是 0，还有一个停止位 1

如果画成电信号就是，起始位低电平，高电平、低电平、高电平.... 校验位是低电平、终止位高电平，当接收端收到起始位时，然后往后接收 8 个数据位，再利用校验位对数据进行奇偶校验，最后遇到终止位时，表明接收到一个字符了

另外两种总线定时方式


在总线定时方式中，除了同步定时和异步定时，还有另外两种定时方式：半同步定时方式和分离式定时方式


1. 半同步定时方式

半同步定时方式既保留了同步定时的基本特点，如所有的地址、命令、数据信号的发出时间，都严格参照总线时钟的同步控制；同时又像异步定时那样，允许不同速度的模块和谐地工作

为此增设了一条 "等待" (WAIT) 响应信号线，采用插入时钟 (等待) 周期的措施来协调通信双方的配合问题

我们以总线读为例，正常情况下，在同步定时中，主设备在 T₁ 时钟周期发出地址，在 T₂ 时钟周期发出命令，在 T₃ 时钟周期传输数据，在 T₄ 时钟周期结束传输

倘若从设备工作速度较慢，无法在 T₃ 这个时钟周期提供数据，则必须在 T₃ 到来前通知主设备，通过 "等待" (WAIT) 响应信号线给主设备出 WAIT (低电平有效) 信号，看下图：

若主设备在 T₃ 时钟周期到来时刻测得 WAIT 信号为低电平，就插入一个等待周期 TW (其宽度与时钟周期一致)，不立即从数据线上取数

若主设备在下一个时钟周期到来时刻又测得 WAIT 信号为低电平，就再插入一个 TW 等待，这样一个时钟周期、一个时钟周期地等待，直到主模块测得 WAIT 信号为高电平时，主设备即把此刻的下一个时钟周期当作正常周期 T₃，即时获取数据，T₄ 结束传输

从上图可见，半同步通信时序可为以下形式：

  • T₁ 主设备发出地址信息

  • T₂ 主设备发出命令

  • TW 当 WAIT 信号为低电平时，进入等待，TW 的宽度与 T 的宽度一致

  • ....

  • T₃ 从设备提供数据

  • T₄ 主设备撤销读命令，从设备撤销数据

半同步通信适用于系统工作速度不高但又包含了由许多工作速度差异较大的各类设备组成的简单总线系统

半同步定时控制方式比异步定时简单，在全系统内各设备又在统一的系统时钟控制下同步工作，可靠性较高，同步结构较方便。其缺点是对系统时钟频率不能要求太高（因为存在低速设备），故从整体上来看，系统工作的速度还不是很高


2. 分离式定时方式

前面说的同步定时、异步定时和半同步定时这三种定时方式都是从主设备发出地址和读写命令开始，直到数据传输结束。在整个总线传输周期中，系统总线的使用权完全由占有使用权的主设备和由它选中的从设备占据

进一步分析总线读的总线传输周期，发现除了总线申请分配这一阶段外，其余时间主要花费在如下 3 个方面：

  1. 主设备通过总线向从设备发送地址和命令

  2. 从设备按照命令进行读数据的必要准备

  3. 从设备经数据总线向主设备提供数据

上面的第 2 个步骤，对系统总线而言，从设备内部读数据过程并无实质性的信息传输，总线纯属空闲等待

为了克服和利用这种消极等待，尤其在大型计算机系统中，总线的负载已处于饱和状态，充分挖掘系统总线每瞬间的潜力，对提高系统性能起到极大作用

为此人们又提出了 "分离式" 的通信方式，其基本思想是将一个总线周期分解为两个子周期

① 第一个子周期中，主设备 A 在获得总线使用权后将命令、地址以及其他有关信息，包括该主设备编号 (当有多个主设备时，此编号尤为重要) 发到系统总线上，经总线传输后，由有关的从设备 B 接收下来。主设备 A 向系统总线发布这些信息只占用总线很短的时间，一旦发送完，立即放弃总线使用权，以便其他设备使用

② 第二个子周期中，当 B 设备收到 A 设备发来的有关命令信号后，经选择、译码、读取等一系列内部操作，将 A 设备所需的数据准备好，便由 B 设备申请总线使用权，一旦获准，B 设备便将 A 设备的编号、B 设备的地址、A 设备所需的数据等一系列信息送到总线上，供 A 设备接收

很明显，上述两个传输子周期都只有单方向的信息流，每个设备都变成了主设备

这种通信方式的特点如下：

  1. 各设备欲占用总线使用权都必须提出申请

  2. 在得到总线使用权后，主设备在限定的时间内向对方传送信息，采用同步方式传送，不再等待对方的回答信号

  3. 各设备在准备数据的过程中都不占用总线，使总线可接受其他设备的请求

  4. 总线被占用时都在做有效工作，或者通过它发送命令，或者通过它传送数据，不存在空闲等待时间，充分地利用了总线的有效占用，从而实现了总线在多个主、从设备间进行信息交叉重叠并行式传送，这对大型计算机系统是极为重要的

当然，这种方式控制比较复杂，一般在普通微型计算机系统很少采用
