Cache 读的操作非常简单，首先，根据主存地址在 Cache 中寻址到所需字 w，如果命中，理解返回字 w 给 CPU，如果不命中，则从主存中取出包含字 w 的主存块，将这个主存块放到 Cache 的某个行中（可能会替换掉一个有效的行），同时主存地址对应字 w 给到 CPU
Cache 写的操作就要复杂一点，如果写一个已经缓存了的字 w（即写命中），在 Cache 中更新好了这个字 w 之后，此时 Cache 中的这个字 w 和主存中的这个字 w 数据就不一致了
如何保持 Cache 和主存的数据一致呢？

全写法（直写法）

最简单的方法就是全写法：就是 Cache 写操作时，若写命中，则同时写 Cache 和主存，若写不命中（就是要写的字 w 不在 Cache 中，而是在主存中），则可以采用写分配法和非写分配法这两种方法


所谓 Cache 写操作就是 CPU 执行指令去写 Cache，比如 int a = 10 这个语句对应的指令是  mov 10, DWORD PTR[rbp - 48]，当 CPU 执行这条指令时，就会将 10 写到 Cache 对应的位置上，这就是 Cache 写
写分配法：先更新主存中的字 w，然后分配一个 Cache 行，将字 w 所在的主存块装入到分配的 Cache 行中。写分配法可以充分利用空间局部性，但每次写不命中都要从主存读一个主存块到 Cache 中，增加了读主存块的开销
非写分配法：仅仅更新主存中的字 w，而不装入字 w 所在的主存块到 Cache 中。这种方式可以减少读入主存块的时间，但没有很好地利用空间局部性
由此可见，全写法实际上采用的是对主存块信息及其所有副本信息全都直接同步更新的做法，因此，该方式通常也被称为通写法或直写法，也有教材称之为写直达法
显然，采用全写法使得 Cache 和主存的一致性能得到充分保证，但是，这种方法会大大增加写操作的开销
例如，假定一次写主存需要 100 个 CPU 时钟周期，那么 10% 的存数指令就使得 CPI 增加了 100 × 10% = 10 个时钟
为了减少写主存的开销，通常在 Cache 和主存之间加一个写缓冲 (write buffer)。在 CPU 写 Cache 的同时，也将信息写入写缓冲，然后由存储控制器将写缓冲中的内容写入主存
写缓冲是一个 FIFO 队列，只有少量空间，在写操作频率不是很高的情况下，因为 CPU 只需将信息写入快速的写缓冲而无须写入慢速的主存，因而效果较好。但是，如果写操作频繁发生，则会使写缓冲饱和而发生阻塞

回写法（写回法）

另一种保持 Cache 和主存之间数据一致性的方法就是回写法：当 CPU 执行写操作时，若写命中，则信息只被写入 Cache 而不被写入主存；若写不命中，则 Cache 中分配一行，将要写入的字 w 所在的主存块装入到该 Cache 行中，并更新相应的字 w 的内容
可以看到，回写法方式下，如果写不命中的话，通常采用写分配法进行写操作
在 CPU 执行写操作时，回写法不会更新主存单元，只有当 Cache 行中的主存块被替换时，才将该主存块内容一次性写回主存
这种方式的好处在于减少了写主存的次数，因而大大降低了主存带宽的需求
为了减少写回主存块的开销，每个 Cache 行设置了一个修改位（也称为脏位），如果修改位为 1，则说明对应的 Cache 行中的主存块被修改过，替换时需要写回主存；若修改位为 0，则说明对应主存块未被修改过，替换时无需写回主存
到现在为止，Cache 中的每一行的标志区，肯定包含标记 Tag 位和有效位，如果 Cache 采用 LRU 替换算法，则还有 LRU 位，如果 Cache 采用回写法保证数据一致性的话，那么还有 1 位修改位（或者说脏位）
由于回写法没有同步更新 Cache 和主存内容，所以存在 Cache 和主存内容不一致而带来的潜在隐患，即存在数据安全问题。通常需要其他的同步机制来保证存储信息的一致性（比如 X86 的 MESI 缓存一致性协议，这个我们不需要去了解了）

总结下：


  • 全写法：写命中的话，同时更新 Cache 和主存；写不命中的话，可以采用写分配法或者非写分配法

  • 回写法：写命中的话，只更新 Cache 而不更新主存，只有当 Cache 行的主存块替换时，根究修改位来决定是否要将主存块写回到主存；写不命中的话，一般采用写分配法
