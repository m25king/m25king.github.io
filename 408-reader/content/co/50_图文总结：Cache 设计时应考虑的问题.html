决定系统访存性能的重要因素之一是 Cache 命中率，命中率与关联度有关，同时也和 Cache 容量有关
显然，Cache 容量越大，命中率就越高。此外，命中率还与主存块大小有一定的关系。大主存块能很好地利用空间局部性，但是，主存块越大，其缺失损失也越大（读取一个主存块需要的时间就多）。因此，主存块大小必须适中
除上述提到的这些问题外，设计 Cache 时还要考虑：
  • 采用单级还是多级 Cache
  • 数据 Cache 和指令 Cache 是分开还是合在一起
  • 主存 - 总线 - Cache - CPU之间采用什么架构
  • DRAM 芯片的内部结构、存储器总线的总线事务类型
这些都与 Cache 设计有关，都会影响系统总体性能，我们分别来看

单级/多级 Cache、联合/分离 Cache 的选择问题

早期采用的是单级片外 Cache，就是只有 1 个 Cache，并且这个 Cache 位于 CPU 外部，在 CPU 和主存之间
现在基本都是采用多级片内 Cache，目前 Cache 都在 CPU 芯片内，且使用 L1 和 L2 Cache，甚至有 L3 Cache
在一个采用两级 Cache 的系统中，CPU 总是先访问 L1 Cache，若访问缺失，再从 L2 Cache 中找。若 L2 Cache包含所请求的信息，则缺失损失为 L2 Cache 的访问时间，这比访问主存要快得多；若 L2 Cache 访问缺失，则需从主存取信息并同时送 L1 Cache 和 L2 Cache，此时缺失损失较大

如下图是 Intel Core i7 处理器的高速缓存层次结构：



上面就是 3 级 Cache，所有的 Cache 都位于 CPU 芯片内，上图每个 CPU 芯片有四个核。每个核有自己私有的 L1 i-cache、L1 d-cache 和 L2 统一的高速缓存。所有的核共享片上 L3 统一的高速缓存
通常 L1 Cache 采用分离 Cache，即数据 Cache（上图的 d-cache）和指令 Cache（上图的 i-cache）分开，是两个不同的 Cache，而 L2 和 L3 Cache 为联合方式，即数据和指令放在一个 Cache 中
L1 Cache 分为数据 Cache 和指令 Cache 的原因有很多
i-cache 通常是只读的，因此比较简单。通常会针对不同的访问模式来优化这两个高速缓存，它们可以有不同的块大小，相联度和容量；使用不同的 Cache 也确保了数据访问不会与指令访问形成冲突不命中（可以消除流水线 CPU 中的结构冒险，这个我们在 【流水线冒险之结构冒险】有详细学习）

在多级 Cache 中，有全局缺失率和局部缺失率两种不同的概念：
  • 全局缺失率是指在所有级 Cache 中都缺失的访问次数占总访问次数的比例
  • 局部缺失率是指在某级 Cache 中缺失的访问次数占对该级 Cache 的总访问次数的比例
例如，对于两级 Cache，若 CPU 总的访存次数为 100，在 L1 Cache 命中的次数为 94，剩下的 6 次中在 L2 Cache 命中的次数为 5，只有 1 次需要访问主存，则全局缺失率为 1 / 100 = 1%
L1 Cache 的访问总次数是 100，缺失次数是 6，因此其局部缺失率 =  6 / 100 = 6%
因为 100 次访问中，94 次都命中 L1 Cache，所以只有 6 次需要访问 L2 Cache，而 L2 Cache 的缺失次数是 1，因此，L1 Cache 的局部缺失率 = 1 / 6 ≈ 16.7%

主存 - 总线 - Cache 之间的连接结构问题

为了计算主存块传送到 Cache 所用的时间，必须先了解 CPU 从主存取一块信息到 Cache 的过程。从主存读一块数据到 Cache，一般包含以下 3 个阶段：
（1）发送地址和读命令到主存：假定用 1 个时钟周期
（2）主存准备好一个数据：假定用 10 个时钟周期
（3）从总线传送一个数据：假定用 1 个时钟周期
主存、总线和 Cache 之间可以有 3 种连接方式：窄形结构、宽形结构以及多模块交叉存取结构

1. 窄形结构

就是每次按一个字的宽度进行传送，假设一个主存块有 4 个字，下图是窄形结构传输一个主存块（4 个字）的过程：

这里连续进行 "送地址 → 读出 → 传送" 4 次，每次传输一个字，其缺失损失为 4 × (1 + 10 + 1) = 48 个时钟周期

2. 宽形结构

就是每次传送多个字，假设一个主存块有 4 个字，然后每次传送 2 个字，下图是宽形结构传输一个主存块（4 个字）的过程：

这里连续进行 "送地址 → 读出 → 传送" 2 次，每次传输 2 个字，其缺失损失为 2 × (1 + 10 + 1) = 24 个时钟周期
假定增加数据总线条数以及总线接口部件，使得每次可传送 4 个字，那么缺失损失可以减少为 1 × (1 + 10 + 1) = 12 个时钟周期

3. 多模块交叉存取结构

就是轮流启动多个存储体进行读写，按一个字的宽度进行传送，假设一个主存块有 4 个字，下图是多模块交叉存取结构传输一个主存块（4 个字）的过程：

这里，在首地址送出后，每隔 1 个时钟周期轮流启动一个存储模块，每个模块都用 10 个时钟周期准备好一个字，然后送总线进行传送，因此缺失损失为 1 + 1 × 10 + 4 × 1 = 15 个时钟周期

DRAM 结构、总线事务类型与 Cache 的配合问题


指令执行过程中，若发生 Cache 缺失，则要从 DRAM 中读取一块信息到 Cache，因此，如何合理设计 DRAM 结构，如何使存储器总线在一次总线事务中高效地传输一个主存块，这些都是需要和 Cache 设计统一考虑的问题
下图所示的存储器总线宽度为 128 位，即连接在其上的每个内存条一次最多能读出 128 位的数据：
每个内存条上排列有多个 DRAM 芯片。上图用 16 个 2Mb 的 DRAM 芯片配置一个 4MB 的内存条，每个芯片内有一个 512×8 位的 SRAM 行缓冲，16 个芯片共 8KB 缓冲
每个芯片每次读写芯片内同行同列的 8 位，16 个芯片共 16 × 8 = 128 位
当 CPU 访问一块连续的主存区域 (即行地址相同的区域) 时，可直接从行缓冲读取，行缓冲用 SRAM 实现，速度极快
当 Cache 缺失而要求从主存读一块信息到 Cache 时，只要给定一个首地址，采用突发传输的方式就可以在一次总线事务中完成一个主存块的传输
特别是当采用 DDR SDRAM、DDR2 SDRAM 或 DDR3 SDRAM 芯片时，在芯片内部采用多模块交叉多数据预取，并在存储器总线上采用时钟上升沿和下降沿各传送一次的方式，使得从主存到 Cache 的数据块传送效率更高
