前面我们讨论的都是在大小相同的数据类型之间进行转换，比如将 16 位的 unsigned short 转换成 16 位的 short，将 32 位的 int 转换位 32 位的 unsigned int
很多时候，还需要在不同大小的数据类型之间进行转换，这个时候，就会用到位扩展和位截断了

位扩展

位扩展又分为零扩展和符号扩展
如果将一个无符号数转换成一个更大的无符号类型的话，就需要执行零扩展，看下图：

上图定义一个无符号短整型数 53191u，其对应的无符号编码是 1100 1111 1100 0111，然后将这个无符号数转换为更大的无符号长整型数据（unsigned int），只需要简单的在短的无符号编码之前添加 0 ，一直达到对应的长度（32 位）为止，这个就是零扩展，经过零扩展后，其数值还是等于短整型的数值 53191
如果将一个有符号数转换成一个更大的数据类型的话，就需要执行符号扩展，看下图：

定义一个短整型有符号数 -12345，其对应的补码是 1100 1111 1100 0111，现在将其转化为长整型的有符号数，那么只需要在短整型补码的前面添加符号即可，因为短整型的符号是 1，所以这里添加 1 ，直到 32 位为止
这就是符号扩展，符号扩展后的二进制串仍然是补码，它的值还是 -12345（在求补码表示的整数时，可以忽略高位连续的 1，只保留 1 个 1）

因为 short 类型的 12345 的符号位是 0，所以，进行符号扩展时，就是扩展 0 了
从上面可以看到，不管是零扩展还是符号扩展，扩展后表示的整数值都是不变的
值得一提的是，从一个数据大小到另一个数据大小的转换，以及无符号和有符号数字之间的转换的相对顺序能够影响一个程序的行为，看下图：

这里，将 short 类型的 sx 转换位 unsigned int 类型，首先数据大小变大了（从 16 位到 32 位），其次从有符号数转换为无符号数，这个时候就需要注意转换顺序了

在 C 语言标准中规定，如果同时涉及到大小转换和符号转换，那么需要先进行数据大小的转换，再进行符号类型转换


这里的 unsigned int 等价于，先将 short 转化为 int ，然后再将 int 转换为无符号数，而不是等价于先转换为无符号短整型，再转化为无符号长整型

上面先对 sx 进行符号扩展，得到 32 位补码 1111 1111 1111 1111 1100 1111 1100 0111，然后将其解释成无符号整数，即 2^32 - 1 - 2^13 - 2^12 - 2^5 - 2^4 - 2^3 = 4294967296 - 1 - 8192 - 4096 - 32 - 16 - 8 = 4294954951

再来看一个 C 语句：unsigned short us = -9，请问 us 的机器数是多少？us 的值是多少？
首先，在 C 语言中，一个整数常量默认是 int 类型的，比如上面的 -9 是 int 类型的，那么执行 unsigned short us = -9 的话，就是将 32 位的补码表示的 -9 转换成 16 位的 unsigned short 了，这里同时涉及到了大小转换和符号转换
在 C 语言标准中规定，如果同时涉及到大小转换和符号转换，那么需要先进行数据大小的转换，再进行符号类型转换
所以，先进行大小转换，将 int 转换成 short 类型，进行位截断即可，因为 -9 = -16 + 4 + 2 + 1 = -2^4 + 2^2 + 2^1 + 2^0，所以 -9 的补码是 1 0111，符号扩展成 32 位，得到 -9 的 32 位补码是 FFFF FFF7H，再将其高 16 位截断，得到 us 的机器数就是 FFF7H，其补码表示的值还是 -9
接下来，在进行符号转换，将 16 位补码 -9 转换成 16 位无符号数，因为  -9 < 0，所以无符号数 us = -9 + 2^16 = -9 + 65536 = 65527
对于补码转换成无符号整数，有一个更便捷的方法：
  • 当 v < 0 时，那么 uv = v + 2n，其中 n 是补码的位数
  • 当 v ≥ 0 时，那么 uv = v
