假定某计算机的 Cache 采用直接映射方式，和主存交换的数据块大小为 1 个字，按字编址，一共能存放 16 字的数据。CPU 开始执行某程序时，Cache 为空，在该程序执行过程中，CPU 依次访问以下地址序列：2，3，11，16，21，13，64，48，19，11，3，22，4，27，6，11。请回答下列问题：
(1) 每次访问在 Cache 中是命中还是缺失？试计算访问上述地址序列的 Cache 命中率。
(2) 若 Cache 数据区容量还是 16 字，而数据块大小改为 4 字，则上述地址序列的命中情况又如何？说明块大小和命中率的关系。

假定某计算机的主存地址空间大小为 64KB，按字节编址；Cache 采用 4 路组相联映射、LRU 替换和写回 (write back) 策略，能存放 4KB 数据，主存与 Cache 之间交换的主存块的大小为 64B。请回答下列问题：
① 主存地址字段如何划分？要求说明每个字段的含义、位数和在主存地址中的位置。
② Cache 的总容量有多少位？
③ 若 Cache 初始为空，CPU 依次从 0 号地址单元顺序访问到 4344 号单元，共重复访问 16 次。Cache 存取时间为 20ns，主存存取时间为 200ns，试估计 CPU 访存的平均时间。

① Cache 采用 4 路组相联映射，所以 Cache 将主存地址划分为标记 Tag、组索引以及块内地址三个字段

因为主存块大小为 64B，按字节编址，所以块内地址的位数 = log2(64) = 6

Cache 能存放 4KB 数据，每个 Cache 行大小是 64B，因此 Cache 总行数 = 4KB / 64B = 64，Cache 采用 4 路组相联映射，即每组有 4 行，因此，Cache 组数 = 64 / 4 = 16，因此组索引的位数 = log2(16) = 4

主存地址空间大小为 64KB，按字节编址，所以主存的地址数量是 64K，那么主存地址的位数 = log2(64K) = 16

标记 Tag 的位数 = 主存地址的位数 - (块内地址的位数 + 组索引的位数) = 16 - (6 + 4) = 6

因此，主存地址有 16 位，其中低 6 位为块内地址，中间 4 位为组号(组索引)，高 6 位为标记


② Cache 总容量 = Cache 标志区容量 + Cache 数据区容量 = Cache 标志区容量 + 4KB

在 Cache 标志区中每一行有以下位：
  • 1 位有效位
  • 6 位标记位
  • 2 位 LRU 位（因为 Cache 采用 LRU 替换，且每组有 4 行，所以 LRU 位数 = log2(4) = 2）
  • 1 位脏位（因为 Cache 采用写回策略）


因此，Cache 标志区容量 = （1 + 6 + 2 + 1）位 × Cache 总行数 = 10 位 × 64 = 80B

所以，Cache 总容量 = Cache 标志区容量 + Cache 数据区容量 = 80B + 4KB = 4176B


③ CPU 在 Cache - 主存层次的平均访问时间为：Ta = p × Tc + (1 - p) × (Tm + Tc) = Tc + (1 - p) × Tm


其中 p 是 Cache 命中率，Tc 是命中时间，而 Tm 是确实损失，在本题中，Tc = Cache 存取时间 = 20ns，Tm = 主存存取时间 = 200ns

所以说，要求 CPU 访存的平均时间 Ta，就要求出 Cache 的命中率 p，而 Cache 命中率 p = Cache 命中次数 / 总的访问次数

 因为 CPU 依次从 0 号地址单元顺序访问到 4344 号单元，共重复访问 16 次，所以总的访问次数 = 4345 × 16 = 69520

所以，接下来只要求出 Cache 命中次数即可

首先，我们需要计算出 0 号地址到 4344 号地址单元位于哪些主存块中，将 4344 除以主存块大小 = 4344 / 64B = 67 ，那么地址 4344 位于 67 号主存块中，那么 0 号地址到 4344 号地址单元就位于 0 号主存块到 67 号主存块中（一共是 68 个连续的主存块）


对于每一个主存块，其大小是 64B，即包含了 64 个单元，当 CPU 第一次访问一个主存块中的第一个单元时，那么 Cache 缺失，然后将这个单元所在的主存块装入到某个 Cache 行，接下来 CPU 对这个主存块的其他的 63 个单元的访问，将会全部命中，因此，CPU 第一次访问一个主存块时，其缺失次数是 1，命中次数是 63


接下来，我们需要来看这 68 个主存块具体映射到 Cache 的哪个位置，在这个过程中，可以计算得到 Cache 命中的次数，请看视频讲解：



就是说，第一遍访问的缺失次数数 68 次，接下来的 15 遍每一遍的缺失次数是 20 次，因此，总的缺失次数是 68 + 15 * 20 = 368 次


因此，Cache 命中率 p = Cache 命中次数 / 总的访问次数 = （总的访问次数 - 总的缺失次数）/ 总的访问次数 = (69520 - 368) / 69520 ≈ 99.47%


因此，CPU 平均访问时间为：Ta = Tc + (1 - p) × Tm = 20ns + (1 - 99.47%) × 200ns = 21.06ns

假定某处理器带有一个数据区容量为 256B 的 Cache，主存块大小为 32B。以下C语言程序段运行在该处理器上，sizeof(int)=4，编译器将变量 i、j、c、s 都分配在通用寄存器中，因此，只要考虑数组元素的访存情况，假定数组起始地址正好在一个主存块的开始处。若 Cache 采用直接映射方式，则当 s = 64 和 s = 63 时，缺失率分别为多少？若 Cache 采用 2 路组相联映射方式，则当 s = 64 和 s = 63 时，缺失率又分别为多少?

因为块大小为 32B，数组起始地址正好是一个主存块的开始，所以每 8 个数组元素占一个主存块，为了方便理解，我们可以假设数组的第一个主存块就是 0 号主存块


Cache 共有 256B/32B = 8 行，在 2 路组相联映射时，Cache 有 4 组。以下仅考虑数组访问情况



① 直接映射，s = 64 时，数组访存顺序为 a[0]、a[64]；a[0]、a[64]；…，共循环 10000 次


a[0] 位于数组的 0 号主存块；a[64] 所在的主存块块号是 (64 * 4B) / 32B = 8


a[0] 所在主存块映射到的 Cache 行行号 = 0 % 8 = 0


a[64] 所在主存块映射到的 Cache 行行号 = 8 % 8 = 0


即在直接映射方式下，a[0] 所在主存块和 a[64] 所在主存块正好被映射到同一个 Cache 行，因而每次都会发生冲突，其缺失率为 100%


② 直接映射，s = 63 时，数组访存顺序为 a[0]，a[63]，a[126]；a[0]，a[63]，a[126]；…，循环 10000 次


a[0] 位于数组的 0 号主存块；a[63] 所在的主存块块号是 (63 * 4B) / 32B = 7；a[126] 位于的主存块块号 = (126 * 4B) / 32B = 15


a[0] 所在主存块映射到的 Cache 行行号 = 0 % 8 = 0


a[63] 所在主存块映射到的 Cache 行行号 = 7 % 8 = 7


a[126] 所在主存块映射到的 Cache 行行号 = 15 % 8 = 7


那么 a[63] 所在主存块和 a[126] 所在主存块都映射到同一个 Cache 行，因此每次都会发生冲突，而 a[0] 不会发生冲突


所以缺失的次数 = a[0] 缺失 1 次 + 10000 * (a[63] 缺失 1 次 + a[126] 缺失 1 次) = 20001


故缺失率约为 20001 / 30000 ≈ 67%


③ 2 路组相联，s = 64 时，数组访存顺序为 a[0]、a[64]；a[0]、a[64]；…，共循环 10000 次


a[0] 位于数组的 0 号主存块；a[64] 所在的主存块块号是 (64 * 4B) / 32B = 8


a[0] 所在主存块映射到的 Cache 组组号 = 0 % 4 = 0


a[64] 所在主存块映射到的 Cache 组组号 = 8 % 4 = 0


在 2 路组相联映射方式下，这两个元素所在主存块会映射到同一个组，可放在同一组的不同 Cache 行中，所以不会发生冲突


总缺失次数仅为 2 次（a[0] 缺失 1 次 + a[64] 缺失 1 次），缺失率近似为 0


④ 2 路组相联，s = 63 时，数组访存顺序为 a[0]，a[63]，a[126]；a[0]，a[63]，a[126]；…，共循环10000次


a[0] 所在主存块映射到的 Cache 组组号 = 0 % 4 = 0


a[63] 所在主存块映射到的 Cache 组组号 = 7 % 4 = 3


a[126] 所在主存块映射到的 Cache 组组号 = 15 % 4 = 3
