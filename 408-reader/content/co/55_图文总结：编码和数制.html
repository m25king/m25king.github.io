为什么计算机系统使用二进制？

在计算机系统中，不管是磁盘文件、内存中的程序、内存中存放的数据，还是网络上传送的数据，都是由一串二进制位表示的
那么，计算机系统为什么采用二进制的表示方式呢？主要有 3 个原因
第一个，二进制只有 0 和 1 两种基本状态，制造有两个稳定状态的物理器件要比制造有多个稳定状态的物理器件容易得多
比如，我们前面讲静态 RAM 是通过六个晶体管就可以实现表达两个稳定状态，而动态 RAM 只需要一个晶体管和一个电容就可以表达两个稳定状态
第二个，二进制的编码和运算规则都很简单，通过简单的电路就可以实现
第三个，有一整个数学分支存在，专门处理 "真" 和 "假"，它已经证明了所有的二进制运算法则，这个分支叫做布尔代数，是英国科学家乔治·布尔提出的二进制的 1 和 0 刚好与真和假相对应，为计算机实现逻辑运算和程序中的逻辑判断提供了便利的条件，特别是能通过逻辑门电路方便的实现算术运算

什么是编码？

在计算机系统中，如果有一串 32 个二进制数，到底表示什么信息呢？这个取决于这一串二进制所处的上下文，看下图：

如果处于不考虑符号的整数计算的上下文的话，这一串二进制就可以解释成这个整数 3286487986；如果处于考虑符号的整数计算的上下文的话，这一串二进制就可以解释成这个负整数 -1008479310
如果处于小数计算的上下文的话，这一串二进制就可以解释成这个小数 -455.654296875；如果处于网络传输的上下文中，这一串二进制又可以解释成这个 IP 地址（195.227.211.178）
如果处于中文处理的上下文的话，这一串二进制又可以解释成【老汤】这两个中文字符，如果处于 CPU 执行程序的上下文中，这一串二进制又可以解释成一条指令
所以说，在计算机的世界里，信息就是一串二进制位 + 上下文

所谓编码，就是用少量简单的基本符号对大量复杂多样的信息进行一定规则的组合，在计算机系统中，只有 0 和 1 这两种基本符号，那么将信息按照一定的规则组合成二进制串，就是编码的过程
比如上图中，将这个正整数 3286487986 用这串二进制（1100 0011 1110 0011 1101 0011 1011 0010）表示，就是一个编码过程
同样，将其他的信息（比如小数、 IP 地址、汉字、指令等），按照某种规则，组合成对应的二进制串，这些过程，都是编码过程，看下图多种编码方式：

十六进制表示法

因为：
  • ① 二进制表示法太冗长
  • ② 二进制和十进制之间转换很麻烦
所以，在计算机系统中，我们会使用十六进制表示法来替代二进制和十进制
十六进制（英文简称 hex）使用数字 0 ~ 9 以及字符 A ~ F 来表示 16 个可能的值，如下图展示了 16 个十六进制数字对应的十进制值和二进制值（下面的这张表必须记住了）：

每个十六进制数使用 4 位二进制来表示（因为 4 位二进制可以表示的数字个数就是 2^4 = 16），十六进制中的 A ~ F 可以大写也可以小写
一个字节由 8 位组成，在二进制表示法中，它的值域是 0000 0000 ~ 1111 1111，用十进制表示的话，其值域是 0 ~ 255，用十六进制表示的话，一个字节的值域是 00H ~ FFH
我们可以在十六进制数的后面加上大写的 H，表示这是一个十六进制数，在 C 语言中，则是在十六进制数据的前面加上 0x，也是表示这是一个十六进制数
比如 C3E3D3B2H 这是一个十六进制数，在 C 语言中，可以这样写：0xC3E3D3B2 或者 0XC3E3D3B2

进制转换的技巧

当值 x 是 2 的非负整数 n 次幂时，也就是 x=2^n，我们可以很容易地将 x 写成十六进制形式，只要记住 x = 2…^n 的二进制表示就是 1 后面跟 n 个 0
十六进制数字 0 代表 4 个二进制 0。所以，当 n 表示成 i+4j 的形式，其中 0≤i≤3，我们可以把 x 写成开头的十六进制数字为 1（i=0）、2（i=1）、4（i=2）或者 8（i=3），后面跟随着 j 个十六进制的 0
比如，x = 2048 = 2^11，我们有 n = 11 = 3 + 4 * 2，从而得到十六进制表示 0x800
