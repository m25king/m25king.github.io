B.r1 - r2

这题本质上就是考察 8 位补码的表示范围，如果你真的基于二进制进行加减乘除，那么你就会浪费很长时间了


我们知道 8 位补码的表示范围是 -2^7 ~ 2^7 - 1，即 -128 ~ 127


r1 的 8 位补码是 F5H = 1111 0101，其十进制值是 -2^4 + 2^2 + 2^0 = -11；r2 的 8 位补码是 EEH = 1110 1110，其十进制值是 -2^5 + 2^3 + 2^2 + 2^1 = -18


那么，可以看出，r1 + r2、r1 - r2、r1/r2 都不会超过 8 位补码的表示范围，即不会溢出，而 r1 * r2 很明显小于 -128 了，因此会发生溢出，所以本题选 C

补码一位乘法的运算规则如下：
  1. 乘数最低位增加一位辅助位 Y-1 = 0
  2. 根据 Yi-1Yi 的值，决定是加 X 的补码，还是减 X 的补码，还是 +0
    1. 如果 Yi-1Yi = 00 或者 11 时，则 [Pi+1] 补 = [Pi+1 + 0] 补
    2. 如果 Yi-1Yi = 01 时，则 [Pi+1] 补 = [Pi+1 - X] 补
    3. 如果 Yi-1Yi = 10 时，则 [Pi+1] 补 = [Pi+1 + X] 补
  3. 每次加减后，对 P 和 Y 整体算术右移一位，得到部分积 Pi+1
  4. 重复第 2 步和第 3 步 32 次，P 和 Y 中存储的就是补码乘法的结果，即 [X × Y] 补


可以看到，通过循环执行 "加/减" 和 "移位" 操作得到乘积，B 正确；由乘数最低两位决定对部分积和被乘数进行加法还是减法，C 正确

n 位定点数的除法，实际上是用一个 2n 位的数取除以一个 n 位的数，得到一个 n 位的商，因此需要进行被除数扩展，对于 n 位定点正整数相除的话，那么就在被除数的高位填 n 个 0 即可，因此 A 正确

每轮由控制逻辑根据 ALU 运算结果的符号位来决定上商为 0 还是 1（因为符号位是 1 的话，说明余数减去除数等于负数，不够减，那么需要恢复余数，此时上商 0；如果符号位是 0 的话，则表示够减，上商 1），为判断中间余数的正/负，需在余数寄存器 R 的最高位前增加一位符号位，B 正确

对于两个 n 位无符号整数除法运算，最大的商为 111…11/000…01=111…11，显然，运算结果没有产生溢出。因此，两个 n 位无符号整数除法运算肯定不会溢出，无须通过得到最高位商（第 n + 1 位商 qn）来判断溢出，也即只要有 n 次循环执行 "加/减" 和 "左移" 操作，就能得到第 n-1～0 位的 n 位商（qn-1～q0）。因此，选项 C 的说法是错误的，D 是正确，本题选 C






【2010 第 13 题】假定有 4 个整数用 8 位补码分别表示 r1 = FEH， r2 = F2H， r3 = 90H， r4 = F8H， 若将运算结果存放在一个 8 位寄存器中，则下列运算中会发生溢出的是（ ）

A.r1 × r2
B.r2 × r3
C.r1 × r4
D.r2 × r4
补码的直接相减和转加法计算结果一样
对于补码的定义，一定一定要牢牢记住：

根据公式，可以得出 8 位补码能表示的最小值就是 1000 0000B，也就是 -2^7，能表示的最大值是 0111 1111，也就是 2^7 - 1，所以 8 位补码能表示的整数范围是 -2^7 ~ 2^7 - 1，也就是 -128 ~ 127

接下来，分别将补码 r1 = FEH， r2 = F2H， r3 = 90H， r4 = F8H 转换成对应的十进制，r1 = -2，r2=-14，r3 = -112， r4 = -8，然后，一看 r2 x r3 = 1568，超过了 8 位补码的范围，发生溢出，选 B

对于这题，有两个地方需要注意

一个就是如果你直接基于二进制做补码乘法，去计算四个选项的结果，那么你就掉入出题人的陷阱了，你会浪费很多时间，还不一定能计算对，对于这题，真正意图是考查补码的表示范围，而不是补码的乘法运算，所以解题时，尤其是对于这种看似很复杂的题，不要轻易动笔，要弄清题目考查的真正意图

第二个要注意的就是，如何快速的将补码转换成对应的十进制，以下我先提出 3 种方法，你自己去选择最快的方式

首先是根据下面补码的定义公式来转换：
r1 = FEH = 1111 1110B = -2^7 + 2^6 + 2^5 + 2^4 + 2^3 + 2^2 + 2^1 + 0 = -2
r2 = F2H = 1111 0010B = -2^7 + 2^6 + 2^5 + 2^4 + 0 + 0 + 2^1 + 0 = -14
r3 = 90H = 1001 0000B = -2^7 + 0 + 0 + 2^4 + 0 + 0  +0 + 0 = -112
r4 = F8H = 1111 1000B = -2^7 + 2^6 + 2^5 + 2^4 + 2^3 + 0 + 0 + 0 = -8
这种方法，很明显，很费力，不是最高效的

接下来，我们通过将补码的数值位取反再加 1，得到原码，然后再来转换：
r1 = FEH = 1111 1110B，它的原码是 1000 0010，对应的十进制是 -2
r2 = F2H = 1111 0010B，它的原码是 1000 1110，对应的十进制是 -(2^3 + 2^2 + 2^1) = -14
r3 = 90H = 1001 0000B，它的原码是 1111 0000，对应的十进制是 -(2^6 + 2^5 + 2^4) = -112
r4 = F8H = 1111 1000B，它的原码是 1000 1000，对应的十进制是 -(2^3) = -8
这种方法，对于 F 开头的补码，转换成十进制，可能稍微轻松点，如果不是 F 开头的话，比如这个 90H，还不如上面一种方法高效了

接下来，如果你能知道并记住，补码中全 1 表示的是十进制的 -1，比如补码的 FFH 等于十进制的 -1，FFH = 1111 1111B，数值位取反加 1 得到原码 1000 0001B，也就是 -1

那么基于这个 FFH 来转换上面的补码的十进制，会相对舒服点
因为 FEH + 01H = FFH，所以 r1 = FEH = FFH - 01H = -1 - 1 = -2
因为 F2H + 0DH = FFH，所以 r2 = F2H = FFH - 0DH = -1 - 13 = -14
因为 90H + 6FH = FFH，所以 r3 = 90H = FFH - 6FH = -1 - (6 × 16 + 15) = -112
因为 F8H + 07H = FFH，所以 r4 = F8H = FFH - 07H = -1 -7 = -8

这里直接利用了【补码直接相减得到的补码也是正确的结果】这个知识点，你会问，这样真的可以吗？如果你不信的话，可以去复习这里：补码的直接相减和转加法计算结果一样

这种方法直接基于十六进制（这里妙用了 FFH），中间没有涉及任何二进制，是不是快很多很多，考试中最好是用最快的，这样节省时间
