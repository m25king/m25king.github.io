前面我们讲过，在 C 语言中，如果基本类型声明前加上 unsigned 的话，就表示无符号整数，但是如果去掉 unsigned 的话，就是声明有符号整数的类型了，看下图：

上面的 unsigned int 可以简写成 unsigned；short 也可以写成 short int，是一个意思
虽然 C 语言标准没有指定有符号数要采用哪种编码，但是几乎所有的机器都使用补码表示 C 语言中的有符号数号
通常，大多数数字都默认为是有符号的。例如，当声明一个像 12345 或者 0x1A2B 这样的常量时，这个值就被认为是有符号的。要创建一个无符号常量，必须加上后缀字符 'U' 或者 'u'，例如，12345U 或者 0x1A2Bu
C 语言允许在各种不同的数字数据类型之间做强制类型转换。例如，假设变量 x 声明为 int，u 声明为 unsigned。表达式 (unsigned)x 会将 x 的值转换成一个无符号数值，而 (int)u 将 u 的值转换成一个有符号整数
在有符号整数和无符号整数之间进行转换时：保持机器码数值不变，只是改变了解释机器码位值的方式而已

接下来，对结果进行解释下，首先 uv 本来就是等于 65432，uv 是 unsigned short 类型，使用 16 位无符号数编码表示，其无符号编码多少呢？
65432 = 65536 - 1 - 64 - 32 - 4 - 2 - 1 = 2^16 - 1 - 2^6 - 2^5 - 2^2 - 2^1 - 2^0 = 1111 1111 1111 1111 -  2^6 - 2^5 - 2^2 - 2^1 - 2^0 = 1111 1111 1100 11000，看下图：

当执行 short v = (short) uv 时，将 uv 强制转换成 short 类型，那么就是将上面的 16 位机器数解释成 16 位的 补码表示的整数，忽略高位连续 1，和补码 1001 1000 标的整数一样，即 -2^7 + 2^4 + 2^3 = -128 + 16 + 8 = -104
其实，对于无符号数转换成有符号数，有一个更便捷的方法：
  • 当 uv > 2n-1 - 1 时，那么 v = uv - 2n，其中 n 是无符号编码的位数
  • 当 uv ≤ 2n-1 - 1 时，那么 v = uv
比如，上面的 v = 65432 > 2^15 - 1 = 32767，那么 v = uv - 2n = 65432 - 65536 = -104
上面的结论请理解记忆 ，如果无符号编码的最高位是 0 的话，那么能表示的整数 uv ≤ 2n-1 - 1 的，此时表示正数，对于同一个正数的编码，不管是补码还是无符号编码，表示的整数是同一个，因此 v= uv
如果无符号编码的最高位是 1 的话，那么能表示的整数 uv > 2n-1 - 1 的，此时无符号编码和补码的最高位的权重不同，如下图：

无符号整数最高位权重是 2n-1，补码最高位权重是 -2n-1，所以只需要将无符号整数的公式减去 2n 就等于 -2n-1，即 v = uv - 2n

我们一一来解释：

首先是 0 == 0U，因为第二个运算数 0U 是无符号的，第一个运算数就会被隐式地转换为无符号数，因此表达式就等价于 0U == 0U，得到的类型是无符号，结果是 1（即 true）

再来看 -1 < 0，两个运算数都是有符号数，得到的类型是有符号，所以结果是 1（即 true）

再来看 -1 < 0U，因为第二个运算数是无符号的，第一个运算数就会被隐式地转换为无符号数，-1 的机器数是 FFFF FFFFH（补码表示），解释成无符号数就是 2^32 - 1 = 4294967295U，因此表达式就等价于 4294967295U < 0U，这个答案显然是错的，结果是 false

再来看 2147483647 > -2147483647 - 1，两个运算数都是有符号数，相当于 2147483647 > -2147483648，第二个运算符并没有超过 int 的表示范围（它是 int 的最小值 -2^31），得到的类型是有符号，所以结果是 1（即 true）

再来看 2147483647U > -2147483647 - 1，因为第一个运算数是无符号数，第二个运算数 -2147483648 会被隐式地转换为无符号数，-2147483648（-2^31） 的机器数是 8000 0000H（补码表示），解释成无符号数就是 2^31 = 2147483648U，所以相当于比较 2147483647U > 2147483648U，很明显结果错误（false）
再来看 2147483647 > (int)2147483648U，第二个运算数强制转换为有符号数，首先 2147483648U （2^31）的机器数是 8000 0000H，解释成有符号数就是 -2^31 = -2147483648，因此 2147483647 > -2147483648 结果是对的（true）

再来看 -1 > -2，两个运算符都是有符号数，所以这个是正确的
再来看 (unsigned) -1 > -2，因为第一个运算数是无符号数，第二个运算数 -2 会被隐式地转换为无符号数，-2 < 0，所以转换成无符号数就是 -2 + 2^32 = 4294967294U，而第一个运算数 -1 < 0，转成无符号数就是 -1 + 2^32 = 4294967295U，而 4294967295U  >  4294967294U 是正确的
