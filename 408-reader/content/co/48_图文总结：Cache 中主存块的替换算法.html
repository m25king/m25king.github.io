下图是 Cache 的基本组成：

在 Cache 中，会有由 SRAM 组成的存储体，主存 - Cache 地址映射变换逻辑，以及 Cache 替换逻辑
前面我们看到的 Cache 的标志区、数据区都是位于 Cache 存储体中，将主存地址进行划分是在主存 - Cache 地址映射变换逻辑中实现的
当 CPU 给出访问主存的主存地址，通过地址映射变换逻辑，可以判断该主存地址是否命中 Cache，如果命中，则根据通过地址映射变换得到的 Cache 地址，去 Cache 存储体中访问对应的数据
如果未命中，需要判断还有没有足够的空闲的 Cache 行，如果有的话，CPU 的会去访问主存，并将对应的主存块装入 Cache
如果没有足够的空闲 Cache 行，则需要 Cache 替换逻辑来替换 Cache 行，接下来，我们详细学习 Cache 替换逻辑
常用的替换算法有：
  • ① 先进先出 (First-In-First-Out，FIFO)
  • ② 最近最少用 (Least-Recently Use，LRU)
  • ③ 最不经常用 (Least-Frequently Used，LFU)
  • ④ 随机替换算法

可以根据实现的难易程度以及是否能获得较高的命中率两方面来决定采用哪种算法，接下来，我们分别来介绍

先进先出 (First-In-First-Out，FIFO)


FIFO 算法的基本思想是：总是选择淘汰最早装入 Cache 的主存块
我们来看一个 4 路组相联中的某一个 Cache 组：

假设主存块 1,2,3,4,5 都被映射到这个 Cache 组中，现在 CPU 依次访问这些主存块：：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
采用 FIFO 替换算法的过程如下：

首先 CPU 依次访问 1、2、3、4 号主存块，均未命中 Cache，都被复制到 4 个 Cache 行中，此时这个 Cache 组满了
接下来，访问 1 、2 号主存块，均命中 Cache
第 ⑦ 次，访问 5 号主存块，未命中 Cache，此时该 Cache 组满了，需要替换一个 Cache 行，按照 FIFO 的替换算法，找到最早装入 Cache 的 1 号主存块，然后将 5 号主存块复制到 1 号主存块所在的 Cache 行，替换 1 号主存块

第 ⑧ 次，访问 1 号主存块，未命中 Cache（1 号主存块刚刚被替换了），Cache 组满了，按照 FIFO 的替换算法，找到并替换最早装入 Cache 的 2 号主存块，然后将 1 号主存块复制到 2 号主存块所在的 Cache 行
第 ⑨ 次，访问 2 号主存块，未命中 Cache（2 号主存块刚刚被替换了），Cache 组满了，按照 FIFO 的替换算法，找到并替换最早装入 Cache 的 3 号主存块，然后将 2 号主存块复制到 3 号主存块所在的 Cache 行
第 ⑩ 次，访问 3 号主存块，未命中 Cache（3 号主存块刚刚被替换了），Cache 组满了，按照 FIFO 的替换算法，找到并替换最早装入 Cache 的 4 号主存块，然后将 3 号主存块复制到 4 号主存块所在的 Cache 行

第 11 次，访问 4 号主存块，未命中 Cache（4 号主存块刚刚被替换了），Cache 组满了，按照 FIFO 的替换算法，找到并替换最早装入 Cache 的 5 号主存块，然后将 4 号主存块复制到 5 号主存块所在的 Cache 行
第 12 次，访问 5 号主存块，未命中 Cache（5 号主存块刚刚被替换了），Cache 组满了，按照 FIFO 的替换算法，找到并替换最早装入 Cache 的 1 号主存块，然后将 5 号主存块复制到 1 号主存块所在的 Cache 行
可以看到，使用 FIFO 替换算法，上面的 CPU 的 12 次访问主存，只有 2 次命中，上面重复访问 1、2、3、4、5 号主存块，都未命中，这就未能正确使用程序局部性
这种算法实现方便，但不能正确反映程序的访问局部性，因为最先进入 Cache 的主存块也可能是目前要用的，因此，这种算法有可能产生较大的缺失率

要实现 FIFO 替换算法，比较简单，只需要在每个 Cache 行前面记录下主存块转入的时间，淘汰时，只需要找出这个时间最小（即最早装入）的主存块淘汰即可

最近最少用 (Least-Recently Use，LRU)


LRU 算法的基本思想是：总是选择淘汰近期最少使用的主存块
这种算法能比较正确的反应程序的访问局部性，因为当前最少使用的块一般来说也是将来最少被访问的，不过它的实现比 FIFO 算法要复杂一点
我们还是以上面的这个 Cache 组为例：

假设主存块 1,2,3,4,5 都被映射到这个 Cache 组中，现在 CPU 依次访问这些主存块：：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
采用 LRU 替换算法的过程如下：

首先 CPU 依次访问 1、2、3、4 号主存块，均未命中 Cache，都被复制到 4 个 Cache 行中，此时这个 Cache 组满了
第 ⑤ 次访问 1 号主存块，命中 Cache，然后把 1 号主存块移动到最上面，此时近期最少使用的主存块是最下面的 2 号主存块
第 ⑥ 次访问 2 号主存块，命中 Cache，然后把 2 号主存块移动到最上面，此时近期最少使用的主存块是最下面的 3 号主存块
第 ⑦ 次访问 5 号主存块，未命中 Cache，此时 Cache 满了，按照 LRU 算法，淘汰掉近期最少使用的最下面的 3 号主存块，此时近期最少使用的主存块是 4 号主存块
第 ⑧ 次访问 1 号主存块，命中 Cache，然后把 1 号主存块移动到最上面，此时近期最少使用的主存块仍然是最下面的 4 号主存块
第 ⑨ 次访问 2 号主存块，命中 Cache，然后把 2 号主存块移动到最上面，此时近期最少使用的主存块仍然是最下面的 4 号主存块
第 ⑩ 次访问 3 号主存块，未命中 Cache，此时 Cache 满了，按照 LRU 算法，淘汰掉近期最少使用的 4 号主存块，此时近期最少使用的主存块是最下面的 5 号主存块
第 11 次访问 4 号主存块，未命中 Cache，此时 Cache 满了，按照 LRU 算法，淘汰掉近期最少使用的 5 号主存块，此时近期最少使用的主存块是最下面的 1 号主存块
第 12 次访问 5 号主存块，未命中 Cache，此时 Cache 满了，按照 LRU 算法，淘汰掉近期最少使用的 1 号主存块，此时近期最少使用的主存块是最下面的 2 号主存块
相比于 FIFO 替换算法，LRU 替换算法命中了 4 次，命中率一般是高于 FIFO 替换算法的
LRU 算法并不是像上面所示通过移动块来实现的。实际上，每个 Cache 行有一个计数器，用计数值来记录主存块的使用情况，通过硬件修改计数值，并根据计数值选择淘汰某个 Cache 行中的主存块， 如下图：
这个计数值称为 LRU 位，其位数与 Cache 组大小有关。理论上，n 路时 LRU 位为log2(n)，例如，2 路时 LRU 位为 1，4 路时 LRU 位为 2
所以，如果 Cache 采用 LRU 替换算法的话，那么每一个 Cache 行的标志位，除了有标识 Tag 位、有效位，还有一个 LRU 位
这个 LRU 位的取值逻辑是这样的（以上面的 2 位 LRU 位为例）：
  • 未命中且该组还有空闲行时，则新装入的行的 LRU 位设为 0，其余全加 1
  • 命中时，被访问的行的 LRU 位清零，比其低的 LRU 位加 1，其余不变
  • 未命中且该组无空闲行时， LRU 位为 3 的那一行中的主存块被淘汰，新装入的行的 LRU 位设为 0，其余加 1

最不经常用 (Least-Frequently Used，LFU)


LFU 算法的基本思想是：替换掉 Cache 中访问次数最少的块
LFU 也用与每个行相关的计数器来实现，了解即可

随机替换算法


从候选行的主存块中随机选取一个淘汰掉，与使用情况无关
模拟实验表明，随机替换算法的性能上只稍逊于基于使用情况的算法（比如 LRU 替换算法），而且代价比较低
