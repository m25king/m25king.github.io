什么是 ISA？

计算机硬件只能识别和理解机器语言程序，用各种高级语言编写的源程序最后都要翻译成指令形式表示的机器语言才能在计算机上执行，一台计算机能执行的机器指令的集合称为该机的指令集，它是构成程序的基本元素，也是硬件设计的依据，它衡量机器硬件的功能，反映硬件对软件支持的程度
指令集体系结构（Instruction Set Architecture，ISA）则是定义机器级程序的格式和行为，它定义了处理器状态、指令格式，以及每条指令对状态的影响，怎么理解 ISA 呢？
指令集体系结构（ISA）也简称为指令系统
① 首先，ISA 定义了处理器状态，所谓状态就是指处理器（CPU）内部的寄存器，ISA 规定了 CPU 运行时软件可见的寄存器（就是可以使用汇编指令操作的寄存器），比如：
  • 通用寄存器（比如 x86 中的 rax、rbx 等，MIPS 中的 $1 ~ $31 号寄存器）
  • 程序计数器 PC（下一跳要执行的指令地址）
  • 程序状态字 PSW / 标志寄存器（比如进位、溢出、零标志等）
  • 栈指针 SP
  • ........
注意：ISA 只定义软件可见的状态（即寄存器），硬件内部的缓存、流水线寄存器等这种软件不可见的状态不归 ISA 管
② 然后，ISA 规定了一条机器指令长什么样（即规定了指令格式），比如：
  • 指令的总长度（MIPS 是定长 32 位指令，而 x86 的指令是变长的）
  • 指令的编码结构：操作码（告诉 CPU 做什么）、操作数（告诉 CPU 用什么数据）的位置和长度  
  • 寻址方式：怎么找到操作数的地址（比如立即数、寄存器、内存寻址等）  
③ ISA 最核心的部分是：规定了每条指令执行后，会怎么改变处理器状态和内存，比如执行 add rax, rbx 指令后，必须把 rax 和 rbx 的值相加，结果写回 rax，同时更新标志寄存器的零位、进位位等。硬件不管用什么方法（单周期、流水线、乱序执行），最终的状态变化必须和 ISA 定义的顺序执行完全一致

ISA 对处理器的抽象

绝大多数 ISA（比如 x86-64、ARM）都定义了顺序执行模型：  
  • 软件视角：程序是一条指令接一条指令顺序执行的，前一条执行完，后一条才开始  
  • 硬件视角：CPU 可以用流水线、超标量、乱序执行等技术，并发执行很多条指令，但必须通过采取措施，保证最终结果看起来和顺序执行一模一样  
这就是 ISA 的抽象作用：用简单的顺序模型，隐藏了硬件复杂的并发实现细节，让软件不用关心硬件怎么跑，只需要按顺序写程序

在处理器（CPU）里，指令集架构（ISA）提供了对实际处理器硬件的抽象，使用这个抽象，机器代码程序表现得就好像运行在一个一次只执行一条指令的处理器上，就是因为这个抽象，使得我们程序员不需要关心底层处理器硬件复杂的实现。底层的硬件远比抽象描述的要复杂精细，它并行地执行多条指令，但又总是与那个简单有序的模型保持一致。只要执行模型一样，不同处理器实现也能执行同样的机器代码
ISA 是一种规定或结构规范，是软件和硬件之间的接口：

对软件（编译器、程序员）来说：ISA 是一套规则手册，规定了 CPU 能听懂哪些指令、指令长什么样、执行后会发生什么； 对硬件（CPU 设计）来说：ISA 是设计要求，硬件必须严格实现这套规则，保证软件写的程序能正确跑起来  
我们可以把 CPU 比作餐厅的后厨：
  • ISA = 菜单：上面写了所有后厨能做的菜（指令）、每道菜的做法（指令格式）、上菜的要求（指令行为）  
  • 软件（程序员 / 编译器）= 顾客：只能点菜单上有的菜（用 ISA 规定的指令写程序），不用管后厨怎么炒菜（硬件实现细节）  
  • 硬件（CPU）= 厨师：必须严格按照菜单的要求做菜（实现 ISA），不管用什么锅、什么火候（硬件架构，比如流水线、超标量），最终端出来的菜（程序执行结果）必须和菜单要求完全一致  

ISA 的种类

不同的应用场景，不同的计算机的指令集体系结构可能是不同的，比如 Intel x86 指令系统支配着计算机的 PC 时代，而最流行的嵌入式设备指令系统却是 ARM 指令系统
因为 x86 指令系统比较复杂，基于 x86 构建计算机比较复杂，所以，在市场上出现了 MIPS 和 RISC-V 指令系统，基于它们可以使得计算机的构建变的简单
我们接下来先学习 MIPS 和 X86-64 这两种具体的 ISA，然后再去学习指令系统设计问题：

在学习具体的 ISA 时，先去学习每个指令系统的三个基本内容，分别是寄存器组、指令格式和寻址方式，然后再去学习用这个指令系统中的指令如何实现高级语言中的选择结构，循环结构以及函数调用结构等，说白了就是要能看懂一段 C 程序对应的指令
指令集被分成了 CISC 复杂指令集和 RISC 精简指令集两大类，CISC 复杂指令集的指令多、功能强、指令长度是变长的、寻址方式多，比如 X86-64 就属于 CISC；RISC 精简指令集指令少、功能简单、指令长度是定长的、寻址方式少、Load-Store 架构，比如 MIPS 就属于 RISC
指令系统这一章要求你能设计一个简单的指令系统，而且还需要看懂一段简单的 C 程序对应的汇编代码
