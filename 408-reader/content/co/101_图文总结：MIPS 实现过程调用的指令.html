jal 和 jr 指令

函数调用就是过程调用，过程调用就可以理解成函数调用，在 MIPS 中使用 jal 和 jr 两个指令来实现过程调用，来看一段 C 代码，在 main 函数中调用 add 函数：

函数调用指令 jal 是一种无条件转移指令，指令 jal 是跳转并链接 (jump and link) 简写，上图中，当执行 jal add 指令时，会完成两件事情：① 保存下条指令地址（即返回地址，也就是上图主存地址 32）到 31 号寄存器；② 跳转到指定地址除执行（跳到 add 函数的第一条指令）
函数调用返回指令也是一种无条件转移指令，在 MIPS 中称为寄存器跳转（jump register） 指令，指令名为 jr，上图中，当执行指令 jr $31 时，跳转到 31 号寄存器指定的主存地址执行，也就是将 $31 寄存器中的返回地址（这个是 jal 指令保存到 $31 寄存器的）恢复到 PC 中，开始执行返回地址位置的指令（对于上图的话，返回地址就是 32，即开始执行 nop 指令），因为 jr 后面跟的是寄存器编号，所以 jr 采用 R 型指令格式：

jr $31 这条指令，操作码是 0，rs 字段是 31，也就是目的寄存器，下面三个字段没有用，功能吗是 8
jal 采用的是 J 型指令格式，J 型指令格式包含一个 6 位操作码和剩下的 26 位直接地址，看下图：
jal 的操作码是 3，后面的目的直接地址就是 jal 跳转的目标指令的主存地址，比如上面 jal add 指令中的标签 add 本质上就是主存地址 0，因为 jal 要跳转到 add 函数的第一条指令的主存地址是 0，因此 jal add 指令其实就是 jal 0（上面使用标签 add 只是为了提高可读性）
我们知道 MIPS 的存储器按字节编址，对于存储器数据，其操作数有效地址为 32 位，而上面 jal 的目的直接地址是 26 位，此时需要将当前 PC 的高 4 位拼上 26 位目的直接地址（这个是 MIPS 自己的规则），最后再添两个 0 就可以得到 32 位跳转目的地址
那么为什么要在最后添两个 0 呢？因为 MIPS 机器采用 32 位定长指令字，其存储单元采用字节编址，所以一条指令占 4 个存储单元，而且要求指令数据内存对齐，所以指令地址总是 4 的倍数，即地址最后两位总是 0，为了不占用指令长度，所以在指令中通常会省略这 2 个 0，然后在寻址时加上这 2 个 0 即可
如果指令中给出的地址码就是操作数的有效地址，通过这个有效地址就可以找到对应的操作数，这种寻址方式称为直接寻址（有的时候也称为主存直接寻址），不过对于上面的 J 型指令，地址码给出的 26 位地址并不是真的操作数的目的内存地址，而是需要做些处理，才可以得到真的目的内存地址，所以这种寻址方式，称为伪直接寻址（或者称为变通的直接寻址）
总结：在 MIPS 中，有三个无条件跳转指令，分别是 j 、jr、jal 指令，其中 jr 后面跟的是寄存器编号，而 j 和 jal 后面跟的是目的内存地址

指令 j (jump 的缩写)，就是无条件跳转指令，无条件的跳转到目标地址，采用 J 型指令格式
jr 指令中的寄存器也可以是除 $31 以外的其他寄存器，所以 jr 指令也可以用于 switch case 语句中的跳转执行 (了解就好)

过程调用的步骤

假定过程 P 调用过程 Q，则过程调用的执行步骤如下：
  1. P 将入口参数（就是 Q 需要的参数）放到 Q 能访问到的地方
  2. P 将返回地址存到特定的地方（用于后续返回），然后将控制转移到 Q
  3. Q 为 P 保存现场（有些数据，在执行完 Q 后，P 还需要，那么这些数据就需要先保存），并为自己的局部变量分配空间
  4. 执行过程 Q
  5. Q 将返回结果放到 P 能访问到的地方
  6. Q 取出返回地址，将控制转移到 P
从上述执行步骤来看，在过程调用中，需要为入口参数、返回地址、调用过程执行时用到的寄存器、被调用过程中的局部变量、过程返回时的结果等数据找到存放空间。如果有足够的寄存器，最好把这些数据都保存在寄存器中，这样，CPU 执行指令时，可以快速地从寄存器取得这些数据进行处理
但是，用户可见寄存器数量有限；并且它们是所有过程共享的，给定时刻所有寄存器只能被一个过程使用；此外，对于过程中使用的一些局部变量 (如数组和结构等复杂类型数据) 也不可能保存在寄存器中。因此，除了寄存器外，还需要有一个专门的存储区域来保存这些数据，这个存储区域就是栈 (stack)
