MIPS 指令在实现程序中的 if 语句时，要用到两条分支指令 beq 和 bne：
  • beq：branch if equal 的缩写，如果相等则分支（跳转执行），不相等则顺序执行
  • bne：branch if not equal 的缩写，如果不相等则分支（跳转执行），不相等则顺序执行

beq 分支指令

这两条指令 beq $rs, $rt, label 和 bne $rs, $rt, label 的指令格式是一样的，都属于 I 型指令格式，来看一段代码：

第一条指令 beq $4, $5, $L4，就是比较 4 号寄存器值和 5 号寄存器的值，也就是比较 i 和 j，如果相等的话，则跳到 $L4 这个分支，执行加法 addu 指令，这里的 $L4 就称为标签（label），如果 i 不等于 j，那么直接往下执行 nop 和 subu 指令
这样就是用 beq 指令实现了 C 语言中的 if 语句了，这里的 $L4 本质上是一个整数，而且在这里，这个整数对应着 4，这个整数我们称为偏移量 offset，这这个 4 怎么来的呢？看下图：

我们将这个代码对应的汇编指令，放到主存储器中，第一条 beq 指令存储在内存地址为 0 的位置上，每条指令占 4 个字节，这里 beq 最后的偏移量是 4，我们稍后来解释为什么是 4
目前 CPU 正在执行第一条 beq $4, $5, 4，所以 PC 中是下一条要执行指令的内存地址是 4，执行 beq 执行时，比较 $4 和 $5 寄存器的值，发现相等（都等于 10），所以应该跳转分支，这里应该要跳的目的地址是 20，也就是加法指令 addu $2, $6, $7 所在地址，也就是说，这时需要将 PC 值设置为 20，而 20 = PC + (offset << 2) = 4 + (4 << 2) = 4 + 16，可以看到 beq 指令的 offset 就是 4 了
就是说，当执行 beq $rs, $rt, offset 时，如果 R[$rs] == R[$rt]，那么 PC 的值将设置为 PC + (offset << 2)，表达式中的 PC 的值就是 beq 指令的下一条指令的内存地址，这里的 offset 可以理解成要跳过的指令条数，比如上面从指令 beq 到目标指令 addu 之间有 4 条指令的，所以 offset 就等于 4，而每一条指令占 4 个字节，所以 PC = PC + (offset * 4) = PC + (offset << 2)

有的时候，你会看到当执行 beq $rs, $rt, offset 时，如果 R[$rs] == R[$rt]，那么 PC = PC + 4 + (offset << 2)，这个时候就要注意了，表达式中的 PC 的值就是分支指令 beq 所在的主存地址，而不是 beq 执行时当前的 PC 值，因为执行 beq 指令时，当前的 PC 已经自动加 4 了，表达式 PC + 4 就是指向 beq 的下一条指令


正常来说，PC 中保存的值就是当前 CPU 正在执行指令的内存地址，但是，在多周期CPU 数据通路中，PC 中保存的是下一条需要执行指令的内存地址，在多周期 CPU 中，取指完会自动完成 PC = PC + 4，但是在单周期 CPU 数据通路中的 PC 都是保存当前 CPU 正在执行指令的内存地址，所以说 PC 中具体保存什么地址，要看 CPU 的实现
分支指令 beq 和 bne 都属于 I 型指令格式：

对于 beq $4, $5, 4 指令，其操作码是 4，即 00100，rs 字段是第一个源操作数的寄存器编号 4，rt 字段第二个是源操作数的寄存器编号 5，其偏移量是补码表示的 4，它的作用是如果 R[$rs] == R[$rt]，那么将 PC 值设置为 PC + 4 + (offset << 2)，这里的 PC 是 beq 指令所在的内存地址，而 PC + 4 则是 beq 指令的下一条指令的内存地址，即跳转到目的地址执行指令，如果  R[$rs] != R[$rt]，那么就顺序执行（即 PC = PC + 4）
我们知道 MIPS 的存储器按字节编址，对于存储器数据，其操作数有效地址为 32 位，那么 PC 的位数也是 32 位，所以执行 PC + 4 + (offset << 2) 时，需要对 16 位补码表示的 offset 进行符号扩展到 32 位
对于 bne $4, $5, 4 指令，它的其他三个字段和上面的 beq 指令是一样，只是操作码是 5，即 000101，其作用是如果 R[$rs] != R[$rt]，那么跳转执行，将  PC 值设置为 PC + 4 + (offset << 2)，如果  R[$rs] == R[$rt]，那么就顺序执行（即 PC = PC + 4）

bne 分支指令

再来看下面稍微复杂的程序，首先执行主存地址为 0 的 beq $4, $5, $L5 指令，比较 i 和 j 是否相等：
  • 如果相等，则跳转执行主存地址为 36 的 addu 指令（执行 f = g + h），然后顺序执行 b $L3 指令，这个 b 是 branch 的缩写，它是无条件分支指令，也就是说无条件直接跳转到 $L3 的位置，取执行 slt 指令
  • 如果不相等，则顺序执行内存地址为 4 的 nop 指令，再执行 subu 指令（执行 f = g - h）
然后顺序执行内存地址为 12 的 slt $4, $2, $4 指令，其作用是小于则置位，如果 R[$2] < R[$4]，那么将 R[$4] 设置为 1，否则将 R[$4] 设置为 0，其实就是比较 f 是不是小于 i，接下来执行 bne $4, $0, $L1 执行，判断 R[$4] != 0 的话（说明 f < i），则跳转到内存地址为 28 位置执行 jr 指令返回函数（就是执行 return f 语句）,如果 R[$4] == 0 的话（说明 f >= i）则顺序执行内存地址为 20 的 nop 指令，然后再执行 f = f - 10 这个分支语句，然后顺序执行内存地址为 28 位置执行 jr 指令返回函数
上面的无条件跳转指令 b $L3 其实是一条伪指令，它由 MIPS 中的 beq $0, $0, $L3 来实现的
来思考两个问题哈，首先看第一个问题：上图中的三个标签 $L1、$L3 和 $L5 对应的 offset 值是多少？我们知道 offset 其实就是要跳过的指令数：
  • 指令 bne $4, $0, $L1，其内存地址是 16，然后 $L1 所在指令的内存地址是 28，中间隔了 2 条指令，所以 bne 的 offset 就是 2，当执行 bne 指令时，如果 R[$4] != 0 的话，那么 PC = 16 + 4 + (2 << 2) = 28

  • 指令 b $L3，其内存地址是 40，然后 $L3 所在指令的内存地址是 12，中间隔了 8 条指令（从主存地址 44 指令开始 → 40 → 36 → ... → 16，总共 8 条指令），因为是从高地址跳到低地址，所以 b 的 offset 就是 -8，当执行 b 指令时，那么 PC = 40 + 4 + (-8 << 2) = 12

  • 指令 beq $4, $5, $L5，其内存地址是 0，然后 $L5 所在指令的内存地址是 36，中间隔了 8 条指令，所以 bne 的 offset 就是 8，当执行 beq 指令时，如果 R[$4] == R[$5] 的话，那么 PC = 0 + 4 + (8 << 2) = 36
再来思考第二个问题：上图中的 slt $4, $2, $4 指令是如何实现比较 R[$2] 和 R[$4] 的大小的？可以直接用加法器执行 R[$2] - R[$4]，然后再看加法器的标志位：
  • 如果是有符号减法，就看 OF ^ SF 的值，如果 OF ^ SF = 1，那么 R[$2] 小于 R[$4]，那么将 R[$4] 设置为 1，否则将 R[$4] 设置为 0，对于上面例子，f 和 i 都是有符号整数，因此看 OF^SF 的值

  • 如果是无符号减法，只要看 CF 就可以，如果 CF 等于 1，说明要借位，不够减，那么 R[$2] 小于 R[$4]，那么将 R[$4] 设置为 1，否则将 R[$4] 设置为 0

相对寻址方式

上面的无条件跳转指令 b -8 实际上是一条伪指令，MIPS 使用 beq $0, $0, -8 来实现无条件跳转指令 b -8，因为 R[$0] 肯定是等于 R[$0] 的，所以执行 beq $0, $0, -8 时，肯定是要跳转执行的
前面我们学习的分支指令 beq 和 bne 的偏移量 offset 都是采用 16 位补码表示，而16 位补码的取值范围：-2^15 ~ 2^15 - 1（-32768 ~ 32767），因此这两个分支指令的跳转目的地址范围是 PC + 4 + (-32768 << 2) ~ PC + 4 + (32767 << 2），其中 PC 是分支指令所在的主存地址
这种指令的转移目的地址位于该指令所在位置的前、后某个固定位置上，那么该转移目标可以用相对寻址方式，采用相对寻址方式时，指令中的地址码字段 A 给出一个偏移量（比如上面的 beq 和 bne 的 offset），基准地址隐含的由 PC 给出，那么转移目标地址 EA = (PC) + A，这里的偏移量 A 是形式地址，转移目标地址可以在当前指令之前或之后，因而偏移量 A 是一个带符号整数，下图是相对寻址方式：
寻址方式是指确定本条指令的操作数的有效地址以及下一条将要执行的指令地址的方法，寻址方式分为指令寻址和操作数寻址两大类，前面我们学习的立即数寻址、寄存器直接寻址以及基址寻址都是操作数寻址方式
指令寻址比较简单，分为顺序寻址和跳跃寻址，顺序寻址就是通过 PC 加 1，自动形成下一条指令的地址，而跳跃寻址则通过转移类指令实现，比如上面的分支指令 beq 和 bne 中的 (PC) + 偏移量都是为了确定下一条跳转目的指令的地址的，所以说相对寻址方式可以用于指令寻址，当然相对寻址方式也可用于操作数寻址（这个我们在后面 X86-64 指令系统中再说）
