直接映射的优点是容易实现，命中时间短，因为只需要看主存块号最后的几位就可以确定 Cache 行号
但由于多个主存块只能映射到同一个 cache 行，当访问集中在这几个主存块时，就会引起频繁的调进调出，即使其他 cache 行都空闲，也毫无帮助
很显然，直接映射方式不够灵活，使得 cache 存储空间得不到充分利用，命中率较低
为了使得 Cache 存储空间得到充分的利用，以及提高 Cache 的命中率，我们可以使用全相联映射方式
全相联映射的基本思想是一个主存块可装入 cache 任意一行中，看下图采用全相联映射的 Cache：

比如主存地址 00 1100 1010，高 5 位（ 00 110），即所在主存块号是 6，如果按照直接映射的话，那么这个 6 号主存块应该映射到 6 % 4 = 2 号 Cache 行，但是在全相联映射中，他可以映射到任意一个空闲行中，这里假设映射到 0 号 Cache 行，有效位设置为 1
这个时候，因为不需要指定映射行号，所以，将整个主存块号作为标记，所以上面的标记的位数就是主存块的位数（5 位），全相联映射 cache 中，每行的标记用于指出该行取自哪个主存块
再比如主存地址 00 1010 1110，高 5 位（ 00 101），即所在主存块号是 5， 5 号主存块装入到 1 号 Cache 行，有效位设置为 1，主存块号（00 101）作为标记
现在，CPU 访问主存地址 11 1110 0110，高 5 位（ 11 111），即所在主存块号是 31， 在访问主存之前，需要先看看是否命中 Cache，在全相联映射时，需要检查所有的 Cache 行，才能确定是否命中
先看 0 号 Cache 行，其有效位是 1，所以需要用主存块号（11 111）和标记（00110）比较，不相等
再看 1 号 Cache 行，其有效位是 1，所以需要用主存块号（11 111）和标记（00101）比较，不相等
接下来看 2 号 Cache 行，发现有效位是 0，所以不需要比较标记，接着看 3 号 Cache 行，其有效位是 0，所以不需要比较标记
查看了所有的 Cache 行后，知道了未命中 Cache，即 31 号主存块不在 Cache 中，此时 Cache 选择任意一个空闲的 Cache 行，用来存储 31 号主存块，比如这里选择 2 号 Cache 行，CPU 通过突发传输，将 31 号主存块传输到 2 号 Cache 行，并将对应的有效位设置为 1，同时，将对应标记设置为主存块号，如下图：

可以看出，在全相联映射中，因为一个主存块可能在任意一行中，因此，主存地址中无须 cache 行索引，只有标记和块内地址两个字段：
全相联映射方式下，只要有空闲 cache 行，就不会发生冲突，因而块冲突概率低，命中率相对也高，Cache 的存储空间利用充分
但是想要判断一个主存块是否命中，需要用主存块号和所有的 Cache 行的标记进行比较，这个时间开销是比较大的
为了加快比较的速度，全相联映射的 Cache 中，通常每个 Cache 行都设置一个比较器，比较器位数等于标记字段的位数
全相联 Cache 访存时根据标记字段的内容来查找 Cache 行中的主存块，因而它查找主存块的过程是一种 "按内容访问" 的存取方式，因此，它是一种 "相联存储器"
全相联映射方式的时间开销和所用元件开销都较大，实现起来比较困难，不适合容量较大的 Cache

按字节编址，块大小为 512B，因此块内地址位数是 9 位（2^9 = 512）
主存地址空间为 1MB，因此主存被划分成 1MB / 512B = 2048 个主存块，那么需要 11 位表示主存块号（因为 2^11 = 2048），所以主存地址划分为低 9 位的块内地址和高 11 位的标记，如下图：
Cache 数据区容量为 8KB，Cache 行大小等于块大小 512B，因此，Cache 总行数 = 8KB / 512B = 16 行
