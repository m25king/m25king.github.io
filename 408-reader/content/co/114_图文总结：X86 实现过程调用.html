栈和栈帧

在 x86-64 中执行过程调用（即函数调用）时，如果一个过程需要的存储空间超出了寄存器能够存放的大小时，就会在栈内存上分配空间，栈内存可以用来传递参数、存储返回地址、保存寄存器以及保存局部变量等；栈内存由多个栈帧组成，一般来说，一个函数会对应一个栈帧，当调用一个函数时，会给这个函数在栈顶创建一个栈帧，函数执行结束时，会释放相应的栈帧，下图是过程 P 调用过程 Q 的两个栈帧的结构：

x86-64 的栈内存也是从地址减少的方向增长，而栈顶地址则由栈指针寄存器 rsp 保存，即栈指针 rsp 一直指向栈顶元素（可以通过 push 和 pop 指令将数据压入栈或弹出栈） ，除了 rsp 栈指针寄存器外，还有一个 rbp 寄存器，用于一个栈帧的基地址（即当前栈帧的第一个元素的内存地址），上图中 rbp ~ rsp 就是函数 Q 的栈帧
当前正在执行的过程对应的栈帧总是在栈顶，当过程 P 调用过程 Q 时，会把返回地址压入栈中，指明当 Q 返回时，要从 P 过程的哪个位置继续执行，在 X86 中将这个返回地址当作调用过程 P 的栈帧的一部分，因为它存放的是与 P 相关的状态（这里和 MIPS 不同，MIPS 将返回地址放到了被调用过程 Q 对应的栈帧中）
下图通过一个具体的例子来看下过程调用的具体实现（下图省略了和过程调用无关的指令），下图当前栈帧是 main 函数对应的栈帧（即正在执行 main 函数），栈帧基址寄存器 rbp 保存 main 栈帧的基地址，而栈指针寄存器 rsp 指向栈顶元素
在执行 main 函数之前，rbp 中保存的是调用 main 函数的函数对应栈帧的基地址，所以执行 main 函数第一条指令 push rbp 将上一个栈帧的基地址 rbp1 保存到 main 栈帧中，然后执行第二条指令 mov rbp, rsp 将 main 栈帧的基地址保存到 rbp 中，即 rbp 现在指向 main 栈帧第一个元素（即元素 rbp1），然后第三条指令 sub rsp, 0x20 相当于给 main 栈帧分配 32 字节（0x20 = 2 * 16）的栈内存
x86-64 的内存地址是 64 位（即 8 字节），所以上图中的 rbp1 和 返回地址都是 8 字节
接下来执行 main 函数中的 call _add 指令，它做两件事情：① 将返回地址（即紧跟这条 call 指令的下一条指令内存地址）压入到栈顶，② 将 _add 函数的第一条指令的内存地址放到 PC（即 rip 寄存器）中，这样就从执行 main 函数转移到执行 _add 函数的第一条指令 push rbp，它做两件事情：① 将 rsp 的值自减 8，② 将 rbp 中的值压入到栈顶，其实就是将 main 栈帧的基地址保存到 _add 栈帧中（看下图的 rbp2），这个时候的 rsp 指向 _add 栈帧的第一个元素（即 rbp2 元素）

接下来执行 _add 函数第二条指令 mov rbp, rsp 将保存在 rsp 中的 _add 栈帧的基地址保存到 rbp 中，即 rbp 现在指向 _add 栈帧第一个元素（即元素 rbp2），第三条指令 sub rsp, 0x18 为 _add 栈帧分配 24 字节的栈内存，此时 rsp 指向新的栈顶元素，接下来执行 call _sub 指令，调用执行 _sub 函数，此时会将 _add 函数的返回地址压入栈顶，然后跳转执行 _sub 函数第一条指令 push rbp 保存 _add 栈帧基地址到栈顶，第二条指令 mov rbp, rsp 将保存在 rsp 中的 ) _sub 栈帧的基地址保存到 rbp 中，看下图的 rbp3：

可以看到 _sub 函数中的两个参数 a 和 b 都可以放在寄存器中，这个函数实际上并不需要栈帧，而且这个 _sub 函数不会调用任何其他函数，这种函数我们也称为叶子函数，这种叶子函数很多时候都不需要对应的栈帧
当执行完 _sub 函数体后，开始执行 pop rbp 指令，它做两件事：① 将栈顶的 rbp3 复制到 rbp 寄存器中，② 将 rsp 的值自增 8，相当于弹出栈顶元素 rbp3 ，然后保存到 rbp 寄存器，此时 rbp 指向 _add 栈帧的基地址，rsp 指向 _add 栈帧的返回地址（使用 rbp 可以恢复到上一个栈帧），看下图：

过程调用指令 call

接下来，我们再来看 main 函数调用 _add 函数的机器指令以及它的内存地址等信息：

先来看上面第 ① 条指令 mov DWORD PTR [rbp - 0x4], 0x3 将一个双字（32 位）的常数 3 复制到内存地址为 rbp - 0x4 的栈内存中（可以看到，因为 rbp 是当前栈帧的基地址，一般不会变，所以作为访问当前栈帧的基地址），然后再来看这条指令对应的机器代码 0xc745fc03000000，其最后的 4 个字节就是双字立即数 0x3（其实就是 0x00000003），可以看到，立即数 0x3 的最低有效字节 0x03 存放在低地址，所以机器采用小端序存储
再来看上面第 ② 条指令 call 400503 <_add> 调用执行 _add 函数的第一条指令（无条件的跳转执行内存地址为 0x400503 的指令 push rbp），那么在 call 指令的机器代码中是如何表示调用目的地址 0x400503 的呢？我们来看这条 call 指令的机器代码 0xe8b1ffffff，其中最高字节 0xe8 是指令 call 的操作码，而剩下的 4 字节是小端序存储的 32 位补码，实际上对应的是 32 位补码 0xffffffb1 = -2^7 + 2^5 + 2^4 + 2^0 = -128 + 32 + 16 + 1 = -79，然后 call 的目的指令的内存地址 0x400503 - 紧跟 call 指令的下一条指令内存地址 0x400552 = -0x4F = - (4 * 16 + 15) = -79 刚好等于 call 指令低 32 位补码，就是说 call 也是采用相对寻址方式来寻址指令的，其目的指令地址 = PC + 低 32 位补码的偏移
