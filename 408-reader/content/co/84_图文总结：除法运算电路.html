原码除法

在进行定点数除法运算前，首先要对被除数和除数的取值和大小进行相应的判断，以确定除数是否为 0、商是否为 0、是否溢出或为不确定的值 NaN。通常的判断操作如下：
  • 若被除数为 0、除数不为 0，或者定点整数除法时 |被除数| < |除数|，则说明商为 0，余数为被除数，不再继续执行
  • 若被除数不为 0、除数为 0，对于整数，则发生 "除数为 0" 异常；对于浮点数，则结果为无穷大
  • 若被除数和除数都为 0，对于整数，则发生除法错异常；对于浮点数，则有些机器产生一个不发信号的 NaN
只有当被除数和除数都不为 0，才进一步进行除法运算。除法运算与乘法运算很相似，都是一种移位和加减运算的迭代过程，而且也需要将符号位和数值位分开处理，商的符号为相除两数符号的异或值，下图是 32 位除法运算逻辑结构：
两个 32 位数相除，必须把被除数扩展成一个 64 位数，就是说，n 位定点数的除法，实际上是用一个 2n 位的数取除以一个 n 位的数，得到一个 n 位的商，因此需要进行被除数扩展，对于 n 位定点正整数相除的话，那么就在被除数的高位填 n 个 0 即可，如果是两个 n 位定点正小数相除的话，那么就在被除数的低位填 n 个 0 即可
除数寄存器 Y 存放除数，余数寄存器 R 开始时置被除数的高 32 位（整数相除的话，就是 32 个 0；小数相除的话，就是 32 位的被除数），作为初始中间余数 R0 的高位部分，结束时存放的是余数；余数/商寄存器 Q 开始时置被除数的低 32 位（整数相除的话，就是 32 位被除数；小数相除的话，就是 32 个 0），作为初始中间余数 R0 的低位部分，结束时存放的是 32 位商；计数器 Cn 初始值是 32，每循环一次，Cn 减 1，当 Cn = 0 时，除法运算结束

每次循环都要对寄存器 R 和 Q 实现同步左移，左移时，Q 的最高位移入 R 的最低位，Q 中空出的最低位上被上商。从低位开始，逐次把商的各个数位左移到 Q 中。每次由控制逻辑根据 ALU 运算结果的符号位来决定上商为 0 还是 1（因为符号位是 1 的话，说明余数减去除数等于负数，不够减，那么需要恢复余数，此时上商 0；如果符号位是 0 的话，则表示够减，上商 1），为判断中间余数的正/负，如果是定点小数的话需在余数寄存器 R 的最高位前增加一位符号位，如果是定点整数的话，使用余数寄存器 R 的最高位作为符号位即可
上面的除法运算是恢复余数除法运算，当中间余数与除数相减结果为负时，要多做一次 +Y 操作，因低了算法执行速度，又使控制线路变得复杂。在计算机中很少采用恢复余数除法，而普用不恢复余数除法
不恢复余数除法算法要点就这 6 个字：正、1、减、负、0、加，意思是，若中间余数为正数，则上商 1，下次做减法，若中间余数为负数，则上商 0，下次做加法
这样运算中每次循环内的步骤都是规整的，差别仅在做加法还是做减法，所以，这种方式也称为加减交替法

补码除法

与补码加减运算、补码乘法运算一样，补码除法也可以将符号位和数值位合在一起进行运算，而且商符直接在除法运算中产生。对于两个 n 位补码除法，被除数需要进行符号扩展。若被除数为 2n 位，除数为 n 位，则被除数无须扩展。同样，首先要对被除数和除数的取值、大小等进行相应的判断，以确定除数是否为 0，商是否为 0、是否溢出等
因为补码除法中被除数、中间余数和除数都是有符号的，所以，不像无符号除法和原码除法那样可以直接用做减法来判断是否够减，而应该根据被除数 (中间余数) 与除数之间符号的异同或差值的正负来确定下次做减法还是加法，再根据加或减运算的结果来判断是否够减
