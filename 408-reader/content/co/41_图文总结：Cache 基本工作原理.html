早期计算机系统的存储器层次结构只有三层：CPU 寄存器、DRAM 主存储器和磁盘存储。不过，由于 CPU 和主存之间逐渐增大的差距，系统设计者被迫在 CPU 寄存器文件和主存之间插入了一个小的 SRAM 高速缓存存储器（cache），如下图所示
cache 的访问速度几乎和寄存器一样快，典型地是大约 4 个时钟周期
在 CPU 和主存之间设置 cache，把主存中被频繁访问的程序块和数据块复制到 cache 中，由于程序访问的局部性，大多数情况下，CPU 能直接从 cache 中取得指令和数据，而不必访问主存，可以提高程序的执行速度

主存块

为了便于 cache 和主存之间交换信息，cache 和主存空间都被划分为相等的区域，主存中的区域称为块，也称为主存块，它是 cache 和主存之间的信息交换单位
Cache 和主存之间每次通过一个主存块交换数据，原因有两个，一个是可以利用好程序的空间局部性，另一个是可以利用突发传输，提高传输效率
这个主存块的大小，一般是设计 Cache 时需要设定的，现在假设主存储器的存储空间大小是 512B，我们假设主存块大小是 32B，那么这个主存可以划分为 512B / 32B = 16 个主存块，如下图：

假设主存按字节编址，那么这个主存的地址是从 0 ~ 511，每个地址对应一个字节数据，0 号主存块包含地址 0 ~ 地址 31 这 32 个字节的数据， 1 号主存块包含地址 32 ~ 地址 63 这 32 个字节的数据，2 号主存块包含地址 64 ~ 地址 95 这 32 个字节的数据
现在，给你一个地址 366，请计算这个地址对应的字节数主存中哪一个主存块的哪一个字节？有两种方法，都要掌握
方法一：将地址除以主存块大小，得到的商就是该地址字节所在主存块的块号，得到的余数就是该地址字节在主存块中的字节序号，比如 366 / 32 商是 11，余数是 14，因此地址 366 对应的字节就是 11 号主存块中的 14 号字节，也就是第 12 个主存块中的第 15 个字节
这里的 11 是主存块号，将主存块号乘以主存块大小，就可以得到这个主存块的起始地址，比如 11 号主存块的起始地址是 11 * 32 = 352，即 11 号主存块的起始地址是 352
这里的 14 是字节的块内偏移，也可以称为块内地址，将主存块起始地址加上块内地址，就可以得到这个字节的真正主存地址，比如 352 + 14 = 366 就是这个字节的主存地址

方法二：将地址 366 转换成二进制地址，因为主存中地址数量是 512 个，那么主存地址是 9 位（2^9 = 512），将地址 366 转换成 9 位二进制地址，就是 1 0110 1110
因为主存块大小是 32B，那么一个主存块内包含 32 个字节，也就是包含了 32 个块内地址，那么需要 5 位才可以表示这 32 个块内地址（2^5 = 32）
所以二进制地址 1 0110 1110 的低 5 位（0 1110）就是块内地址，对应十进制 14，高 4 位（1011）就是主存块号，对应十进制 11
因此，地址 366 对应的字节就是 11 号主存块中的 14 号字节
为什么可以这样来计算呢？因为 366 / 32 得到的余数就是 366 对应二进制位的低 5 位（因为 2^5 = 32），得到的商就是二进制地址的高 4 位
再比如，如果将 366 / 64 的话，得到的余数等于 366 % 64（就是取模），就是拿到 366 对应二进制串的低 6 位（因为 2^6 = 64）
求余数其实就是取模，如果模数（或者说除数）是 2 的 n 次方，那么取模（求余数）就是拿到被除数的低 n 位二进制位

CPU 在 cache 中的访问过程

cache 中存放一个主存块的区域称为行，一个 cache 行大小等于一个主存块大小，一个 cache 被划分成若干个 cache 行，看下图：

主存按字节编址，主存空间大小是 1KB，那么有 1K 个地址，所以主存地址的位数是 10 位（2^10 = 1024 = 1K），主存块大小是 32B，那么主存储器被划分成 1KB / 32B = 32 个主存块，其编号是 0 ~ 31
CPU 中的 cache 被划分成了 4 个 cache 行，每个 cache 行大小等于主存块大小，也就是 32B，因此，这个 cache 可以存储的数据总量 = 4 * 32B = 128B
在系统启动时，每个 cache 行都是空的，其中的信息是无效的，只有装入了主存块后信息才有效
下图，给出了带 cache 的 CPU 执行一次访存操作的过程：

现在 CPU 执行一条 mov [10AH]  eax 指令，就是将内存地址为 10AH 字节的数据传送到 CPU 的 eax 寄存器中
此时，CPU 给出主存地址 AD = 10AH，要去访问主存，此时，先检查这个主存地址 AD 所在的主存块是否在 cache 中：
  • 如果存在的话，那么 cache 命中，那么直接从 cache 中取出数据送到 CPU 的寄存器 eax 中，就不用访问主存了
  • 如果不存在的话，也就是说 cache 缺失，那么聪主存中取出主存地址 AD 所在的主存块，通过突发传输，传输到 cache 中的某一个空闲的 cache 行中，并且把主存地址对应的字节数据送到 CPU 的 eax 中
可以看到，整个访存过程包括判断数据是否在 cache 中，从 cache 中取数据或从主存中取一个主存块到 cache 等工作，当对应 cache 行已满而找不到空闲行时，还要选择将某 cache 行中的信息替换到主存，以使得新的主存块能够存放到该 cache 行中
这些工作要求在一条指令执行过程中完成，因而只能由硬件来实现。因此，cache 对程序员来说是透明的，程序员编程时不用考虑信息存放在主存中还是 cache 中

cache - 主存层次的平均访问时间

CPU 在访存过程中，需要判断所访问信息是否在 cache 中

  • 若在 cache 中，则称 cache 命中，命中的概率称为命中率 p，它等于命中次数与访问总次数之比

  • 若不在 cache 中，则称 cache 未命中（或者称为 cache 缺失），未命中次数与访问总次数之比称为缺失率

cache 命中时，CPU 在 cache 中直接存取信息，所有的时间开销就是访问 cache 的时间 Tc，称为命中时间

cache 缺失时，需要从主存读取一个主存块送到 cache，同时将所需信息送到 CPU，因此，所有时间开销为访问主存的时间 Tm 和 Tc 之和

通常，把从主存读入一个主存块到 cache 的时间 Tm 称为缺失损失

CPU 在 cache - 主存层次的平均访问时间为：Ta = p × Tc + (1 - p) × (Tm + Tc) = Tc + (1 - p) × Tm

由于程序访问的局部性特点，cache 的命中率可以达到很高，即 p 接近于 1。因此，虽然 Tm 远远大于 Tc，但最终的平均访问时间仍可接近 Tc
