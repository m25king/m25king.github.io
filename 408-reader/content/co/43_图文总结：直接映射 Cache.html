还是以这个计算机为例，看下图：

主存按字节编址，主存空间大小是 1KB，那么有 1K 个地址，所以主存地址的位数是 10 位（2^10 = 1024 = 1K），主存块大小是 32B，那么主存储器被划分成 1KB / 32B = 32 个主存块，其编号是 0 ~ 31
CPU 中的 cache 被划分成了 4 个 cache 行，每个 cache 行大小等于主存块大小，也就是 32B，因此，这个 cache 可以存储的数据总量 = 4 * 32B = 128B
现在 CPU 要访问主存中地址为 01 0000 1010 的字节，因为主存块大小是 32B = 2^5B，那么主存地址的低 5 位（0 1010）是块内地址（对应十进制 10），那么高 10 - 5 = 5 位（01 000）就是主存块号（对应十进制 8），也就是说 CPU 要访问主存中 8 号主存块中的 10 号字节
因为现在 cache 中没有 8 号主存块，所以需要通过突发传输将 8 号主存块的数据传输到 cache 中，那么具体是存储到 cache 的哪一个行中呢？也就是说 8 号主存块要映射到 cache 的哪一个行？这就是主存块和 cache 行之间的映射方式了
根据不同的映射规则，主存块和 cache 行之间有以下 3 种映射方式：
  1. 直接映射：每个主存块映射到 cache 的固定行中
  2. 全相联映射：每个主存块映射到 cache 的任意行中
  3. 组相联映射：每个主存块映射到 cache 固定组的任意行中

这篇文章，我们先来学习直接映射

有效位和标记（Tag）

直接映射的基本思想：把主存的每一个主存块映射到固定的一个 cache 行中，也称为模映射
其映射关系是 cache 行号 = 主存块号 % cache 总行数，还是来看这个例子：

这里的 cache 总共有 4 行，根据 8 % 4 = 0 可知，8 号主存块应映射到 0 号 cache 行，再比如 30 % 4 = 2，所以，30 号主存块映射到 2 号 cache 行
根据这种映射关系，那么多个不同的主存块可以映射到同一个 cache 行中，比如上面的 0、4、8 号主存块都会映射到 0 号 cache 行中，现在问题是，cache 又如何判断这个 0 号 cache 行中的数据是哪一个主存块的数据呢？
为了解决这个问题，这里需要为每个 cache 行额外添加两个字段，一个是有效位，一个是标记（tag），如下图：

在系统启动的时候，整个 cache 是空的，所有 cache 行中的数据是无效的，因此，一开始是所有的 cache 行的有效位都是 0，表示对应的 cache 行的数据是无效的，只有当对应主存块装入对应的 cache 行，才将 cache 行对应的有效位设置为 1，说明该 cache 行数据有效，有效位只有 1 位，用于指明这个 Cache 行是否包含有效的信息

那么 CPU 就需要去主存中，将 8 号主存块的数据通过突发传输传输到 0 号 Cache 行中，并且将对应有效位设置为 1，还要将主存地址的高 3 位 001 设置到标记这个字段中，标记这个字段唯一地标识存储在这个 Cache 行中的块，如下图：

标记 Tag 占多少位？

思考问题：那么标记位 Tag 具体占主存地址的多少位呢？
看上图，主存地址被分成低 5 位的块内地址和高 5 位的主存块号，因为 Cache 行大小等于主存块大小，所以，块内地址也是 Cache 行行内地址，根据这个块内地址就可以定位到 Cache 行中的字节位置，比如上图的主存地址的块内地址是 01010，即十进制的 10，那么 CPU 需要的字节就在 0 号 cache 行的第 11 个字节（上图红色框框）
我们将主存块号和 Cache 总行数取模就得到主存块对应 Cache 行行号，一般来说，Cache 总行数是 2 的幂，比如 2^c，那么主存块号 % 2^c，就是拿到主存块号对应二进制的低 c 位，比如上图 Cache 总行数是 2^2，那么主存块号对应二进制的低 2 位就是 Cache 行号，主存块号的高 5 - 2 = 3 位（010）就是标记 Tag 了，如下图：

假设计算机的主存地址是 m 位，那么主存地址总数 M = 2^m，如果主存块大小 B = 2^b 字节，Cache 总行数是 2^c，此时 Cache 行的标记 Tag 占主存地址多少位呢？
首先，因为主存块大小 B = 2^b 字节，那么块内地址占 b 位，并且是位于主存地址的低 b 位
然后，可以计算出主存地址高 m - b 位是主存块号，因为 Cache 总行数是 2^c，那么主存块号的低 c 位是Cache 行号，如下图：

最后，就可以计算标记 Tag 占 m - b - c 位，位于主存地址的高位

Cache 总容量计算

思考问题：上面的 Cache 总容量是多少呢？
一个 Cache 包含了 2 个区，分别是标志区和数据区，如下图：

标志区包含了所有 Cache 行对应的标志位，比如标记 Tag、有效位；数据区就是存储主存块数据的区域
Cache 总容量 = 标志区容量 + 数据区容量，数据区容量 = 主存块大小 × Cache 总行数；而要计算标志区容量的话，需要先计算出标记 Tag 占多少位，然后可以计算标志区容量 = （标记 Tag 位数 + 有效位的 1 位） × Cache 总行数
比如上图中的 Cache 数据区容量 = 主存块大小 × Cache 总行数 = 32B × 4 = 128B；标志区容量 = （标记 Tag 位数 + 有效位的 1 位） × Cache 总行数 = (3 位 + 1 位) × 4 = 16 位 = 2B，所以 Cache 总容量 = 标志区容量 + 数据区容量 = 2B + 128B = 130B
你也可以这样计算 Cache 总容量 = （标记 Tag 位数 + 有效位的 1 位 + 主存块大小）× Cache 总行数 = （3 位 + 1 位 + 32B） × 4 = 130B

CPU 访存过程

前面我们说，在直接映射的 Cache 中，为了寻址 Cache 中的数据，Cache 会将主存地址划分成标记 Tag、Cache 行号和块内地址三部分，如下图：

其中 Cache 行号占用位数由 Cache 总行数计算得到，块内地址占用位数由主存块大小计算得到，而标记 Tag 位数 = 主存地址位数 m - c - b
接下来看，在直接映射的 Cache 中 CPU 访存过程，如下图：

首先根据主存地址中间的 c 位表示的 Cache 行号，直接找到对应的 Cache 行；然后将对应 Cache 行中的标记 Tag 和主存地址的高 t 位进行比较（这里需要一个比较器）
  • 如果相等并且有效位为 1，则访问 Cache 命中，此时，根据主存地址中低 b 位的块内地址，在对应的 Cache 行中存取信息

  • 如果不相等或有效位为 0，则访问 Cache 不命中（缺失），此时，CPU 从主存中读出该地址所在的主存块信息送到对应的 Cache 行中，将有效位设置为 1，并将标记 Tag 设置为地址中的高 t 位，同时将该地址对应的数据送到 CPU
再来看一个具体的采用直接映射的 Cache 例子，如下图：

该 Cache 的 Cache 行大小是 16B，因此主存块大小也是 16B = 2^4B，从上图可以看到，主存地址的低 4 位是块内地址，因此，这个计算机的主存采用按字节编址，一个字节一个地址
从上图可以看出，一个字等于 4B，如果是按字编址的话，一个主存块中只有 16B / 4B = 4 个字，那么块内地址只需要 2 位就可以表示了（2^2 = 4）
该 Cache 的总行数是 4K = 2^12，因此，主存地址的中间 12 位表示 Cache 行号，那么标记 Tag 占的位数 = 主存地址位数 - 块内地址位数 - Cache 行号位数 = 32 - 4 - 12 = 16 位
Cache 总容量 = 标志区容量 + 数据区容量 = （标记位数 + 有效位位数）× Cache 总行数 + Cache 行大小 × Cache 总行数 = （标记位数 + 有效位位数 + Cache 行大小） × Cache 总行数 = （1位 + 16 位 + 128 位） × 4K = 72.5KB
再来看 CPU 的访存过程：

访存的第一步是根据 Cache 行号直接定位到主存块所在的 Cache 行
第二步将 16 位的标记与对应行中的标记进行比较
第三步将标记比较结果和有效位取与运算，如果比较相等并且有效位 V 为 1 时，则输出 1，表示命中
接下来读取 Cache 行中的数据，假设这里按照存储字来读取，到底要读取哪一个字，这个取决于块内地址的高 2 位，块内地址的高两位可以确定读取哪一个字，如果要读取一个字节的话，可以由块内地址的低 2 位选择读取哪一个字节，最终输出主存地址对应的字节
比如块内地址是 1011，前 2 位 10 表示块内字的地址是 2，后 2 位 11 表示字内字节的地址是 3，即要访问 Cache 行中的 2 号字中的 3 号字节（即第 3 个字的第 4 个字节）
如果 CPU 要读取的是字的话，就从上面第 4 步拿到数据，如果 CPU 要读取的是字节的话，就从第 5 步拿到数据
如果第三步输出的是 0，也就是缓存未命中的话，则 CPU 要启动一个 Cache 行读总线事务操作，通过存储器总线到主存中通过突发传输读一块连续的数据到 Cache 行中
