主存按字节编址，那么一个存储单元就是一个字节，块大小 B = 16B，那么对于一个地址为 A 的单元，它所在的主存块的块号 = A / B （注意，需要向下取整）


因为 Cache 有 16 行


如果采用直接映射的话，主存块映射到的 Cache 行号 = 主存块号 % Cache 总行数 = （A / B） % Cache 总行数


如果采用 2-路组相联映射的话，每组有 2 行，那么 Cache 组数 = 16 / 2 = 8，那么主存块映射到的 Cache 组号 = 主存块号 % Cache 组数 = （A / B） % Cache 组数


对于 A，52 号和 102 号单元


直接映射的话：

  • 地址 52 的单元所在的 Cache 行行号 = （A / B） % Cache 总行数 = （52 / 16）% 16 = 3

  • 地址 102 的单元所在的 Cache 行行号 = （A / B） % Cache 总行数 = （102 / 16）% 16 = 6


两个单元所在主存块没有映射到同一行，所以在直接映射下，不会产生 Cache 冲突，因此，排除 A


对于 B，48 号和 308 号单元


直接映射的话：

  • 地址 48 的单元所在的 Cache 行行号 = （A / B） % Cache 总行数 = （48 / 16）% 16 = 3

  • 地址 308 的单元所在的 Cache 行行号 = （A / B） % Cache 总行数 = （308 / 16）% 16 = 3


两个单元所在主存块映射到同一行，所以在直接映射下，会因此 Cache 冲突


再来看 2 路组相联：

  • 地址 48 的单元所在的 Cache 组组号 = （A / B） % Cache 组数 = （48 / 16）% 8 = 3

  • 地址 308 的单元所在的 Cache 行行号 = （A / B） % Cache 组数 = （308 / 16）% 8 = 3


即 48 号和 308 号单元所在的主存块，映射到同一个 Cache 组，因此，有可能会产生冲突


所以，不管在哪一种映射方式下，访问 48 号和 308 号单元 都有可能产生冲突，本题选 B

在 Cache 中，常用的替换策略有随机法 (RAND)、先进先出法 (FIFO)、近期最少使用法 (LRU)，其中与局部性原理有关的是 ( )。

A.随机法 (RAND)
B.先进先出法 (FIFO)
C.近期最少使用法 (LRU)
D.都不是

随机法 (RAND) 算法的思想：从候选行的主存块中随机选取一个淘汰掉，与使用情况无关，A 错误


FIFO 算法的基本思想是：总是选择淘汰最早装入 Cache 的主存块，这种算法实现方便，但不能正确反映程序的访问局部性，因为最先进入 Cache 的主存块也可能是目前要用的，因此，这种算法有可能产生较大的缺失率，因此 B 错误


LRU 算法的基本思想是：总是选择淘汰近期最少使用的主存块。这种算法能比较正确的反应程序的访问局部性，因为当前最少使用的块一般来说也是将来最少被访问的，本题选 C


下列关于 Cache 替换算法的叙述中，错误的是 ( )。

A.组相联映射和全相联映射都必须考虑如何进行替换
B.先进先出算法无须对每个 Cache 行记录替换信息
C.直接映射是多对一的映射，无须考虑替换问题
D.LRU 算法需要对每个 Cache 行记录替换信息
组相联和全相联映射下，多个主存块会映射到同一个 Cache 组 / 行集合中，当集合满时必须选择替换哪一块，因此必须考虑替换算法，因此，A 正确

先进先出（FIFO）算法需要记录每个 Cache 行的调入顺序，以此判断谁是最早进入的块，因此必须对每个 Cache 行记录替换信息（如时间戳或顺序号），B 错误，本题选 B

直接映射是多对一映射，每个主存块只能映射到唯一的 Cache 行，若该行已被占用则直接覆盖，无需选择替换对象，因此无须考虑替换问题，C 正确

最近最少使用（LRU）算法需要记录每个 Cache 行的最近使用时间，以此判断谁是最久未被使用的块，因此必须对每个 Cache 行记录替换信息（如使用位或时间戳），D 正确

全写法（写直达）和回写法（写回）是写操作的更新策略，与读操作无关。读命中时直接读取 Cache 数据，不涉及写策略，A 错误

回写法是写命中时的策略，但写分配法是写失效时的策略，并非写命中时应用，B 错误

全写法和写分配法均与读操作无关，读操作失效时只会加载数据到 Cache，不触发写策略，C 错误

写操作失效时，会采用写分配法（将主存块加载到 Cache 后再写）或非写分配法（直接写主存，不加载到 Cache），二者都是写失效时的处理策略，本题选 D

在不同的情况下，需要采用适合的 Cache 写策略。对于下面两种情况：① 主要运行访问密集型应用，其中包含写操作；② 安全性要求很高，不允许有任何数据不一致的情况发生。适合它们的写策略分别是 ( )。

A.回写法，全写法
B.全写法，回写法
C.回写法，回写法
D.全写法，全写法
场景①：主要运行访问密集型应用，包含写操作

访问密集型应用对性能要求高，回写法（写回法） 更适合：写命中时只更新 Cache，仅当脏块被替换时才写回主存，能大幅减少总线写操作次数，提升系统效率，适合频繁读写的场景

若使用全写法，每次写操作都要同步更新主存，会产生大量总线开销，降低性能

场景②：安全性要求很高，不允许任何数据不一致

安全性优先的场景需要强数据一致性，全写法（写直达法） 更适合：写命中时同时更新 Cache 和主存，保证 Cache 与主存数据始终一致，避免因系统故障导致数据丢失或不一致

回写法存在脏块暂存于 Cache、未及时写回主存的窗口，有数据不一致风险，不满足高安全性要求

在多级 Cache 中，有全局缺失率和局部缺失率两种不同的概念：
  • 全局缺失率是指在所有级 Cache 中都缺失的访问次数占总访问次数的比例
  • 局部缺失率是指在某级 Cache 中缺失的访问次数占对该级 Cache 的总访问次数的比例

这里是求总命中率，其实就是求全局命中率，即所有级 Cache 中都命中的访问次数占总访问次数的比例


总的访问此时是 1000 次，最终只有 10 次未命中，需要去访问内存，因此总命中率 = (1000 - 10) / 1000 = 99%，本题选 A


对于第一级 Cache，总的访问次数是 1000 次，其中 40 次未命中，所以，第一级 Cache 的局部命中率 = (1000 - 40) / 1000 = 96%

采用合适的地址映像方式 → 如组相联映射相比直接映射，能减少冲突缺失，可提高命中率。D 正确

【2012 第 17 题】假设某计算机按字编址，Cache 有 4 个行，Cache 和主存之间交换的块大小为 1 个字。若 Cache 的内容初始为空，采用 2 路组相联映射方式和 LRU 替换策略。访问的主存地址依次为 0,4,8,2,0,6,8,6,4,8 时，命中 Cache 的次数是（ ）

A.1
B.2
C.3
D.4
首先，主存是按字编址的，也就是一个地址对应一个字，而且主存和 Cache 之间交换的块大小也是 1 个字，所以说，当 CPU 向主存访问一个地址时，这个地址对应的字就是一个主存块，会占用 Cache 的一个缓存行

因此，块内地址位数 b = 0 (1 = 2^0)，也就是说，整个主存地址就是主存块号，没有块内地址


而 Cache 总共有 4 行，采用 2 路组相连映射方式，也就是每组 2 行，因此 Cache 有 4 / 2 = 2 组，所以，我们就可以简单的将 CPU 访问主存地址和 Cache 组数 2 取模，就可以得到该主存地址映射到 Cache 的哪一组中

【2015 第 15 题】假定主存地址为 32 位，按字节编址，主存和 Cache 之间采用直接映射方式，主存块大小为 4 个字，每字 32 位，采用回写 (Write Back) 方式，则能存放 4K 字数据的 Cache 的总容量的位数至少是（ ）

A.146k
B.147K
C.148K
D.158K

记住公式：Cache 总容量 = 单 Cache 行容量 × 总行数


Cache 总行数 = Cache 存储数据的容量 ÷ 主存块大小 = 4K 字 ÷ 4 字 = 1K


单 Cache 行容量 = 标记 tag 位数 + 有效位 + 脏位 + 主存块大小，在这里有效位是 1 位、脏位是 1 位（因为题目规定使用回写方式，因此需要 1 位脏位）、主存块大小等于 4 字 * 32 位 = 128 位，如下图



接下来，需要求标记 tag 的位数，在直接映射方式下，主存地址被分为 3 个字段，如下图：

因为主存块大小是 128 位，也就是 16 字节，因为主存按字节编址，因为一个字节对应一个地址，所以块内地址位数 b = 4 （16 B = 2^4 × 1B）；因为 Cache 总行数是 1K，因此 Cache 行号的位数 c = 10（1K = 2^10）；而主存地址总位数 m 是 32 位，所以标记 tag 的位数 t = m - b - c = 32 - 4 - 10 = 18 位


因此，单 Cache 行容量 = 标记 tag 位数 + 有效位 + 脏位 + 主存块大小 = 18 位 + 1 位 + 1 位 + 128 位 = 148 位


所以，Cache 总容量 = 单 Cache 行容量 × 总行数 = 148 位 × 1K = 148K 位，选 C


一般而言，一个 Cache 行包含标记 tag、有效位以及缓存块，如果题目要求采用回写方式来保证 Cache 和主存的数据一致性，那么一个 Cache 行还需要加上 1 位脏位


如果题目要求采用 LRU 替换算法的话，那么一个 Cache 行还需要加上 LRU 位，至于加多少位的 LRU 位，取决于一个 Cache 组中的行数，如果 Cache 组中有 2 行，那么 LRU 位是 1 位，如果 Cache 组有 4 行，那么 LRU 位是 2 位，LRU 的位数 = log2n，n 是 Cache 组内的行数，不过这个题目的 Cache 是直接映射方式，采用的是直接替换，不需要任何替换算法

【2021 第 16 题】若计算机主存地址为 32 位，按字节编址，Cache 数据区大小为 32KB，主存块大小为 32B，采用直接映射方式和回写 (Write Back) 策略，则 Cache 行的位数至少是 ( )。

A.275
B.274
C.258
D.257

一个 Cache 行容量大小 = 标记 tag 位 + 1 位有效位 + 1 位脏位 + 主存块大小


因为题目规定采用回写策略保证 Cache 和主存的数据一致性，所以一个 Cache 行还包括 1 位脏位；主存块大小是 32B，也就是 256 位


接下来只要求标记 tag 位，题目规定采用直接映射方式，在直接映射方式下，地址被划分成了 3 个字段：

首先，主存块大小是 32B，并且是按字节编址，因此块内地址位数 b = 5（因为 2^5 = 32）；因为 Cache 数据区大小为 32KB，那么 Cache 中共有 32KB / 32B = 1K 个 Cache 行，那么 Cache 行号的位数 c = 10（因为 2^10 = 1K）


因为主存地址是 32 位，即 m = 32 位，所以标记 tag 的位数 t = m - b - c = 32 - 5 - 10 = 17 位


所以，一个 Cache 行容量大小 = 标记 tag 位 + 1 位有效位 + 1 位脏位 + 主存块大小 = 17 位 + 1 位 + 1 位 + 256 位 = 275 位，所以选 A
