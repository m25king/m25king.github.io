因为空闲表使用数组来实现，使用空闲表法管理磁盘空闲盘块时，如果释放盘块删除合并空闲区，可能需要移动空闲表中的表项数据，这样会影响磁盘分配和释放的性能，这个也是数组的缺点，为了避免表项数据移动，我们可以使用空闲链表法来实现磁盘分配表，空闲链表法有两种实现方式，分别是空闲盘块链和空闲盘区链

空闲盘块链

所谓空闲盘块链就是将所有的空闲盘块组织成单链表（看下图（a））
当需要为某个文件分配 3 个盘块时，只需要从表头，依次拿到 3 个盘块分配给这个文件即可，看上图（b）将 2、3、4 号盘块分配给文件；当用户删除了文件，释放对应的盘块时，文件系统将回收的盘块依次挂在空闲盘块链的末尾，看上图（c）依次释放 12、13、14 号盘块，依次挂在链表表尾；这种方法的优点是分配和回收一个盘块的过程非常简单，不会涉及到数据的移动
思考一个问题：在文件系统中，这个单链表如何用代码实现？有两种方法，分别是显示链接和隐式链接

显示链接

所谓显式链接就是在内存中显示的维护这个单链表（看下图），单链表中的每个结点包含空闲盘块号和下一个结点的指针，然后定义 head 指针指向头结点，tail 指针指向尾结点
在内存中，就会存在一个 FreeList 实例以及多个 Node 实例（有多少个空闲盘块，就会有多少个 Node 实例），假设在 64 位机器上，一个指针占 8 个字节，那么一个结点 Node 实例占 12 字节，上图有 15 个结点和 2 个指针，所以总共占的内存大小是 12B * 15 + 8B * 2 = 196B
上面的空闲盘块号使用 32 位的 unsigned 表示，可以表示的序号范围是 0 ~ 2^32 - 1，也就是说最多可以表示 2^32 个空闲盘块，假设每个盘块的大小是 1KB，那么能表示的最大的磁盘空间大小是 2^32 * 1KB = 4TB

隐式链接

所谓隐式链接是指，在每个空闲盘块中存放下一个空闲盘块的地址或者说盘块号，然后在内存中，维护单链表中表头的盘块号（head）用于分配，维护表尾的盘块号（tail）用于回收，比如下图的 head = 2，tail = 23
也就是说每一个盘块存放两部分内容数据，一部分是存放文件数据，另一部分存放的是下一个空闲盘块的盘块号；假设一个盘块大小是 1KB，然后盘块号使用 32 位的 unsigned 类型来表示，即一个盘块号占 4B，所以，对于一个盘块可以存放文件数据的部分大小是 1KB - 4B = 1020B
使用上面的隐式链接可以管理的最大的磁盘空间是 2^32 * 1KB = 4TB，但是能存储文件数据的磁盘空间是 2^32 * 1020B = 2040GB
显示链接分配和释放盘块时不用去读磁盘块，直接基于内存中的单链表分配释放盘块号即可，这样速度快，但是它比较占内存；而隐式链接则不耗内存，不过每次分配和释放一个盘块时，都需要读写磁盘块（因为要更新磁盘块中的下一个盘块号），性能相对比较差，而且隐式链接中，盘块需要一部分空间来存储下一个盘块号，这样会减少磁盘存储文件数据的空间
对于空闲盘块链是以盘块为单位，如果空闲盘块很多的时候，相应的空闲盘块链会很长，同时在为一个文件分配多个盘块时，可能要重复操作多次，因为是一个盘块一个盘块的分配，分配和回收的效率较低，为了避免空闲盘块链的这些缺点空闲盘区链

空闲盘区链

空闲盘区链就是将所有的空闲盘区组织成单链表，每一个空闲盘区对应一个单链表结点，每个结点包含起始盘块号、空闲盘块数以及指向下一个空闲区的指针，同时分别使用头指针 head 和尾指针 tail 来辅助分配和回收盘块
很明显，这个链表就比较短了，占用的内存也少了很多，假设一个指针占 8 个字节，上图的一个结点占用内存大小是 4B + 4B + 8B = 16B，那么上图的单链表占用内存空间大小是 5 * 16B + 2 * 8B = 96B，占用内存比前面的空闲盘块链的显示链表要少很多
对于空闲盘区链，进行分配盘块时，可以遍历内存中的单链表，然后可以采用首次适应分配算法、最佳适应分配算法或者最坏适应分配算法；回收盘块时，需要考虑相邻的空闲盘区进行合并，比如，在上图中，现在回收 20 和 21 号盘块，就要合并最后的 3 个相邻的空闲盘区为 1 个空闲盘区（即起始盘块号是 15，空闲盘块数是 9）
空闲盘区链的优点和缺点刚好与空闲盘块链的优缺点相反，即分配与回收的过程比较复杂，但分配和会收的效率可能较高，每次为文件分配多个连续的块，且空闲盘区链较短
