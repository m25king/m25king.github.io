【09-24】下列进程调度算法中，综合考虑进程等待时间和执行时间的是（ ）

A.时间片轮转调度算法
B.短进程优先调度算法

C.先来先服务调度算法
D.高响应比优先调度算法
A. 时间片轮转调度算法：该算法按照固定的时间片为就绪队列中的进程轮流分配 CPU 时间。其主要考虑的是进程的公平性，让每个进程都能得到及时响应，不直接综合考虑等待时间和执行时间

B. 短进程优先调度算法：此算法优先选择执行时间最短的进程投入运行。它的核心是缩短平均周转时间，但只侧重进程的执行时间，忽略了等待时间，可能导致长进程长期等待（即产生了饥饿）

C. 先来先服务调度算法：该算法按照进程到达就绪队列的先后顺序分配 CPU，先到达的进程先执行。它仅考虑进程的等待顺序（等待时间的先后），不涉及执行时间的综合评估，容易出现 "长进程阻塞短进程" 的情况

D. 高响应比优先调度算法：其响应比计算公式为：响应比 =（等待时间 + 执行时间）/ 执行时间，从公式可以看出，该算法同时兼顾了进程的等待时间（等待时间越长，响应比越高）和执行时间（执行时间越短，响应比相对越高），综合考虑了两者的影响，既避免了长进程无限期等待，又能优先调度短进程


综上，综合考虑进程等待时间和执行时间的调度算法是高响应比优先调度算法，本题选 D


不理解高响应比优先调度算法的话，请复习：高响应比优先调度算法

【10-26】下列选项中，降低进程优先级的合理时机是（ ）

A.进程的时间片用完
B.进程刚完成 I/O，进入就绪列队
C.进程长期处于就绪列队中
D.进程从就绪状态转为运行状态
A. 进程的时间片用完：在时间片轮转调度算法中，进程用完分配的时间片后会被暂停，回到就绪队列。此时降低其优先级是合理的：一方面，该进程已经占用过 CPU 资源，暂时降低优先级可让其他进程获得运行机会，保证公平性；另一方面，避免某一进程通过反复用完时间片而过度占用 CPU，符合调度策略的平衡原则

B. 进程刚完成 I/O，进入就绪队列：进程完成 I/O 操作后，通常需要及时处理 I/O 的结果（如用户输入、数据读取等），此时应保证其能尽快获得 CPU 响应（例如采用 I/O 优先调度）。若降低其优先级，可能导致该进程迟迟无法运行，拖延 I/O 后续处理，不合理

C. 进程长期处于就绪队列中：进程长期等待而无法获得 CPU 时，说明其优先级可能过低或被其他高优先级进程阻塞。此时应提高其优先级（避免 "饥饿" 现象），而非降低（如果降低的话，则不符合调度策略的公平原则），因此该选项不合理

D. 进程从就绪状态转为运行状态：进程即将获得 CPU 运行时，若降低其优先级，可能导致其被其他进程抢占，无法正常执行。这违背了调度的初衷（让就绪进程转为运行状态是为了使其执行），不合理

综上，只有当进程的时间片用完时，降低其优先级是合理的时机，我们在学习【多级反馈队列（MLFQ）】的时候，也讲过，一个进程在最高级别的队列中，用完了一个时间片，就可以将其放到优先级稍微低一点的队列中
这里补充下调度策略的基本准则

不同的 CPU 调度算法具有不同属性，选择一个特定算法会对某些进程更为有利。为了选择算法以便用于特定情景，我们必须考虑各个算法的属性

为了比较 CPU 调度算法，可以采用许多比较准则。选择哪些特征来比较，对于确定哪种算法是最好的有本质上的区别

这些准则包括：

① CPU 使用率：应使 CPU 尽可能地忙碌。从概念上讲，CPU 使用率从 0% 到 100%，对于一个实际系统，它的范围应从 40% (轻负荷系统) 到 90% (重负荷系统)

② 吞吐量：如果 CPU 忙于执行进程，那么工作就在完成。一种测量工作的方法称为吞吐量，它是在一个时间单元内进程完成的数量。对于长进程，吞吐量可能为每小时一个进程；对于短进程，吞吐量可能为每秒十个进程

③ 周转时间：从一个特定进程的角度来看，一个重要准则是运行这个进程需要多长时间。从进程提交到进程完成的时间段称为周转时间。周转时间为所有时间段之和，包括等待进入内存、在就绪队列中等待、在 CPU 上执行和 I/O 执行

不过，为了简化问题，一般将进程完成时间减去到达就绪队列的时间称为周转时间

④ 等待时间：CPU 调度算法并不影响进程运行和执行 I/O 的时间，它只影响进程在就绪队列中因等待所需的时间。等待时间为在就绪队列中等待所花时间之和

⑤ 响应时间：对于交互系统，周转时间不是最佳准则。通常，进程可以相当早地产生输出，并且继续计算新的结果同时输出以前的结果给用户。因此，另一时间是从提交请求到产生第一响应的时间。这种时间称为响应时间，是开始响应所需的时间，而非输出响应所需的时间。周转时间通常受输出设备速度的限制

最大化 CPU 使用率和吞吐量，并且最小化周转时间、等待时间和响应时间，这是可取的。在大多数情况下，优化的是平均值。然而，在有些情况下，优化的是最小值或最大值，而不是平均值。例如，为了保证所有用户都能得到好的服务，可能要使最大响应时间最小

还需要考虑公平性和平衡性：

⑥ 公平性：公平性是指应使诸进程都获得合理的 CPU 时间，不会发生进程饥饿现象。公平性是相对的，对相同类型的进程应获得相同的服务；但对于不同类型的进程，由于其紧急程度或重要性的不同，则应提供不同的服务

⑦ 平衡性：由于在系统中可能具有多种类型的进程，有的属于计算型作业，有的属于 I/O 型。为使系统中的 CPU 和各种外部设备都能经常处于忙碌状态，调度算法应尽可能保持系统资源使用的平衡性

【11-29】当系统发生抖动 (thrashing) 时，可以采取的有效措施是（ ）
I：撤销部分进程
II：增加磁盘交换区的容量
III：提高用户进程的优先级

A.仅 I
B.仅 II
C.仅 III
D.仅 I、II
要分析该题，首先需要明确抖动（thrashing）的本质：当系统中进程过多，导致每个进程分配到的物理块数量不足，频繁发生页面置换（刚换出的页面很快又需要换入），使得 CPU 大部分时间用于处理页面交换，而非执行进程指令，系统效率急剧下降。解决抖动的核心是减少系统中并发进程的数量，降低对物理内存的总需求


对于抖动，不理解的话，请复习视频：抖动和工作集


I：撤销部分进程：撤销部分进程可以减少系统中并发运行的进程数量，从而释放出一部分物理块，使剩余进程能获得更多物理块，减少页面置换频率，有效缓解抖动。这是解决抖动的经典有效措施，合理


II：增加磁盘交换区的容量：抖动的根源是物理内存不足导致的频繁页面置换，而非交换区容量不够。即使交换区容量增大，只要物理内存仍无法满足进程需求，页面置换的频率不会降低，抖动依然存在。因此，增加交换区容量无法解决抖动，不合理


对于什么是交换区，请复习：缺页异常处理流程中添加判断页面置换功能，最后一个视频


III：提高用户进程的优先级：优先级调整仅影响进程获取 CPU 的顺序，与物理内存分配和页面置换无关，无法解决因内存不足导致的抖动问题。反而可能因高优先级进程持续运行，加剧对内存的占用，不合理


综上，只有撤销部分进程是降低抖动的有效措施，答案为 A

【14-23】下列调度算法中，不可能导致饥饿现象的是（ ）

A.时间片轮转
B.静态优先数调度
C.非抢占式短作业优先
D.抢占式短作业优先

要判断调度算法是否会导致饥饿现象（即某些进程长期无法获得 CPU 资源），需分析其调度逻辑是否可能使部分进程被无限期延迟


A. 时间片轮转：该算法为就绪队列中的每个进程分配固定的时间片，进程用完时间片后立即让出 CPU，回到就绪队列等待下一轮调度


其核心是公平性，每个进程无论优先级、执行时间长短，都会按顺序轮流获得 CPU 时间。即使有新进程不断加入，旧进程也会在后续轮次中得到执行机会，不会出现某个进程长期无法运行的情况，因此不可能导致饥饿现象


B. 静态优先数调度：静态优先数在进程创建时确定，且运行过程中不改变。若系统中存在大量高优先级进程，低优先级进程会一直被阻塞，无法获得 CPU 资源，可能导致饥饿。例如，实时进程（高优先级）持续运行时，普通进程（低优先级）可能长期等待


对于优先数调度，请复习：优先级调度算法


C. 非抢占式短作业优先：该算法优先调度执行时间最短的进程，且一旦某个进程开始运行，不会被打断。若系统不断有新的短作业到达，长作业会一直处于就绪队列，可能长期无法获得 CPU，导致饥饿


D. 抢占式短作业优先：当有更短的新作业到达时，当前运行的长作业会被抢占 CPU。若新的短作业持续不断地进入系统，长作业会被反复抢占，始终无法完成，必然导致饥饿


综上，只有时间片轮转算法能保证所有进程定期获得 CPU 时间，不可能导致饥饿现象，本题选 A


对于非抢占短作业优先和抢占式短作业优先，可以复习：FIFO、SJF 调度算法（周转时间）


另外，先来先服务调度算法（也就是 FIFO）不可能出现饥饿现象，因为按照作业到达时间来调度，不管怎么样，所有到达的进程都会被调度执行

I：就绪队列的数量：多级反馈队列的核心是 “多级”，即设置多个就绪队列。队列数量的设计直接影响调度的灵活性和系统性能（如队列过多会增加管理开销，过少则无法体现优先级差异）。因此，就绪队列的数量是设计时必须考虑的因素，I 需要考虑

II：就绪队列的优先级：多级反馈队列中，不同队列具有不同的优先级（通常编号越小的队列优先级越高）。优先级决定了进程调度的先后顺序（高优先级队列的进程优先获得 CPU），是算法的核心机制之一。因此，II 需要考虑

III：各就绪队列的调度算法：不同队列可采用不同的调度算法：例如，高优先级队列可能采用时间片轮转（时间片较短），低优先级队列可能采用时间片轮转（时间片较长）或其他策略。各队列调度算法的选择直接影响进程的响应速度和公平性，III 需要考虑

IV：进程在就绪队列间的迁移条件：反馈机制体现在进程会根据执行情况在队列间迁移：例如，若高优先级队列的进程用完时间片仍未完成，会被迁入低优先级队列；若低优先级队列的进程等待时间过长，可能被提升到高优先级队列（避免饥饿）。迁移条件是维持算法平衡的关键，IV 需要考虑

综上，设计多级反馈队列调度算法时，I、II、III、IV 均需考虑，答案为 D

分时系统的时间片轮转调度核心是让进程按固定时间片轮流使用 CPU

I：进程控制块（PCB）：PCB 是进程存在的唯一标识，记录了进程的状态（运行、就绪等）、剩余时间片、优先级等关键信息。时间片轮转调度中，需要通过 PCB 跟踪进程的时间片使用情况和状态，是实现调度的基础数据结构。因此，I 需要使用

II：时钟中断处理程序：时间片轮转依赖时钟中断触发时间片的更新：每当时钟中断发生，系统会减少当前运行进程的剩余时间片。当时间片为 0 时，触发进程切换（将当前进程转为就绪态，调度下一个就绪进程）。因此，时钟中断处理程序是时间片轮转的核心驱动机制，II 需要使用

III：进程就绪队列：就绪队列用于存放等待 CPU 的就绪态进程。时间片轮转中，进程用完时间片后会回到就绪队列，新调度的进程从就绪队列中选取，队列的维护（如入队、出队）是调度的关键环节。因此，III 需要使用

【25-25】某基于优先权的进程调度程序中，进程就绪队列采用优先权由高到低的有序单链表实现。若就绪队列长度为 n，则就绪队列的插入操作和从就绪队列中选出将要执行进程的操作的时间复杂度分别是（ ）

A.O(1)，O(1)
B.O(1)，O(n)
C.O(n)，O(1)
D.O(n)，O(n)
在优先权调度中，就绪队列采用单链表存储，且高优先级进程位于队头。需分别分析插入进程和选出进程的时间复杂度：

插入进程的时间复杂度（O (n)）：插入新进程时，需保证单链表的有序性（高优先级在前）。因此，必须从队头开始遍历链表，找到新进程的正确插入位置（即第一个优先级低于新进程的位置）。在最坏情况下（如新进程优先级最低），需要遍历整个链表（长度为 n），因此时间复杂度为 O(n)

选出进程的时间复杂度（O (1)）：选出进程时，根据优先权调度规则，总是选择优先级最高的进程，而高优先级进程位于队头。因此，只需直接获取链表的第一个节点（队头元素）即可，无需遍历链表，时间复杂度为 O(1)

综上，插入进程的时间复杂度为 O (n)，选出进程的时间复杂度为 O (1)，答案为 C
