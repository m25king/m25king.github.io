运行操作系统代码时，也就是 CPU 执行的是操作系统的代码，那么 CPU 的状态为核心态，也称为内核态

B.将运算结果装入内存
C.算术运算
D.输入/输出

对于 B，将运算结果装入内存指令是非特权指令，同样是操作进程自身内存，用户态可执行


对于 C，算术运算指令是非特权指令，加减乘除等运算属于进程私有操作，用户态可执行


CPU 处于核心态时，它可以执行的指令是 ( )。

A.只有特权指令
B.只有非特权指令
C.只有 "访管" 指令
D.除 "访管" 指令的全部指令
访管指令：用户态程序用来发起系统调用、陷入内核态的指令（如 int 0x80、syscall），核心态可以执行特权指令 + 非特权指令，但访管指令是给用户态程序用的，核心态本身不需要通过访管指令来请求内核服务，因此核心态可以执行除访管指令外的全部指令，本题选 D

操作系统区分内核态和用户态是为了保护系统资源。下列程序或处理过程中，哪一个主要运行在用户态? ( )

A.系统调用服务例程
B.进程切换程序
C.文本编辑器应用程序
D.I/O设备中断处理程序
操作系统将CPU的执行状态分为用户态和内核态。用户态下执行非特权指令，内核态下可以执行特权指令和非特权指令。用户程序运行在用户态，而操作系统内核及相关模块运行在内核态

A.系统调用服务例程：系统调用是用户程序请求操作系统服务的接口。当用户程序执行系统调用时，会通过陷入 (trap) 指令从用户态切换到内核态，由内核执行相应的服务例程。因此，系统调用服务例程运行在内核态

B.进程切换程序：进程切换涉及修改进程控制块 (PCB)、更新内存管理信息 (如页表基址寄存器)、保存和恢复 CPU 现场等操作。这些操作需要访问受保护的系统资源和执行特权指令，因此进程切换程序必须运行在内核态

C.文本编辑器应用程序：文本编辑器是用户应用程序，用于处理文本文件。它的大部分功能，如编辑文本、响应用户输入 (不涉及系统调用时) 等，都运行在用户态。只有当它需要操作系统服务时 (如读写文件、申请内存等)，才会通过系统调用短暂进入内核态。因此，文本编辑器主要运行在用户态，本题选 C

D.I/O 设备中断处理程序：当 I/O 设备完成操作后，会向 CPU 发送中断信号。CPU 响应中断后，会从用户态切换到内核态（如果此时 CPU 位于用户态的话），执行相应的中断处理程序来处理中断事件。因此，中断处理程序运行在内核态

以下哪些事件或操作必然会触发 CPU 从用户态转换到内核态? ( )
I 执行算术运算指令(如加法、减法)
II 发生硬件中断 (如时钟中断、I/O 完成中断)
III 程序执行过程中发生除零错误
IV 程序主动调用操作系统的服务(如文件读写)

A.仅 II、III
B.仅 II、IV
C.仅 III、IV
D.I、II、III、IV
CPU 从用户态转换到内核态主要是由中断、异常或系统调用引起的

I 执行算术运算指令：普通的算术运算指令 (如加法、减法) 属于非特权指令，在用户态下正常执行，不会引起 CPU 模式的转换。只有当算术运算导致异常 (如除零错误) 时才会转换

II 发生硬件中断：外部硬件中断 (如时钟中断、I/O完成中断等) 发生后，CPU 必须暂停当前用户进程的执行，转而去执行内核中的中断处理程序来响应中断，这个过程需要从用户态切换到内核态，但是当 CPU 已经处于内核态（比如执行某个内核函数），此时发生硬件中断的话，CPU 还是处于内核态，不需要改变，因为 II 错误，即外部硬件中断不一定会引起用户态转成内核态


III 程序执行过程中发生除零错误：除零错误属于程序执行中的异常。当 CPU 检测到此类异常时，会强制从用户态切换到内核态，由操作系统内核处理该异常


IV 程序主动调用操作系统的服务：用户程序需要操作系统提供服务 (如文件读写、创建进程等) 时，必须通过系统调用接口 (如 read) 来实现。执行系统调用会引发陷入 (trap)，使 CPU 从用户态切换到内核态，由内核执行相应的服务程序


因此，III、IV 都会必然触发 CPU 从用户态到内核态的转换。故选 C

下列指令或操作在执行过程中，哪一项可能不会导致 CPU 从用户态切换到内核态? ( )

A.试图执行一条当前 CPU 不支持的指令
B.从内存中读取一个普通变量的值到寄存器
C.执行 fork() 系统调用以创建子进程
D.执行整数除法指令，且除数为 0

A 试图执行一条当前 CPU 不支持的指令：这会引发 "非法指令" 异常。CPU 检测到无法识别的指令时，会强制从用户态切换到内核态，由操作系统内核处理该异常。因此，这会导致模式切换


B 从内存中读取一个普通变量的值到寄存器：这通常对应一条普通的数据传送指令(如 MOV)。如果该变量所在的内存地址是合法的、有效的，并且对应的页面在物理内存中，那么这条指令会在用户态正常完成，不会导致模式切换。只有在地址非法或发生缺页时，才会间接引发异常导致模式切换，但这并非读取普通变量的必然结果，本题选 B


C 执行 fork() 系统调用以创建子进程：fork() 是一个典型的系统调用。用户程序通过执行类似 fork() 的系统调用指令 (如 trap 或 SYSCALL ) 来请求操作系统服务。执行系统调用会主动引发陷入 (trap)，使 CPU 从用户态切换到内核态


D.执行整数除法指令，且除数为 0:除数为零会引发算术运算异常。CPU在执行除法指令时检测到除数为零，会强制从用户态切换到内核态，由操作系统内核处理该异常。因此，从内存中读取一个普通变量的值到寄存器是可能不会导致 CPU 从用户态切换到内核态的操作

下列各操作中，不一定需要进入内核态实现的操作为 ( )

A.主动退出当前进程
B.利用虚拟地址访问进程数据
C.创建新文件
D.获取当前进程的pid

对于 A，进程退出需要操作系统内核来回收它占用的内存、文件句柄等所有资源，这必须通过系统调用（如 exit()）陷入内核态来完成


对于 B，用户进程在用户态访问自己的虚拟地址时，地址转换工作是由 CPU 的硬件 MMU（内存管理单元）直接完成的，全程不需要内核介入。举个例子，你的程序读取自己定义的变量、数组元素，这些操作都在用户态执行，MMU 会自动把虚拟地址翻译成物理地址，直接读写内存。只有当你访问了一个无效的地址（比如越界访问、访问未映射的内存），触发了缺页或段错误，才会被硬件捕获，然后陷入内核态由操作系统处理。所以，这个操作 “不一定” 需要进入内核态，本题选 B


对于 C，创建文件涉及对磁盘文件系统的操作，而文件系统是由内核管理的，用户态进程必须通过系统调用（如 open()）请求内核来完成，因此必须进入内核态


对于 D，PID（进程 ID）是由内核分配和管理的，属于内核数据结构。用户态进程无法直接读取，必须通过系统调用（如 getpid()）来请求内核提供这个信息，因此也必须进入内核态

I 从应用程序中取到了特权指令

II 从编译程序中取到了特权指令

III 用户态取到了 "启动 I/O" 指令

IV 内核态取到了 "启动 I/O" 指令

A.I、III
B.I、III、IV
C.I、II、IV
D.II、III、IV

应用程序运行在用户态，特权指令（如关中断、直接 I/O）只能在内核态执行。CPU 在用户态取到特权指令时，会拒绝执行并触发 “非法操作” 异常，I 正确


编译程序本身也是用户态应用，它的代码同样运行在用户态。和 Ⅰ 一样，取到特权指令会触发异常，但关键是：编译程序的工作是生成机器指令，它本身不会包含特权指令，因此这种情况不会发生，II 错误


“启动 I/O” 指令是典型的特权指令，只能由内核态的设备驱动执行。用户态执行该指令会被 CPU 拒绝，触发 “非法操作” 异常，III 正确，IV 错误

【14-25】下列指令中，不能在用户态执行的是（ ）

A.trap 指令
B.跳转指令
C.压栈指令
D.关中断指令
只要是特权指令，那么就不能再用户态下执行，比如：
  • I/O 控制指令（启动设备指令、in 指令、out 指令等）
  • 设置系统时钟时间的指令
  • 内核态切换到用户态的指令
  • 关中断的指令（你可以想一想，如果应用程序都可以关中断的话，那么一旦某个应用程序关了中断，忘了开启中断的话，那么整个计算机系统就会崩溃的，所以说，如果用户态可以执行关中断指令的话，非常的危险）

trap 指令就是系统调用的指令，比如 int 软中断执行、syscall 指令，都是在用户态执行，然后再切换到内核态，执行内核中的系统调用服务程序的


跳转指令 (jmp、return 等指令)、压栈指令 (push 指令) 都不是特权指令，所以可以在内核态，也可以在用户态下执行


因此本题选 D

【15-24】假定下列指令已装入指令寄存器，则执行时不可能导致 CPU 从用户态变为内核态 (系统态) 的是（ ）

A.DIV R0,R1; (R0)/(R1)→R0
B.INT n; 产生软中断
C.NOT R0; 寄存器 R0 的内容取非
D.MOV R0,addr; 把地址 addr 处的内存数据放入寄存器 R0 中
在用户态中，只要执行系统调用指令、会产生中断或者异常的指令，都会切换到内核态

首先看 A，DIV R0,R1; (R0)/(R1)→R0，如果 R1 寄存器中的值是 0 的话，就会产生除 0 异常，进而切换到内核态，区执行除 0 异常服务程序

再来看 B，INT n;  这条指令会产生软中断，会切换成内核态，去执行中断号为 n 的中断服务程序

再来看 C，NOT R0; 寄存器 R0 的内容取非，不会产生系统调用，也不会产生中断或者异常，因此，执行这条指令不会切换到内核态，本题选 C

最后看 D，MOV R0,addr; 把地址 addr 处的内存数据放入寄存器 R0 中，需要区访问存储器，如果存储器地址为 addr 的存储单元的数据不在存储器中，而是在磁盘中的话，会产生一个缺页异常，切换到内核态，执行缺页异常程序

【21-23】下列指令中，只能在内核态执行的是 (  )

A.trap 指令
B.I/O 指令
C.数据传送指令
D.设置断点指令
在内核态下，CPU 可执行任何指令，在用户态下 CPU 只能执行非特权指令，而特权指令只能在内核态下执行

对于 A  trap 指令，用于应用程序调用操作系统提供的系统调用，所以是在用户态执行，执行完后，会切换成内核态，然后去执行陷阱处理程序，所以 A trap 指令在用户态执行

对于 B I/O 指令，用于控制访问 I/O 设备硬件的，属于特权指令，因此只能内核态下执行，本题选 B

对于 C 数据传送指令（比如 x86 中的 mov 指令，MIPS 中的 lw 和 sw 指令），并非特权指令，在用户态和内核态下均可以执行

对于 D 设置断点指令（其实就是 int 3 指令），就是产生 3 号中断的指令，可以在用户态的执行，用于程序调试中的断点功能，所以它不是特权指令

III：read 系统调用
