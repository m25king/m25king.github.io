【15-25】下列选项中，会导致进程从执行态变为就绪态的事件是（ ）

A.执行 P(wait) 操作
B.申请内存失败
C.启动 I/O 设备
D.被高优先级进程抢占

对于 A，P 操作是信号量的等待操作：若信号量值 ≤ 0，进程会因等待信号量资源而暂停，主动放弃 CPU，然后进入等待队列中，所以此时是从运行态到阻塞态


对于 B，内存是进程运行的必要资源，申请失败后，进程需等待内存释放，无法继续执行，主动放弃 CPU，然后进入等待队列中，所以此时是从运行态到阻塞态


对于 C，启动 I/O 后，进程需等待 I/O 操作完成（如磁盘读写、网络传输），此期间无法使用 CPU，主动放弃 CPU，然后进入等待队列中，所以此时是从运行态到阻塞态


对于 D，高优先级进程进入就绪态时，操作系统会暂停当前低优先级的执行态进程，将 CPU 分配给高优先级进程。此时低优先级进程仍具备运行条件（资源齐全、无等待事件），仅需等待 CPU 再次调度，所以低优先级进程会进入就绪队列，因此此时是从运行态到就绪态，本题选 D

前面，我们说过，在实现进程互斥时，都应该遵循的四条准则

① 空闲让进：当无进程处于临界区时，表明临界资源处于空闲状态，应允许一个请求进入临界区的进程立即进入自己的临界区，以有效地利用临界资源

② 忙则等待：当已有进程进入临界区时，表明临界资源正在被访问，因而其它试图进入临界区的进程必须等待，以保证对临界资源的互斥访问

③ 有限等待：对要求访问临界资源的进程，应保证在有限时间内能进入自己的临界区，以免陷入"死等" 状态，其实就是说，不能出现饥饿现象

④ 让权等待：当进程不能进入自己的临界区时，应立即释放处理机，以免进程陷入"忙等" 状态

很明显硬件方法实现进程互斥不能实现让权等待，因为硬件方法本来就是要 CPU 来执行的，比如 swap 指令和 TestAndSet 指令，这些指令，本来就是需要 CPU 来执行的，所以  B、D 错误

不过 Peterson 算法是满足有限等待的，当在临界区中的进程退出临界区之后，另一个等待的进程会立马进入临界区，不存在饥饿的情况

说到文件共享，你可能会想到我们在这里【文件共享：硬链接和符号链接】讲的文件共享

硬链接、软链接是文件共享的实现方式，而本题讨论的是多个进程访问已存在的共享文件时的系统机制，二者属于不同层面的概念，并不冲突
  • 硬链接 / 软链接：是文件系统层面的共享手段，目的是让多个目录项（文件名）指向同一个物理文件（硬链接）或间接指向（软链接），本质是文件实体的共享

  • 本题考察的进程共享文件：是进程层面的访问行为，指多个进程通过打开操作，访问同一个物理文件（无论这个文件是否通过链接创建），本质是进程对文件的访问共享


比如你通过硬链接创建了文件 F 的链接文件 F1，多个进程既可以直接打开 F，也可以打开 F1，最终都是访问同一个物理文件 —— 这就是 "文件系统层面的链接共享" 支撑了 "进程层面的访问共享"


反过来，多个进程共享同一个文件，不一定需要通过链接，直接打开同一个文件名（如都打开 “/home/file.txt”），也属于进程层面的文件共享
