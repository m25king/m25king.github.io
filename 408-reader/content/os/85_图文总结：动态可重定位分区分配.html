紧凑技术

连续分配方式的一个重要特点就是，一个应用程序必须被装入到一片连续的内存空间，当一台计算机运行了一段时间后，它的内存空间会被分割成许多小的空闲分区，看下图右边，出现了 5 个小的空闲分区（大小分别是 30KB、20KB、20KB、30KB、40KB），现在有一个应用程序 F 需要 50KB 的内存，很明显，没有足够大的空闲分区，所以，如果不做任何处理的话，那么分配会失败
不过，你看，虽然没有大于等于 50KB 的空闲分区，但是这 5 个空闲分区容量之和是 140KB，这个是大于 50KB 的，所以，我们可以将用户空间所有的应用程序进行移动，使他们都相邻接，这样，把原来分散的多个空闲小分区拼接成一个大的空闲分区，这个空闲分区容量变为 140KB，这样，我们就可以将 50KB 的内存分配给应用程序 F
这种，通过移动内存中作业的位置，将原来多个分散的小分区拼接成一个大分区的方法，称为紧凑，这里需要在应用程序运行时在内存中移动程序的位置，那么应用程序在内存中的基地址会变，这种情况下，必须要采用动态运行时的装入方式来装入应用程序（就是前面我们学习的第三种装入方式）来装入应用程序，动态运行时的装入方式其实就是动态重定位的装入方式，所以，这种动态分区分配的方式，称为动态可重定位分区分配
动态重定位分区分配算法与动态分区分配算法基本上相同，差别仅在于：在这种分配算法中，增加了紧凑的功能，通常，当该算法不能找到一个足够大的空闲分区以满足用户需求时，如果所有的小的空闲分区的容量总和大于用户的要求，这时便须对内存进行 "紧凑"，将经 "紧凑" 后所得到的大空闲分区分配给用户。如果所有的小的空闲分区的容量总和仍小于用户的要求，则返回分配失败信息
紧凑技术可以提高内存的利用率，但是紧凑的过程还是很慢的，开销很大，因为将每个程序在内存中的数据，一一拷贝在挨在一起，这里非常耗费 CPU 的时间，就好比，你的电脑在运行一段时间后，突然间卡了一段时间，这段时间有可能就是在做紧凑操作，这个很影响体验
那么如何既能提高内存利用率，又能避免紧凑呢？答案就是使用离散分配，允许将一个应用程序占用的内存，直接分散地装入到许多不相邻接的分区中，便可充分地利用内存空间，而无须再进行 "紧凑"
比如，上图应用程序 F 需要 80KB，那么可以不连续的 3 个空闲分区（30KB、20KB 以及 30KB 的空闲分区），分配给应用程序 F，这样，应用程序 F 占用的内存空间，在内存中是离散的，不连续的，这样既可以提高内存利用率，又可以避免紧凑，从而提高性能，对于离散分配，后面会详细讲解

内存保护

下面计算机系统中，采用动态运行时装入方式，在 CPU 中有一个重定位寄存器，或者成为基地址寄存器，当执行应用程序 A 的时候，会将应用程序 A 的基地址 128 放到重定位基地址中，PC 设置为应用程序 A 要执行的第一条指令的逻辑地址，假设现在执行的是这条指令，会出现什么问题呢？
指令执行时，产生逻辑地址 180，将其和重定位寄存器值相加，得到 308，这个内存地址超过了应用程序 A 的最大内存地址 128 + 119 = 247，那么此时，拿到的数据肯定是错的，对吧，因为，你现在访问的是应用程序 C 中的数据，这肯定是不允许的，那么，在这种多道程序环境下，如何进行内存保护呢？也就是说，如何保证防止一个程序访问另一个程序的内存数据呢？
动态分区中的内存保护，可以通过加一个硬件界限寄存器来实现（看下图），界限寄存器规定当前执行应用程序的逻辑地址的上限，应用程序 A 的占用内存大小是 120B，所以程序 A 的逻辑地址的上限就是 120，不能大于等于 120，所以，这个界限寄存器的值就是120
接下来，当执行指令时，产生这个逻辑地址 180，先和界限寄存器比较，如果大于等于界限寄存器的值，那么触发异常，寻址错误，这里可以通过 int 软中断指令，触发一个软中断，然后去执行寻址错误的中断处理程序
看上图，当 CPU 执行指令时，产生的逻辑地址，小于界限寄存器中的地址的话，才可以和重定位寄存器的基地址相加，产生物理地址，然后才可以正常访问内存；如果逻辑地址大于等于界限寄存器的话，那么可以使用 int 软中断指令，触发陷阱处理程序，注意哈，陷阱一般就是指 int 中断指令，触发软中断后，就去执行寻址错误的中断处理程序，这个中断处理程序，可能会停止正在执行的应用程序
