在下面的 I/O 系统分层图中，最底层的 I/O 设备和控制器这些 I/O 硬件我们已经在计组的第七章学习过了，再往上的中断处理程序，在计组第七章和操作系统第一章也有学习了很多
那么接下来，我们就来先学习设备驱动程序，虽然每个设备的设备驱动程序具体的功能都不相同，但是它们执行过程是差不多的，这一小节，我们就来看下设备驱动程序的执行过程的 5 个步骤

第 ① 步：将抽象要求转换为具体要求

先来看下图的块设备，用户的应用程序发起一个读文件的 I/O 请求，通过 read 系统调用，来读取文件 /home/user/test.txt 的前 1024 个字节，陷入内核后，经过文件系统的处理，找到这个文件的 FCB 或者说 inode，然后就可以知道要读取数据所在盘块的盘块号
然后通过调用块设备接口，将请求转发给块设备管理程序，在这里会将盘块号转换为逻辑扇区号，并且通过设备分配查找的功能，可以找到具体的磁盘，然后，将这个 I/O 请求的命令转发给对应的磁盘驱动程序，这个命令就是【读取起始逻辑扇区号为 20 ，连续 2 个扇区的数据】，这个是抽象的命令，因为这个命令直接发给磁盘控制器的话，它不能理解，也就不会执行，所以，需要转换为具体的命令，这些命令应该是磁盘控制器可以理解的，什么是磁盘控制器可以理解呢？
我们知道控制器中都有若干个寄存器，比如数据缓冲寄存器，命令寄存器，状态寄存器，驱动程序只有按照控制器的这些寄存器的要求，传送过来正确格式的数据，那么这个控制器才能理解，然后按照指定的命令进行工作。对于机械磁盘的磁盘控制器，很明显不认识这个逻辑扇区号，那么就需要磁盘驱动程序进行转换，转换成具体的命令，比如，读取磁头号 10、磁道号 100、扇区号 1 的数据，读取的数据是 1KB，将这些数据发送给磁盘控制器的寄存器，它才可以理解，可以正常工作
将抽象要求转换为具体要求的这一转换工作只能由驱动程序来完成，因为在 OS 中只有驱动程序才同时了解上面抽象要求和设备控制器中的寄存器情况，也只有它才知道命令、数据和参数应分别送往控制器的哪个寄存器
再比如看下图，现在应用程序提出抽象要求：向 IP 地址 192.168.1.100 发送一个 1000 字节的数据包，这个要求只涉及 "目的 IP 地址、数据长度"，不关心网卡是千兆还是万兆，也不关心底层是以太网还是 Wi-Fi
这个请求，经过系统调用处理，调用网络接口，再经过 TCP/IP 协议，封装成 IP 数据包；然后调用驱动程序，将 "IP 数据包" 封装为以太网帧（即添加目标 MAC 地址、源 MAC 地址，MAC 地址就是网卡的物理地址，是具体的），按网卡要求添加 CRC 校验码，然后向网卡发送开始发送指令，这些都是具体的要求，驱动程序将发送 IP 数据包这个抽象的要求转换成了具体的要求
所有的驱动程序，都要完成从上层的抽象要求转换为具体的硬件操作要求，这样使得上层无需知道硬件的物理特性（如扇区、MAC 地址等），只需关注逻辑需求，也就是说驱动程序屏蔽了底层的硬件细节，驱动程序必须根据不同的硬件设备的要求，重新表达要执行的操作要求

第 ② 步：对 I/O 请求进行校验

设备驱动程序在启动 I/O 设备之前，必须先检查该用户的 I/O 请求是不是该设备能够执行的，比如看下图，应用程序通过 read 来发起读 I/O，陷入内核，经过字符设备接口转发给字符设备管理程序，然后经过设备分配查找功能，找到了具体的打印机设备
将这个请求转发给打印机驱动程序，这里用户试图请求从一台打印机读入数据，很明显，打印机只能打印输出数据，而不能读数据，这个时候，驱动程序就要检查出这类错误，认为这次 I/O 请求非法，它将向 I/O 系统的错误处理功能报告 I/O 请求出错。错误处理可以根据具体情况做出不同的决定，如可以停止请求进程的运行，或者仅通知请求进程它的 I/O 请求有错，但仍然让它继续运行

第 ③ 步：检查设备状态

启动某个设备进行 I/O 操作，它的前提条件应是该设备正处于就绪状态，为此，在每个设备控制器中，都配置有一个状态寄存器，比如这个打印机控制器（看下图），有 3 个寄存器，每个寄存器就是一个端口，每个端口都有自己的地址
驱动程序在启动设备之前，要先把状态寄存器中的内容读入到 CPU 的某个寄存器中，通过测试寄存器中的不同位，来了解设备的状态，上图的打印机驱动程序通过指令 in eax, 0x666 将打印机控制器的状态寄存器中的状态值读取到 CPU 的 eax 寄存器中，然后打印机驱动程序中有相应的程序指令根据 eax 寄存器中的状态值来判断打印机的状态（上图的 if 语句块是一段伪代码，其本质是一段指令程序）
比如，为了向某设备写入数据，此前应先检查状态寄存器中接收就绪的状态位，看它是否处于接收就绪状态，仅当它处于接收就绪状态时，才能启动其设备控制器，否则只能等待

第 ④ 步：传送必要的参数

在确定设备处于就绪状态后，便可向控制器的相应寄存器传送数据及与控制本次数据传输有关的参数
比如，磁盘驱动器就需要将磁头号 10、磁道号 100、扇区号 1 以及读取长度 1KB 等参数发送给磁盘控制器
再比如，打印机驱动程序需要将数据传输速率（波特率）发送给打印机控制器，这个波特率必须与外设一致，否则数据错乱，另外，将数据格式数据位（8位）、校验位（无校验）、停止位（1位）发给打印机控制器，用于定义数据帧结构

第 ⑤ 步：启动 I/O 设备

在完成上述各项准备工作后，驱动程序便可向设备控制器中的命令寄存器传送相应的控制命令
对于字符设备，若发出的是写命令，则设备驱动程序会把一个字节（或字）传送给设备控制器的数据缓冲寄存器；若发出的是读命令，则设备驱动程序会等待接收数据，并通过读入设备控制器的状态寄存器中状态字的方法来确定数据是否到达
在多道程序系统中，设备驱动程序一旦发出 I/O 命令、启动一个 I/O 操作后，其便会把控制权返回给 I/O 系统，把自己阻塞起来，直到中断到来时再被唤醒。具体的 I/O 操作是在设备控制器的控制下进行的，因此，在设备忙于传送数据时，CPU 可以去干其他的事情，实现了 CPU 与 I/O 设备的并行操作
