III 如果所有进程的执行严格区分优先级，则死锁就不会发生

死锁发生的4 个必要条件（必须同时满足才会死锁）：
  1. 互斥条件：资源独占，同一时间只能一个进程使用；
  2. 请求与保持：进程已持有资源，又请求新资源、不释放已有资源；
  3. 不可剥夺：已占资源不能被强制抢走；
  4. 循环等待：存在进程 - 资源的环形请求链。

对于 I，每个进程只能拥有一个资源，那么必然不符合【请求与保持】这个条件，所以肯定不会产生死锁，I 正确

对于 II，死锁产生的必要条件之一是互斥条件，即资源在一段时间内只能被一个进程所占用。如果所有资源都可以被多个进程无冲突地共享访问，那么互斥条件就不成立，死锁也就不会发生。II 正确

对于 III，仅仅有优先级并不能完全避免死锁。例如，一个高优先级进程 P1 可能等待一个低优先级进程 P2 持有的资源，而 P2 又在等待另一个资源。如果这个等待链形成循环，即使有优先级，死锁依然可能发生。优先级调度可能会影响饥饿现象，但不能直接消除所有类型的死锁，III 错误

对于 IV，循环等待条件是产生死锁的四个必要条件之一。如果能够破坏循环等待条件，例如通过资源有序分配法，确保进程请求资源时不会形成环路，那么死锁就不会发生。IV 正确

对所有资源进行编号，并要求进程按严格增加(或减少)的顺序来请求资源，这是死锁预防的一种方式，破坏了死锁四个必要条件中的 ( )

A.互斥条件
B.占有并请求条件
C.不可抢占条件
D.循环等待条件

循环等待条件指系统发生死锁时，一定存在一条进程请求资源的循环等待链。题干中对所有资源进行编号，并要求进程只按严格增加(或减少)的顺序来请求资源，破坏了死锁产生的循环等待条件，选 D

在哲学家就餐问题中，若哲学家中同时存在左撇子和右撇子，左撇子会先拿左手边的筷子，而右撇子会先拿右手边的筷子。这种情况下不会发生死锁，因为这破坏了 ( )

A.互斥条件
B.请求与保持条件
C.不剥夺条件
D.循环等待条件
传统全是右撇子的场景会形成循环等待：每位哲学家都先拿左筷子、再拿右筷子，环形互相等待相邻哲学家手里的筷子

加入左撇子（先拿左手边筷子）+ 右撇子（先拿右手边筷子）后，资源请求的环形依赖链被打破，无法形成首尾相接的循环等待环，直接破坏了循环等待条件这一死锁必要条件，本题选 D


我们也可以逐一排除其他选项：

  • 互斥条件：筷子依然一次只能一人使用，互斥性保留，A 错；

  • 请求与保持：哲学家拿到第一根筷子后仍会保持持有、请求第二根，该条件保留，B 错；

  • 不剥夺条件：筷子依旧不能被强行抢走，该条件保留，C 错

死锁预防是保证系统不进入死锁状态的一种静态策略，它通过破坏死锁产生的四个必要条件中的一个或多个来预防死锁，下列破坏了死锁产生的 "请求和保持条件" 的是 ( )。

A.银行家算法
B.一次性分配策略
C.剥夺资源法
D.有序资源分配法

一次性分配策略：进程运行前就申请全部需要的资源，要么全分配、要么全不分配，进程不会出现 "拿着旧资源再申请新资源" 的情况，直接破坏请求和保持条件，本题选 B

先区分死锁预防和死锁避免的核心概念，再逐个判断选项：
  • 死锁预防：静态破坏死锁 4 个必要条件之一，从根源杜绝死锁可能。
  • 死锁避免：动态管控资源分配，不让系统进入不安全状态，以此避免死锁，典型算法是银行家算法
对于 A：防止进入不安全状态是死锁避免的做法，不是死锁预防，错误

对于 B：死锁避免的核心思路就是动态预判资源分配的安全性，阻止系统进入不安全状态，从而避免死锁出现，正确，本题选 B

对于 C：银行家算法是死锁避免的经典算法，不属于死锁预防，错误

对于 D：规定资源申请顺序是死锁预防里破坏循环等待的手段；银行家算法是分配前做安全性检查，不限制申请顺序（D 错误），进程可以按照任何顺序来申请资源，只不过，系统在真正给进程分配资源前，需要先检查下假设分配资源了，会不会让系统处于不安全状态，如果会的话，就不分配资源，否则立马分配资源

下列关于死锁避免和死锁检测的说法中，不正确的是 ( )

A.死锁避免会同一时间请求所有资源，而死锁检测不会
B.死锁避免需要进程运行所需资源总量信息，而死锁检测不需要
C.死锁避免不会给可能导致死锁的进程分配资源，而死锁检测会
D.死锁避免会去评估分配资源的风险，而死锁检测不会

选项 A：同一时间请求所有资源是死锁预防（破坏请求与保持条件）的策略，不是死锁避免的特征。死锁避免允许进程动态分多次申请资源，只是分配前做安全性校验，所以 A 错误，本题选 A


选项 B：死锁避免（如银行家算法）必须预先知道进程运行所需的资源最大总量；死锁检测只看当前资源分配图判断是否出现环路，不需要提前知道进程总资源需求，该说法正确


选项 C：死锁避免事前拦截，不会进行会引发不安全（可能死锁）的资源分配；死锁检测放任分配、允许系统进入死锁状态，之后再检测处理，该说法正确


选项 D：死锁避免分配前评估风险、只做安全分配；死锁检测不预判分配风险，只事后排查死锁，该说法正确

资源剥夺法允许一个进程强行剥夺其他进程所占有的系统资源。撤销进程会强行释放一个进程已占有的系统资源，其与资源剥夺法同理，亦是通过破坏死锁的“请求和保持”条件来解除死锁的。拒绝分配新资源只能维持死锁的现状，而无法解除死锁。

下列关于死锁的预防、避免、检测和解除的叙述中，正确的有()

I 资源的有序分配策略可以破坏死锁的请求和保持条件

II 银行家算法通过控制资源的分配，破坏了死锁的循环等待条件

III 产生死锁的根本原因是系统资源分配不足和进程推进顺序非法

IV 采用进程回退法解除死锁需要保存进程的历史信息，设置还原点

A.仅 I、II
B.仅 III、IV
C.仅 II、III、IV
D.I、II、III、IV

资源有序分配策略的作用是破坏循环等待条件，不是请求和保持条件；破坏请求和保持一般采用一次性申请所有资源的方式，因此 I 错误


银行家算法属于死锁避免策略，它不会破坏死锁的四个必要条件，只是在资源分配前做安全性判断、规避不安全分配；破坏循环等待是死锁预防的手段，因此 II 错误


死锁的发生首先是因为系统中的资源数量有限，不足以满足所有并发进程的需求（资源分配不足）。其次，即使资源不足，如果进程请求和释放资源的顺序得当，也未必会发生死锁。只有当多个进程对资源的请求和保持形成一种特定的循环等待关系，即进程推进顺序非法（导致了循环等待条件），才会最终导致死锁，因此 III 正确

进程回退是一种死锁解除策略。当检测到死锁后，系统选择一个或多个死锁进程，使其回退到足以避免死锁的某个先前状态（检查点或还原点）。这要求系统能够记录进程在不同时间点的状态信息（历史信息）并设置还原点，以便能够进行回退操作。因此 IV 正确

对于本题，你可以对每个选项逐个分析，也可以使用银行家算法来求安全序列，至于哪个方便，你往下看看，自行判断：


先来看逐个分析的解法：


先来看 A：P₁,P₂,P₃,P₄
  • P1 的尚需资源 (0, 0 , 1) < 可用资源 (0, 2, 1)，可以将资源分配给 P1，P1 完成后，将 P1 的已分配资源 (2, 0, 0) 归还给操作系统，那么可用资源为 (0, 2, 1) + (2, 0, 0)  = (2, 2, 1) 
  • P2 的尚需资源 (1, 3 , 2) > 可用资源 (2, 2, 1)，因此，P2 没有足够的资源，也就运行不完

所以  A：P₁,P₂,P₃,P₄ 不是安全序列

  • P3 的尚需资源 (1, 3, 1) > 可用资源 (2, 2, 1)，因此，P3 没有足够的资源，也就运行不完

所以 B：P₁,P₃,P₂,P₄ 不是安全序列

  • P3 的尚需资源 (1, 3, 1) > 可用资源 (2, 2, 2)，因此，P3 没有足够的资源，也就运行不完

所以  C：P₁,P₄,P₃,P₂ 不是安全序列

可用资源是 (0, 2, 1)，接下来，从尚需分配矩阵中，找到小于等于可用资源的进程，只有进程 P1 的 (0, 0, 1)，那么可以将资源分配给进程 P1 ，运行完，将资源归还给系统，那么系统，现在总的可用资源 = 已分配资源 (2, 0, 0) + 可用资源 (0, 2, 1) = (2, 2, 1)


接下来，从 P2、P3、P4 中的尚需矩阵中找到小于等于可用资源 (2, 2, 1) 的进程，只有进程 P4 的 (2, 0, 0)，将资源分配给 P4，让 P4 运行完成，然后将 P4 的已分配资源归还给系统，那么系统，现在总的可用资源 = 已分配资源 (0, 0, 1) + 可用资源 (2, 2, 1) = (2, 2, 2)


接下来，因为 P2 和 P3 中的尚需资源分别是 (1, 3, 2) 和 (1, 3, 1) 都是大于总的可用资源 (2, 2, 2) ，因此，P2 和 P3 都没有足够的资源来运行


所以，目前的状态下，是没有安全序列的，系统处于不安全的状态

死锁的 4 个必要条件：资源互斥、请求和保持（占有且等待）、不可剥夺、循环等待。银行家算法通过 "预判资源分配后果" 避免循环等待，不直接破坏 “请求和保持” 条件，也不是直接破坏循环等待，只是避免了循环等待，所以，我们称为死锁避免算法，因此 D 错误

  • 剩余资源 1 台，对比各进程剩余需求（P1 还需 2、P2 需 4、P3 需 4 ），没有进程能直接满足，模拟分配后无安全序列，银行家算法拒绝 P1 的请求

这里不是直接破坏循环等待，直接破坏循环等待的基础是已经产生了循环等待了，而银行家算法是避免了循环等待

其效果就是：通过 “预判安全分配”，引导资源分配按安全序列执行，自然绕开了循环等待的可能

【19-30】下列关于死锁的叙述中，正确的是（ ）
I：可以通过剥夺进程资源解除死锁
II：死锁的预防方法能确保系统不发生死锁
III：银行家算法可以判断系统是否处于死锁状态
IV：当系统出现死锁时，必然有两个或两个以上的进程处于阻塞态

A.仅 II，III
B.仅 I，II、IV
C.仅 I，II，III
D.仅 I，III，IV
死锁是指多个进程因竞争资源而互相等待，且无法自行推进的僵局。其产生需满足 4 个必要条件：资源互斥、持有并等待、不可剥夺、循环等待

I：可以通过剥夺进程资源解除死锁

死锁的解除方法包括资源剥夺法、进程终止等。其中资源剥夺法的核心逻辑是：强制剥夺死锁进程已占有的部分或全部资源，分配给其他死锁进程，打破不可剥夺的死锁必要条件，从而消除死锁（例如操作系统可暂时剥夺进程的 CPU 资源分配给其他进程），因此 I 正确

II：死锁的预防方法能确保系统不发生死锁

死锁预防的本质是破坏死锁的 4 个必要条件之一，从根源上杜绝死锁产生的可能：

  • 破坏 “资源互斥”：如采用共享资源（如磁盘文件）替代互斥资源
  • 破坏 “持有并等待”：要求进程一次性申请所有所需资源（申请不到则不启动）
  • 破坏 “不可剥夺”：允许系统剥夺进程已占有的资源
  • 破坏 “循环等待”：对资源编号，要求进程按编号顺序申请资源

由于预防方法直接消除了死锁的必要条件，因此能确保系统绝对不发生死锁（代价是可能降低资源利用率），因此 II 正确

III：银行家算法可以判断系统是否处于死锁状态

银行家算法的核心功能是避免死锁，而非检测死锁：

  • 避免死锁（银行家算法）：在进程申请资源时，先判断分配后系统是否仍处于安全状态（即存在一个资源分配序列，能让所有进程顺利完成）。若安全则分配，否则拒绝，从而避免死锁发生（仅适用于可动态分配的资源）
  • 检测死锁：需通过资源分配图化简判断系统是否已处于死锁状态，与银行家算法无关

因此，III 错误

IV：当系统出现死锁时，必然有两个或两个以上的进程处于阻塞态

死锁的定义是多个进程互相等待资源，等待资源的进程会因资源不可得而进入阻塞态（阻塞态的核心是进程等待某事件发生才能继续）。若仅 1 个进程，无法形成互相等待的循环（单进程只能等待自身释放资源，无循环条件），因此死锁必然涉及至少 2 个进程，且这些进程均因等待对方资源而阻塞，因此 IV 正确


所以，I、II、IV 正确，本题选 B
