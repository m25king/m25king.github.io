在计算机系统中，每个 I/O 设备在内核中都有对应的驱动程序，前面我们已经讲了设备驱动程序的几个作用：
  1. 接收与设备无关的软件发来的命令和参数，并将命令中的抽象要求转换为与设备相关的底层操作序列
  2. 检查用户 I/O 请求的合法性，了解 I/O 设备的工作状态，传递与 I/O 设备操作有关的参数，设置设备的工作方式
  3. 发出 I/O 命令，如果设备空闲，便立即启动 I/O 设备，完成指定的 I/O 操作；如果设备忙碌，可以将请求者的请求阻塞，然后等待
  4. 支持 4 种 I/O 控制方式：程序查询方式、中断控制方式、DMA 控制方式以及通道控制方式
接下来，我们再来看下设备驱动程序的另一个主要的作用：初始化设备

初始化设备

你可以试想一下，当一个厂家生产好一个新的 I/O 设备，都需要为这个设备编写对应的设备驱动程序和中断处理程序，当我们将这个新的设备插入到电脑上时，需要先安装好对应的设备驱动程序，然后这个 I/O 设备才可以正常运行。当操作系统启动的时候，会去加载这台计算机上面所有 I/O 设备对应的驱动程序，然后让这些驱动程序一个一个的进行初始化，主要就是让这些驱动程序初始化对应的 I/O 设备。那么，在驱动程序初始化设备的过程中，需要做哪些事情呢？我们一个一个来看
首先就是检查设备是不是可以正常工作，如果能正常工作，那么就对设备进行复位操作，确保其初始状态是正确的，接下来，就是给设备分配三类资源，包括：I/O 端口号/内存地址、用于传输数据的内核缓冲区、中断号
① 第一个资源是：I/O 端口号/内存地址，我们知道，每个 I/O 设备对应的控制器都有一些寄存器，我们称为 I/O 端口，每一个 I/O 端口都需要一个地址，如果采用是 I/O 端口独立编址的话，驱动程序需要向内核申请对应的 I/O 端口号给到设备的 I/O 端口，如下图：
上图中的 0x3345、0x3346、0x3347 这三个端口号，就是打印机驱动程序向内核申请分配的，这些端口号会维护在打印机驱动程序中，同样 0x3348、0x3349、0x334A 这三个端口号，就是磁盘驱动程序向内核申请分配的，这些端口号会维护在磁盘驱动程序中
如果采用的是 I/O 统一编址的话，那么驱动程序就需要为 I/O 端口申请内存地址了，因为此时 I/O 端口和内存使用同一个地址空间，这里要是忘记了，可以复习【IO 接口的通用结构】这个视频，从 7 分 50 开始
② 第二个资源是：用于传输数据的内核缓冲区，我们知道 I/O 设备的速度比 CPU 和内存要慢很多很多，当在 I/O 设备和 CPU 或者内存之间传输数据的话，就需要一个缓冲区，主要是为了缓和 CPU 和 I/O 设备之间的矛盾，提高 CPU 的利用率，在现代 OS 中，都无一例外的为字符设备和块设备配置了相应的缓冲区，对于缓冲区，我们后面还有一节课会详细讲解
③ 第三个资源是：中断号，我们知道，每个 I/O 设备都可能会产生中断，当产生中断的时候，就需要根据中断号，去中断向量表中，查找这个中断处理程序在内存中的起始地址，进而才可以跳转到这个起始地址，开始执行中断处理程序。一般而言，一台计算机系统上的中断号的数量是有限的，比如 X86 系统中，有 256 个中断号，如下图：
其中前 0 ~ 31 号中断号对应这固定的中断处理程序，从 32 号到 255 号是用户自定义的中断

当一个设备的驱动程序初始化话时，就需要从内核中申请一个中断号，然后再加载设备对应的中断处理程序到内存中，并且修改中断向量表，将申请到的中断号和设备对应的中断处理程序的起始内存地址关联起来，这样下次发生中断，就可以根据中断号，从中断向量表中找到中断处理程序的起始地址
实际上，设备驱动程序向内核申请一个中断号，是设备驱动程序注册中断处理程序的一个步骤，也可以这么说，注册设备的中断处理程序也是设备驱动程序初始化的过程中的一个步骤，驱动程序注册设备的中断处理程序主要包括 3 步：
  1. 向内核申请一个中断号
  2. 加载设备的中断处理程序到内存中，得到内存起始地址
  3. 修改中断向量表，将申请的中断号和中断处理程序在内存中的起始地址关联起来
综上所述，设备驱动程序在初始化设备的时候，主要做以下事情：
  1. 检查设备是不是可以正常工作
  2. 给设备分配三类资源，包括：I/O 端口号/内存地址、用于传输数据的内核缓冲区、中断号
  3. 注册设备的中断处理程序

中断处理程序和驱动程序的关系

严格来说，中断处理程序是和设备驱动程序绑定在一起的，属于驱动的 "下半部分"， 为什么中断处理程序必须和驱动绑定呢？
原因一：中断处理程序要处理的都是设备相关的工作，当中断发生时，中断处理程序要做的事情，全都是和硬件强相关的，比如：
  • 读取设备状态寄存器：比如磁盘完成 I/O 后，驱动的中断处理程序要读取磁盘控制器的状态寄存器，判断是读写成功还是出错了（比如坏道）
  • 清除中断标志：不同设备的中断清除方式不一样，有的要写特定寄存器，有的要读数据端口，这些都只能由驱动来实现
  • 唤醒等待的进程：把之前被 I/O 阻塞的进程唤醒，通知它 "数据已经准备好了，可以继续执行了"
  • 处理 DMA / 数据传输收尾：比如 DMA 完成后，要更新缓存、统计 I/O 完成情况，这些都和设备的传输方式绑定
这些工作没有通用逻辑，每个设备（磁盘、键盘、网卡）的中断处理逻辑都不一样，只能写在对应的驱动里
原因二：中断向量是由驱动注册的，操作系统启动时，驱动会把自己的中断处理程序，注册到对应的中断向量号上（比如磁盘控制器的中断号是 14），当设备发出中断时，CPU 根据中断向量号，直接跳转到驱动注册的这个处理程序执行。也就是说，中断处理程序的入口，是由驱动提供的，它本身就是驱动的一部分
就是因为中断处理程序和设备驱动程序关系非常的紧密，所以，有的时候，我们说设备驱动程序的时候，实际上已经包括了这个设备的中断处理程序的
