设备驱动程序处理 I/O 请求的完整流程：


  1. ④ 将抽象要求转化为具体要求首先，驱动程序需要把上层（设备无关软件）发来的通用 I/O 请求（如读文件），转化为设备能理解的具体操作（如 “从磁盘的 XX 扇区读取 XX 字节”）
  2. ① 对服务请求进行校验接着，校验请求的合法性：检查参数是否有效、进程是否有权限访问设备、请求是否合理
  3. ⑤ 检查设备的状态确认设备当前是否空闲、是否就绪，能否响应新的 I/O 请求
  4. ② 传送必要的参数向设备控制器寄存器写入操作所需的参数，如数据地址、传输长度、控制命令等
  5. ③ 启动 I/O 设备最后，向设备控制器发送启动命令，让设备开始执行 I/O 操作

因此，正确的顺序是：④ → ① → ⑤ → ② → ③，对应选项 B

I/O 通道是一种专门的硬件控制器，它有自己的通道指令，能够独立执行通道程序，控制设备完成 I/O 操作。CPU 只需向通道发送启动命令，后续的数据传输、设备管理都由通道独立完成，CPU 几乎不需要干预，是四种方式中自主性最高的，本题选 A


中断驱动 I/O 这种方式下，CPU 在发起 I/O 请求后可以执行其他任务，但设备完成操作后必须通过中断通知 CPU，CPU 需要响应中断并处理数据，仍需 CPU 干预


程序 I/O（轮询）这种方式下，CPU 需要不断查询设备状态，全程参与数据传输，是最依赖 CPU 的方式


直接存储器访问（DMA）方式下，数据可以直接在外设和内存间传输，不经过 CPU，但 DMA 控制器需要 CPU 进行初始化（设置地址、长度等），且每次 DMA 传输完成后仍需 CPU 处理中断，无法做到完全独立

对于程序直接控制（轮询）方式，进程发起 I/O 请求后，会不断轮询设备状态，直到 I/O 完成。在这个过程中，进程会一直占用 CPU，无法执行其他任务，此时进程的状态仍然是运行态，并没有阻塞，所以 I 错误


对于中断方式，进程发起 I/O 请求后，会被操作系统阻塞在驱动程序，让出 CPU 给其他进程执行；当设备完成 I/O 后，通过中断唤醒该进程。因此，进程会经历阻塞态，II 正确


对于 DMA 方式，进程发起 DMA 传输请求后，同样会被阻塞，直到 DMA 控制器完成数据传输并通知操作系统。因此，进程也会进入阻塞态，III 正确

已知磁盘采用 DMA 方式进行数据传送，若用户进程 P 通过系统调用向磁盘发起了读命令，则下列哪个时间点磁盘数据恰好已经进入内核缓冲区 ( ) 

A.进程 P 被阻塞时
B.CPU 接收到 DMA 中断时
C.DMA 中断处理完毕时
D.系统调用完成时
我们来梳理 DMA 方式下磁盘读数据的完整流程，关键是找到数据恰好进入内核缓冲区的时间点：
  1. 用户进程 P 发起 read 系统调用，向磁盘发送读命令；操作系统将进程 P 阻塞
  2. 驱动程序设置 DMA 控制器参数（源地址：磁盘扇区、目的地址：内核缓冲区、传输长度），启动 DMA 传输
  3. DMA 控制器独立完成数据从磁盘到内核缓冲区的传输，传输完成后，DMA 控制器向 CPU 发送中断信号
  4. CPU 接收到中断信号后，才会进入中断处理程序，此时数据已经在内核缓冲区中了


A 错误，进程 P 被阻塞时，只是发起了 I/O 请求，DMA 传输还未开始，数据还在磁盘上


B 正确，DMA 传输完成后才会发送中断，此时数据已经全部进入内核缓冲区，CPU 接收到中断信号的瞬间，数据已经就位，本题选 B

C 错误，中断处理程序会将数据从内核缓冲区复制到用户缓冲区，并唤醒进程 P。所以，DMA 中断处理完毕时，数据不仅在内核缓冲区，而是已经被复制到用户缓冲区

D 错误，统调用完成时，数据已经从内核缓冲区复制到用户缓冲区，进程 P 被唤醒，数据早已不在内核缓冲区了

【24-23】下列关于中断、异常和系统调用的叙述中，错误的是( )。

中断或异常发生时，CPU 既可能处于内核态，也可能处于用户态。例如，当某个用户程序试图将一个数除以 0 时， CPU 会检测到这一非法操作并触发异常，此时 CPU 仍处于用户态，再比如，CPU 在执行用户程序中的加法指令时，处于用户态，此时你发送一个鼠标中断，因此 A 错误，本题选 A


系统调用的目的就是让内核帮忙完成一定的功能（可能是操作硬件的功能等），所以每个系统调用都有对应的内核服务例程，因此 B 描述正确


由于中断处理程序是内核中的程序，所以，当开始执行中断处理程序时，CPU 一定是处于内核态，因此 C 描述正确


当系统添加新类型的设备时，需要先安装这个设备的驱动程序，然后再设备的驱动程序中，会注册响应的中断服务程序，因此 D 描述正确


驱动程序注册设备的中断处理程序主要包括 3 步：

  1. 向内核申请一个中断号

  2. 加载设备的中断处理程序到内存中，得到内存起始地址

  3. 修改中断向量表，将申请的中断号和中断处理程序在内存中的起始地址关联起来
