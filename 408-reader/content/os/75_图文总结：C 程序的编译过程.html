编译器驱动程序

大多数编译系统提供编译器驱动程序，它代表用户在需要时调用语言预处理器、编译器、汇编器和链接器。比如，要用 GNU 编译系统来编译一个程序的话，我们就可以通过在 shell 中输入下面的命令 gcc hello.c -o hello 来调用 GCC 驱动程序，下图就是 GCC 编译器驱动程序将 ASCII 码源文件 hello.c 翻译成可执行目标文件的 4 个步骤，包括翻译阶段（预处理、编译和汇编）和链接阶段两个阶段
翻译阶段的三个步骤是：
  • ① 预处理：根据以字符 # 开头的命令，修改 hello.c 源程序文件
  • ② 编译：将程序翻译成 ASCII 汇编语言程序 hello.s
  • ③ 汇编：将汇编语言程序翻译成机器语言，生成可重定位目标文件 hello.o
链接阶段则是将多个可重定位目标文件合并成一个可执行目标文件，然后就可以直接执行这个可执行目标文件 hello，然后在 shell 中可以通过 ./hello 来调用操作系统内核中的加载器，加载器将可执行文件 hello 中的代码和数据复制到内存，然后开始执行 hello 程序的第一条指令
可以看到，使用 gcc 编译器执行预处理、编译、汇编和链接属于编译时，编译完成后，就可以进入加载时，加载器将可执行目标文件加载到内存，然后程序就可开始运行，也就进入到运行时，链接阶段的输入是多个可重定位目标文件，链接阶段的的输出就是程序执行的输入
再来看下面两个源程序文件 main.c 和 sum.c，分别通过编译器 gcc 经过预处理、编译和汇编步骤得到各自的可重定位目标文件 main.o 和 sum.o
接下来执行 gcc main.o sum.o -o prog，经过链接器的链接步骤，最终得到一个可执行目标文件 prog，这里是通过链接器将多个可重定位目标文件，合并成一个可执行目标文件，这种链接方式称为静态链接

链接的类型有 3 种：
① 静态链接：在程序运行之前，先将各个可重定位目标文件以及它们所需的库函数链接成一个完整的可执行目标文件
② 装入时动态链接：这个链接发生在加载时（即发生在装入时），一个用户程序包括多个可重定位目标文件，然后边装入边链接的方式装入内存
③ 运行时动态链接：这个链接发生在运行时，一个用户程序包括多个可重定位目标文件，先装入一部分的可重定位目标文件到内存中链接运行，在程序运行时，如果用到剩下的某些可重定位目标文件，则装入到内存，边运行边链接，这样可以打打节省内存空间

目标文件

目标文件有三种形式：
  • ① 可重定位目标文件：包含二进制代码和数据，其形式可以在链接时与其他可重定位目标文件合并起来，创建一个可执行目标文件
  • ② 可执行目标文件：包括二进制代码和数据，其形式可以被直接复制到内存并执行
  • ③ 共享目标文件：一种特殊类型的可重定位目标文件，可以在加载或者运行时被动态地加载进内存并链接
编译器和汇编器生成可重定位目标文件（包括共享目标文件），链接器生成可执行目标文件。从技术上来说，一个目标文件就是一个以文件形式存放在磁盘中的字节序列而已。目标文件是按照特定的目标文件格式来组织的，各个系统的目标文件格式都不相同（看下图）
从贝尔实验室诞生的第一个 Unix 系统使用的是 a.out 格式（直到今天，可执行文件仍然称为 a.out 文件）。Windows 使用可移植可执行 (Portable Executable, PE) 格式。Mac OS-X 使用 Mach-O 格式。现代 x86-64 Linux 和 Unix 系统使用可执行可链接格式 (Executable and Linkable Format, ELF)。尽管我们接下来的讨论都是集中在 ELF 上，但是不管是哪种格式，基本的概念是相似的
接下来我们先来学习可重定位目标文件，它也是采用 ELF 文件格式，在每个可重定位目标文件中，包含了程序代码，也包含了程序数据，因为可重定位目标文件是链接器的输入文件，所以，在可重定位目标文件中还包含了引导链接器的数据结构（比如符号表等），在具体学习可重定位目标文件之前，我们先来看看符号和符号表

符号和符号表

一般情况下，每个 C 文件可以看成一个程序模块，每个程序模块一般会：
  • ① 自己定义一些符号，称为符号定义
  • ② 引用其他模块的符号，称为符号引用
比如看下图的 main1.c 就是一个程序模块，在这个程序模块中，比如全局变量 array、m，以及函数名 swap、main 都是符号定义；而 shared、sum、printf 都是引用其他模块的符号，那么这些就是符号引用（也可以称为外部符号）
在一个程序模块中定义的非静态 C 函数和非静态全局变量的符号称为全局符号，比如上图中的 array、arr_p、c、main 是全局符号，全局符号是可以被其他的程序模块引用的；而由 static 修饰的 C 函数（即静态函数）和全局变量（即静态全局变量）的符号称为局部符号，比如上图中的 swap、第 7 行代码的 m 是局部符号，局部符号只能被本程序模块引用，这里的 static 相当于 java/c++ 中 private
在一个函数中定义的符号称为本地符号，比如上图函数 swap 中定义的 a、b 和 tmp 都属于本地符号，在 main 函数中定义的 b、m、val 也都是本地符号，本地符号也可以用 static 来修饰，比如上图 main 函数中的 b、m 就是静态本地变量，没有用 static 修饰的本地符号都是非静态本地变量
需要注意的是，只有非静态本地符号（比如上图函数 swap 中的 a、b、tmp，和 main 函数中的 val）是在程序运行时在函数调用栈中被管理，链接器不会管理非静态本地符号，除了非静态本地符号，其他的符号都是在链接器管理范畴（看下图）
