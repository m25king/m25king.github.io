地址转换流程

假设进程虚拟地址大小是 n 位、物理地址大小是 m 位，页大小是 2^p 字节，那么页面偏移占 p 位，页帧号占 m - p 位，虚拟页号占 n - p 位，看下图，每个程序在装入到内存中时，执行前，内核会为这个程序创建一个页表，每个页表项包含有效位和页帧号，页表项的数量等于虚拟页的数量（即 2^(n - p)），在 MMU 中，有一个页表寄存器，保存着页表基地址和页表长度，页表基地址保存着当前正在执行的进程的页表在内存中的基地址（注意是页表的起始物理地址）
当 CPU 产生一个 n 位的虚拟地址，需要通过 MMU 将其转换为物理地址，步骤是这样（看上图）：
  • ① 首先，MMU 将这个虚拟地址分成两部分，低  p 位是页面偏移，高 n - p 位是虚拟页号
  • ② 然后，将虚拟页号和页表长度比较，如果页号大于页表长度，则产生越界异常，这里主要是做了存储保护
  • ③ 然后，将虚拟页号乘以一个 PTE 大小，再加上页表基地址，就得到虚拟页号对应的页表项的物理地址
  • ④ 根据页表项的物理地址，就可以将内存中的页表项数据读取到 MMU 中，然后查看有效位为 1 的话，就拿到这个页表项中的页帧号作为 m 位物理地址中的高 m - p 位
  • ⑤ 最后，虚拟地址的低 p 位的页面偏移，直接作为物理地址的低 p 位的页面偏移
这样，就将 n 位的虚拟地址转换为 m 位的物理地址了，拿到物理地址，就可以访问物理内存

访问内存的次数

接下来，我们来看有了地址变换机构后，CPU 要从内存中拿一次数据或者指令，需要访问几次内存，看下图：
  • ① 首先处理器（CPU）生成一个虚拟地址，这个虚拟地址可以某个数据的虚拟地址，也可以是某一条指令的虚拟地址，并把它传给 MMU
  • ② MMU 根据虚拟地址的虚拟页号和页表的基地址，生成页表项的物理地址，根据这个 PTE 的物理地址，去访问内存，这里需要访问 1 次内存
  • ③ MMU 拿到对应的页表项 PTE
  • ④ 接下来，MMU 将 PTE 中的页帧号和虚拟地址中的页面偏移拼接，得到物理地址，并把它传给内存，这里又需要访问 1 次内存
  • ⑤ 从内存中拿到数据或者指令，通过数据总线，传给处理器
可以看到，现在 CPU 每次为了拿到内存中的数据或指令，最多需要访问 2 次内存，主要就是因为引入了页表，需要额外访问一次内存中的页表，这种方式使得 CPU 的处理速度降低一半。我们引入地址变化机构的目的是为了实现分页存储管理，从而提高内存利用率，但是，这里为了提升内存利用率，而降低了计算机的处理速度，这个有点得不偿失，那如何做到即要使用这种分页机制提高内存利用率，又要使得 CPU 性能不会降低呢？答案就是缓存

缓存（TLB）

在计组的第三章，我们学习过 CPU 内部的高速缓存，对吧，它可以提升 CPU 访问内存的速度，看下图，现在处理器生成一个虚拟地址，送到 MMU，MMU 根据虚拟地址的虚拟页号和页表的基地址，生成页表项的物理地址，送到高速缓存中，如果命中，那么直接从高速缓存中拿到页表项，送给 MMU；如果不命中的话，那么需要将页表项的物理地址，发给内存，拿到对应的页表项，缓存在高速缓存中，然后再送给 MMU
MMU 拿到页表项中的页帧号和虚拟地址的页面偏移拼接成物理地址，发送给高速缓存，如果命中缓存的话，就可以直接从高速缓存中拿到数据，传给处理器；如果未命中的话，就需要将物理地址发给内存，从内存中拿到数据，然后缓存在高速缓存中，最后送给处理器
有了高速缓存，如果 PTE 和数据都命中的话，就不需要访问内存，因为指令的指令和数据的访问一般符合局部性要求，所以带有高速缓冲的处理器，处理速度非常快。不过，访问高速缓存还是存在一定的开销，这么说吧，如果 CPU 访问内部寄存器非常快，在 1 个时钟周期内就可以访问完，CPU 访问一次内存的话，可能需要 200 个左右的时钟周期，而访问一次高速缓存的话，可能需要 3 ~ 50 个时钟周期
那么，在根据 PTE 物理地址，去高速缓存中查找对应的 PTE ，命中的话，也需要消耗 3 ~ 50 个时钟周期，我们还可以通过翻译后备缓冲器（Translation Lookaside Buffer，TLB）来消除访问高速缓存的 3 ~ 50 个时钟周期的开销，在 MMU 内部，由翻译部分和 TLB 两个硬件部分组成，看下图：
当处理器生成一个虚拟地址，送到 MMU 中的翻译组件中，然后翻译组件拿到虚拟页号，去 TLB 中查找是否有对应的页表项，如果有，直接返回给翻译组件，然后，翻译组件将页表项中的页帧号和虚拟地址页面偏移拼接，得到物理地址，送到高速缓存中，如果命中，直接存高速缓存取数据，如果不命中，则将物理地址发给内存，从内存中取数据
有了 TLB，查找虚拟页对应的页表项时，可能就不需要访问高速缓存了，这个 TLB 是有特殊的 SRAM 静态存储芯片组成，并且它的工作原理和高速缓存是一模一样的，不过为了提升 TLB 的命中率，TLB 一是是全相联或者是组相联的，不会采用直接相联映射方式
TLB 和高速缓存还有一点不同的是，TLB 中只存放页表项，而且是用虚拟页号来查找，你可以把 TLB 理解为一个软件中的映射表，映射表的关键字是虚拟页号，映射表的值是页表项，而高速缓存中的数据或者指令，都是由物理地址来定位查找的，根据虚拟页号查找 TLB，如果命中的话，那么在 1 个时钟周期内，就可以拿到虚拟页对应的页表项了，所以，有的时候，我们也把这个 TLB 称为快表
如果翻译组件，在使用虚拟页号查找 TLB 时，找不到这个虚拟页对应的页表项，那么翻译组件会通过页表基地址和虚拟页号，得到页表项在内存中的物理地址（下图的 PTEA 表示的就是页表项的物理地址），将 PTEA 送到高速缓存，如果命中的话（即下图的 PTEA 命中），直接从高速缓存中拿到对应的页表项，送到 TLB 中，那么在 TLB 中会维护虚拟页号对这个页表项的映射关系，并把这个页表项 PTE 送到翻译机构
如果高速缓冲不命中的话（即上图的 PTEA 不命中），就需要将页表项的内存地址（PTEA）发给内存，拿到页表项后，缓存在高速缓存中，再送给 TLB 中，TLB 也会缓存这个虚拟页号对应的页表项，下次拿这个虚拟页号对应的页表项，就可以直接从 TLB 中拿
然后翻译组件构造物理地址，发送高速缓存，命中的话，直接拿数据，否则，去内存中拿数据，缓存到高速缓存，并传输给处理器

内存的有效访问时间

从进程发出指定逻辑地址的访问请求，经过地址变换，再到在内存中找到对应的实际物理地址单元并取出数据，所需要花费的总时间，称为内存的有效访问时间（Effective Access Time，EAT）
假设访问一次内存的时间为 t，在基本分页存储管理方式中，有效访问时间分为第一次访问内存时间 (即查找页表对应的页表项所耗费的时间 t ) 与第二次访问内存时间（即将页表项中的物理页号与页内偏移拼接成实际物理地址，然后访问内存所耗费的时间 t ）之和：EAT = t + t = 2t
在引入快表的分页存储管理方式中，通过快表查询，可以直接得到逻辑页所对应的物理页号（即页帧号），由此拼接形成实际物理地址，减少了一次内存访问，缩短了进程访问内存的有效时间（下图 a）
上图中，VA 是虚拟地址（Virtual Addres）的缩写，VPN 是虚拟页号（Virtual Page Number）的缩写，PA 是物理地址（Physical Address）的缩写
但是，由于快表的容量限制，不可能将一个进程的整个页表全部装入快表，所以在快表中查找到所需表项存在着命中率的问题。所谓命中率，是指使用快表并在其中成功查找到所需页面的表项的比率。这样，在引入快表的分页存储管理方式中，假设，λ 表示查找快表所需要的时间，a 表示命中率，t 表示访问一次内存所需要的时间，那么内存有效访问时间的计算公式即为：EAT = 查找到逻辑页对应的页表项的平均时间 + 实际物理地址的内存访问时间  = a * λ + (t + λ) (1 - a) + t = 2t + λ - t * a
