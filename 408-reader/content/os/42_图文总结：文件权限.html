每次应用程序打开文件时，都会找到对应的 inode，然后查看这个权限信息，看看应用程序有没有读写权限，接下来，我们来看下 Linux 操作系统中如何实现文件权限

Linux 操作系统中的文件权限

在 Linux 操作系统中，支持多用户，也就是说多个用户可以同时登陆一个 Linux 服务器，然后执行操作，然后，将用户分成组，每一组可能有多个用户，也可能只有 1 个用户，看下图
userA、userB、userC 三个用户属于用户组 group1，userD、userE、userF、useH 四个用户属于用户组 group2，用户 useG 属于一个组，如果一个组中只有一个用户的话，那么这个组名默认和用户名相同，都是 user G
然后，在 Linux 操作系统中每个文件可能有 3 种权限，分别是可读（read，r）、可写（write，w）、和可执行（execute，e），在这里，我们使用二进制 1 表示用户对文件有某个操作权限，二进制 0 表示用户对文件没有某个操作权限
一般而言，假设一个用户创建了一个文件 file1，那么这个文件的所有者，对它有可读权限和可写权限，如果这个文件不是可执行文件，那么用户对这个文件就没有可执行权限，看下图，用户（文件所有者）对 file1 和 file2 都有可读可写权限，而没有可执行权限；而用户（文件所有者）对 file3.sh 有可读可写可执行所有权限
而文件所有者所在的组的其他的组员，可能对这个文件只有读的权限，而没有写和执行的权限，比如用户组的其他用户对 file1 只有只读权限，没有写和执行权限；用户组的其他用户对 file2 有可读可写权限，没有可执行权限；用户组的其他用户对 file3 有可读可执行权限，没有可写权限
对于其他的用户（和文件所有者不属于同一个组），可能都不让他看，比如其他用户对 file1、file2 没有任何权限，只是对 file3.sh 有可执行权限
这样，通过这种二进制矩阵，就可以表示所有的文件的权限分配了，对于每个文件需要 3 * 3 = 9 个二进制位来表示就可以了
我们可以使用字母 r 表示具有可读权限，使用 w 表示具有可写权限，使用 e 表示具有可执行文件，使用 - 表示没有权限，上图中：
  • file1 所有者对这个文件有可读可写权限，没有可执行权限，可以写成 rw-
  • 而用户所属用户组的其他组员对 file1 具有可读权限，没有可写和可执行文件，可以写成 r--
  • 对于其他的用户，对 file1 三个权限都没有，可以写成 ---
那么这个 file1 文件的权限可以写成 rw-r-----，这也是一种文件权限的表示法
我们还可以使用整数数字来表示，对于所有者的权限是 rw-，对应 3 位二进制是 110，也就是十进制的 6，用户组权限是 r--，对应 3 位二进制是 100，也就是十进制  4，其他权限是 ---，对应 3 位二进制 000，也就是十进制的 0，所以还可以使用 640 三个整数数字来表示这个 file1 文件的权限
文件 file2 的权限 rw-rw----，对应的 9 位二进制是 110 110 000，对应十进制是 660；文件 file3.sh 的权限 rwer-e--e，对应的 9 位二进制是 111 101 001，对应十进制是 751，如果一个文件的权限是 777 的话，对应 9 位二进制是 111 111 111，那么文件的权限就是 rwerwerwe

文件创建时指定文件权限

文件的权限这个属性，在创建文件的时候，就可以指定，比如下面应用程序 A 执行 open /fs/a.txt 这个文件的系统调用，创建文件时，给这个文件的权限赋值为 644（第三个参数，即权限是 rw-r--r--）
在执行创建文件的时候，首先会去系统级打开文件表中查找 a.txt 所在的目录 fs 对应的 inode，然后查看 fs 的目录，是否存在 a.txt，如果不存在，才可以创建，如果存在的话，则报错，因为在同一个目录下文件名是不能重复的，假设没有 a.txt 目录项，所以从 inode 位图中，分配一个空闲的 inode ，然后再内存中初始化一个 inode 用于存储文件的元数据，将权限信息保存到这个 inode 上，然后，在 fs 目录中，新增一个 a.txt 对应的目录项，然后在系统级打开文件表中，新增一个表项，指向 a.txt 文件的 inode，并且在进程 A 的打开文件表中，分配一个文件描述符 3，指向这个文件的 inode，最后返回文件描述符 3

其他权限控制模型

上面的 Linux 操作系统文件权限模型称为 UGO 模型（即 User 用户、Group 用户组、Other 其他用户），除了 UGO 模型，还有基于口令密码的权限控制、访问控制表等模型
口令保护是一种简单的文件访问控制机制，核心是通过口令验证用户身份，只有持有正确口令的用户才能访问文件。 文件所有者为文件设置一个口令，口令与文件绑定，存储在文件的元数据中（如目录项或 inode 扩展信息） ， 任何用户尝试打开文件时，系统会要求用户输入口令 ， 系统将用户输入的口令与文件元数据中存储的口令进行比对，口令正确则允许用户访问文件，口令错误则拒绝访问，返回权限不足错误；口令保护只能控制 "能不能访问文件"，无法控制用户的具体操作类型（如只读 / 读写）。只要口令正确，用户就能执行文件允许的所有操作（如读写、删除）
访问控制表（Access Control List，简称 ALC） 是一种细粒度的文件访问控制机制，它的核心思想是： 为每个文件 / 目录单独维护一张 "访问控制列表"，里面列出每个用户 / 用户组对该文件的具体权限（读、写、执行等），实现比传统 UGO（用户 / 组 / 其他）更灵活的权限管理 ，传统的 UGO 权限模型只能把用户分为三类（所有者、同组、其他），无法对单个用户 / 组设置独立权限；而 ACL 可以为任意用户 / 组单独授权
