为了方便用户和提高 OS 的可适应性和可扩展性，在现代 OS 的 I/O 系统中，都无一例外地增加了与设备无关的 I/O 软件，以实现设备独立性，也称为设备无关性。其基本含义是：应用程序中所用的设备不局限于使用某个具体的物理设备。为每个设备所配置的设备驱动程序，是与硬件紧密相关的软件。为了实现设备独立性，必须再在设备驱动程序之上设置一层软件，称之为与设备无关的 I/O 软件，或设备独立性软件，在 I/O 系统中，设备独立性软件主要是完成映射、保护、分块、缓冲、分配等功能，看下图：
① 映射的作用就是将逻辑设备名转换成对应的物理设备名，一般来说，用户程序是用逻辑设备名（比如 /dev/printer、/dev/sda 等）来请求 I/O 的， 设备独立性软件的映射功能，就是把这些逻辑设备名 / 文件描述符，转换成操作系统能识别的物理设备名、驱动程序入口，让请求能正确送达对应的硬件，对于映射，我们后序还会详细学习
② 保护的核心是权限控制，防止用户程序随意操作硬件设备，导致系统崩溃或数据泄露 ，具体通过限制用户程序直接访问设备寄存器（比如硬盘的控制端口），所有操作必须通过操作系统的系统调用完成；再比如检查用户是否有读写设备的权限（比如普通用户不能直接格式化硬盘）
③ 分块的作用是适配上层数据与下层硬件的单位差异，比如用户程序提交的往往是连续的大段数据（比如一个 1GB 的文件），而底层硬盘、磁盘等硬件，只能按固定大小的块（扇区 / 簇，常见 512B/4KB）读写。设备独立性软件会把大段数据拆分成硬件能处理的块，再交给驱动程序
不同类型的设备的数据交换单位是不同的，读取和传输数据的速率也各不相同，如字符设备以单个字节 (字) 为单位，块设备以一个数据块为单位。即使同一类型的设备，它们的数据交换单位的大小也是有差异的，如不同磁盘由于扇区大小的不同，可能会造成数据块大小的不一致。与设备无关软件应能隐藏这些差异而使用逻辑设备，并向上层软件提供大小统一的逻辑数据块
④ 缓冲的作用是解决 CPU 和 I/O 设备的速度不匹配问题，减少 I/O 次数，提升效率 。无论是字符设备还是块设备，它们的运行速度都远低于 CPU 的速度，为了缓和 CPU 与I/O设备之间的矛盾、提高 CPU 的利用率，在现代OS 中都无一例外地分别为字符设备和块设备配置了相应的缓冲区。缓冲区有多种形式，如单缓冲区、双缓冲区、环形缓冲区、缓冲池等，以满足不同情况的需要，稍后我们会详细学习
⑤ 分配的作用是管理多进程对设备资源的竞争，保证资源有序、高效分配。多任务系统中，多个进程可能同时请求同一个设备（比如多个程序同时打印、多个进程同时读写硬盘），如果不管理，会出现数据混乱、死锁。对于设备的分配，我们稍后也会详细学习
接下来，我们用用户程序写文件到硬盘的例子，把这些功能串起来：
  1. 用户层：程序调用 write() 系统调用，发起写文件的 I/O 请求
  2. 设备独立性软件层：
    • 映射：把文件路径（即逻辑设备名）映射到硬盘的物理分区和设备号
    • 保护：检查用户是否有写这个文件的权限
    • 分块：把用户提交的大段数据，拆分成硬盘支持的 4KB 块
    • 缓冲：把数据先写到内存缓冲区，不直接发给硬盘
    • 分配：把请求加入硬盘的 I/O 队列
  1. 设备驱动程序层：把请求转换成硬盘控制器能识别的指令，设置寄存器，启动写操作
  2. 硬件层：硬盘执行写，完成后触发中断
  3. 中断处理程序：通知操作系统 "I/O 写操作完成"，设备独立性软件再把结果反馈给用户程序
总结下，设备独立性软件这一层的设计目标，就是 "让上层不用关心硬件细节，让下层不用关心用户逻辑"：
  • 对上层用户程序：提供统一的文件、设备接口，不用区分硬盘、U 盘、网络设备
  • 对下层驱动程序：只需要处理标准化的请求，不用考虑权限、缓冲、调度这些复杂逻辑
