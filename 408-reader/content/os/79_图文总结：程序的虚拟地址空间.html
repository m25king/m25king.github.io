地址空间（address space）

有了前面的知识铺垫后，我们来看下和内存管理相关的一个核心概念：地址空间，所谓地址空间，就是一个非负整数地址的有序集合，如果地址空间中的非负整数是连续的，那么我们就说它是一个线性地址空间，接下来，我们研究的都是线性地址空间，我们后面说的地址空间，就是线性地址空间
在上面计算机系统中，就存在两个地址空间
  • 一个是逻辑地址空间（或者称为虚拟地址空间），从 0 到 35，即 {0, 1, 2, 3, 4, 5, 6, ... , 35}
  • 一个是物理地址空间，从 0 到 1023，即 {0, 1, 2, 3, 4, 5, 6, ... , 1023}
在这里，每个字节都有两个地址，一个是逻辑地址，另一个是物理地址，CPU 通过重定位寄存器，可以将逻辑地址转换为物理地址，很明显，逻辑地址是可以很大很大的，比如逻辑地址是 48 位，那么逻辑地址空间就是从 0 ~ 2^48 - 1，而物理地址空间的大小，就取决于物理内存的容量了，这个一般不能很大，不可能有 2^48B（即 256TB） 这么大的内存

广义的编译和狭义的编译

前面我们说过 C 程序需要经过预处理、编译、汇编以及链接，生成可执行文件，才可以装入到内存进行执行，在这里的编译是狭义的 "编译"，而预处理、狭义的编译、汇编这三个阶段，构成了广义的编译（看下图），所以，很多时候，我们说编译的时候，都是指这个广义的编译
接下来，我们说的编译就是这个广义上的编译，而链接，一般是独立的，称为链接阶段，C 程序经过编译后，得到可重定位目标文件，链接阶段得到的是可执行目标文件

在链接阶段，链接器为这个可执行目标文件中的每条指令和每个数据都分配了对应的虚拟地址（或者称为逻辑地址），下图就是 prog1 这个可执行目标文件包含的内容：
上图的可执行目标文件是 64 位 gcc 编译器生成的，所以分配的虚拟地址的位数是 64 位，那么这个程序的虚拟地址空间就是 0 ~ 2^64 - 1（即从 0x0000000000000000 ~ 0xFFFFFFFFFFFFFFFF），在链接阶段，链接器只为代码段和数据段分配了虚拟地址，上图将虚拟地址空间 0x0000000000400000 ~ 0x0000000000400803 分配给了只读代码段，将虚拟地址空间 0x0000000000600E10 ~ 0x0000000000601067 分配给了读写数据段
一个程序在运行的时候，除了代码段和数据段需要占用内存外，在程序运行时产生的动态数据也需要占用内存，比如函数调用栈，再比如程序使用 malloc 动态申请的内存空间等，记住：在现代操作系统中，只要程序产生的数据需要保存在内存中，那么就需要给这个数据分配虚拟地址，当 CPU 要访问数据时，将数据的虚拟地址转换成物理内存地址，然后使用物理内存地址去物理内存中寻址数据，所以说，在一个程序运行前，链接器需要给代码段和数据段分配虚拟地址，在一个程序运行时，内核还需要给这个程序的运行时堆、共享库内存映射区域、函数栈中的数据分配虚拟地址，看下图：

上面将虚拟地址空间 0x0000 8000 0000 0000 ~ 0xFFFF FFFF FFFF FFFF 分配给操作系统的内核，内核也是软件程序，也有代码段和数据段，内核运行时也会产生临时的数据（比如我们前面学到的 FCB、文件系统相关的数据结构、I/O 设备管理的数据结构，以及进程相关的 PCB、页表等），这些都是需要虚拟地址的
不过 64 位虚拟地址空间中，一般在内核空间和用户空间之间隔着很大的空隙（看下图 a 的空洞），以此来进行隔离，那么在 64 位虚拟地址空间的 0x0000 0000 0000 0000 ~ 0x0000 7FFF FFFF F000 分配给程序的用户程序的数据和指令，将 0xFFFF 8000 0000 0000 ~ 0xFFFF FFFF FFFF FFFF 分配给内核态的内核程序的指令和数据
在 Linux 操作系统中，如果是 32 位虚拟地址空间的话，总的虚拟地址空间是 2^32 = 4G，其中内核占 1G 的虚拟地址空间（0xC000 0000 ~ 0xFFFF FFFF），用户态程序占用 3G 的虚拟地址空间（0x0000 0000 ~ 0xBFFF FFFF）
