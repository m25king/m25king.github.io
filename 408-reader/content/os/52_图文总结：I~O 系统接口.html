在整个 IO 系统中，包含了很多的 I/O 设备，这些 I/O 设备都是通过相应的控制器，连接到 IO 总线上，每一个 I/O 设备都有自己对应的中断处理程序和驱动程序（看下图），在这些设备中，分为三类设备，分别是块设备、字符设备和网络设备，在 I/O 系统中，为每一种类型的设备提供了对应的接口，分别是块设备接口、字符设备接口和网络接口，这些接口就是 I/O 系统接口
在用户发出 I/O 请求时，都需要通过系统调用处理程序，系统调用处理程序核心功能就是将用户态的请求传递到内核态，并调用对应的模块完成操作后返回结果，如果是块设备相关的 I/O 请求，就会调用块设备接口来处理 I/O 请求，如果是字符设备 I/O 请求，则调用字符设备接口来处理，如果是网络 I/O 请求，则调用网络接口来处理 I/O 请求

块设备接口

块设备接口是块设备管理程序与上层之间的接口。该接口反映了大部分磁盘存储器、光盘存储器、闪存等的本质特征，用于控制该类设备的 I/O
所谓块设备就是指数据的存取和传输都是以数据块为单位的设备，比如上图的机械磁盘、固态硬盘等，块设备的基本特点有：① 传输速率较高，每秒数十 MB 的传输速率；② 可寻址，也就是能指定读出数据在设备中的地址，或者写数据的时候，也可以指定地址，比如磁盘中的磁头号、磁道号和扇区号，我们也可以随机的读写磁盘中的任一个扇区；③ 一般这种设备的 I/O 常采用 DMA 方式
对于计算机中的所有块设备，在内核中有一系列的软件，来管理这些块设备，这些软件统称为块设备管理软件（看上图右边），块设备管理软件包括将盘块号转换为逻辑扇区、缓冲区的管理、盘块缓存的管理、I/O 调度、驱动程序管理等功能，这些都是属于和设备无关的程序功能，后续我们会一一详细学习
然后基于块设备管理的这些功能，再对上层软件提供对设备进行操作的接口，以方便上层对设备的使用，在用户应用程序中，就可以通过这些接口来操作块设备，比如一些块设备操作命令，fdisk 磁盘分区的命令、mkfs 磁盘格式化的命令（就是在磁盘分区上创建文件系统的命令）、mount 挂载命令（是将磁盘分区上的文件系统挂在到某个目录下），这些命令都会通过系统调用来调用块设备接口，来操作相应的块设备；还有就是用户程序发起的文件操作，通过文件系统后，也会调用块设备接口，来访问对应的块设备
当块设备接口接收到用户层的 I/O 命令，就会将这些 I/O 请求转发给块设备管理程序，块设备管理程序会找到对应的设备驱动程序；然后设备驱动程序将 I/O 请求转换为具体的命令，发给对应的控制器，然后控制设备完成 I/O 操作；当 I/O 操作完成的话，可能会发出一个中断信号，然后执行相应的中断处理程序，中断处理程序有可能需要唤醒在执行驱动程序是阻塞的进程，然后继续执行驱动程序，执行完，返回即可
虚拟存储器系统（即虚拟内存）也需要使用块设备接口，因为在进程运行期间，每当它所访问的页面不在内存中时，便会发生缺页中断，此时就需要利用 I/O 系统（通过块设备接口）从磁盘存储器中将所缺页面调入内存

字符设备接口

字符设备接口也可以称为流设备接口，是字符设备管理程序与上层之间的接口（看下图），它反映了大部分字符设备的本质特征，用于控制字符设备的 I/O
所谓字符设备，是指数据的存取和传输是以字符为单位的设备，如键盘、打印机等，字符设备的基本特征有：① 传输速率较低，通常为每秒几个字节至数千字节；② 不可寻址，比如，用打印机打印字符，不用给出地址，从键盘中读入字符，也不用给出地址；③ 字符设备在输入/输出时，常采用中断驱动方式
在内核的 I/O 系统 中，也会有对应的字符设备管理程序，来管理字符类的设备，并且对上层用户提供字符设备接口，比如看上图，计算机中有一台打印机，使用设备文件 /dev/printer 来表示，接下来在用户程序中通过 open 来启动这个打印机，然后通过 write 让打印机打印 1024 个字符数据，这些系统调用，陷入内核后，在系统调用服务程序中会调用字符设备的接口，将要打印的数据拷贝到打印机的缓冲区，然后，通过设备分配查找功能，根据这个设备文件找到打印机的驱动程序，驱动程序，会将具体的打印命令和数据下发给打印机控制器，让打印机打印数据，打印完一个字符后，会发送一个中断信号给 CPU，然后 CPU 去执行打印机中断处理程序，如果缓冲区还有数据的话，就继续打印数据，没有的话，则直接返回了
在字符设备管理中，也有设备驱动程序管理，用于管理不同字符设备的驱动程序，另外还有设备访问控制，有些设备只能一个进程使用，所以，当多个进程用时，就需要进行访问控制，对吧，比如这个键盘，确保一次只有一个进程读取键盘输入

阻塞 I/O 和非阻塞 I/O

在应用程序调用 I/O 系统调用接口时，需要选择阻塞 I/O 还是非阻塞 I/O，默认情况下，比如 read、write 等这些 I/O 系统调用都是阻塞 I/O，所谓阻塞 I/O 就是当进程（线程）执行 I/O 时，当进程执行到驱动程序时，当前进程会被挂住（即被阻塞），然后等待 I/O 设备完成 I/O 操作，再通过中断来唤醒当前进程继续执行
上图是阻塞 I/O（Blocking I/O，简称 BIO）的执行步骤，应用进程发起 read I/O 读操作，执行到驱动程序时会被挂起来，一直等到 I/O 操作结束，此时数据已经从 I/O 设备拷贝到内核缓冲区，然后 I/O 设备发出中断信号，在中断处理程序中，会唤醒当前进程（线程），当前进程继续执行驱动程序将内核缓冲区中的数据拷贝到用户态的缓冲区，拷贝完成后，就会成功返回
所谓非阻塞 I/O（Non-Blocking I/O，简称 NIO） 就是当进程（线程）执行 I/O 时，当进程执行到驱动程序时，当前进程不会被挂起阻塞，而是立即返回，看下图：
上图应用进程发起 read I/O 读操作，当在内核中执行到驱动程序时，会判断内核缓冲区是空的，即数据没有准备好，那么当前进程会立即返回，不会阻塞；等过一小段时间，应用进程再发起 read I/O 读操作，如果数据还未准备好，那么立即返回；等过一小段时间，应用进程再发起 read I/O 读操作，如果此时数据已经准备好，即 I/O 控制器已经将设备中的数据拷贝到内核缓冲区了，那么当前进程执行驱动程序，将内核缓冲区数据拷贝到用户态缓冲区，拷贝完成后，就会成功返回
阻塞 I/O 就好比，你去了书店，告诉老板你想要某本书，然后你就一直在那里等着，直到书店老板找到你想要的书为止；而非阻塞 I/O 就好比，你去了书店，问老板有没有某本书，老板告诉你没有，你就离开了，一周后，你又来这个书店，再问这个老板，老板一查，有了，于是你就买了这本书
很明显，这种非阻塞 I/O 需要应用进程不断的轮询调用 read，其效率不高，还有一种效率更高的非阻塞 I/O，就好比，你去了书店，直接告诉老板："老板，书到了的话给我打电话吧，我再来付钱取数"，来看下图：
这里就需要多路复用技术了，应用进程通过多路复用技术直接通知内核要读取哪个设备的数据，一旦设备的数据准备好了就会通知应用进程，然后应用进程再通过 read 去读取数据到用户态缓冲区，这里我们稍微了解下即可
