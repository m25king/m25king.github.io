中断和异常的分类

到现在为止，我们学习了外部中断（硬中断）、软中断、内部异常等内容，接下来，我们稍微总结下这些相关的概念，首先我们平时叫的中断，一般就是指外部中断（硬中断），很多时候我们把软中断称为陷阱，主要是因为在用户态执行软中断 int 指令时会使得系统陷入内核态，可以这么说，陷阱是有意的内部异常，是执行一条指令（比如 int 指令）的结果，这些概念之间的分类如下图：

外部中断

外部中断是异步发生的，是来自处理器外部的 I/O 设备的信号的结果。硬件中断不由任何一条专门的指令造成的，就是说和指令没关系，从这个意义上来说它是异步的，下图是一个中断的处理（Icurr 是当前 CPU 正在执行的指令，Inext 是 Icurr 的下一条紧挨的指令）
I/O 设备，例如网络适配器（网卡）、磁盘控制器和定时器芯片，通过向 CPU 芯片上的一个引脚发信号，并将中断向量号放到系统总线（数据总线）上，来触发中断，CPU 可以通过这个中断向量号识别引起中断的设备，在当前指令执行完后，CPU 注意到中断引脚的电压变高，它就从系统总线读取中断向量号，然后调用适当的中断处理程序。当处理程序返回时，它就将控制返回给下一条指令 Inext，接下来 CPU 开始执行 Inext 这条指令，即程序继续执行，就好像没有发生过中断一样
外部中断和指令无关，是异步发生的，而内部异常却是同步发生的，是执行当前指令的结果

陷阱

陷阱是有意的内部异常，是执行一条指令（比如软中断指令 int 或者 syscall 指令）的结果，就是当 CPU 执行一条 int 指令或者 syscall 指令时，肯定会发生内部异常，这些异常都是系统有意为之的，这些异常也主要是为了实现某些功能的，陷阱最重要的用途是在用户程序和内核之间提供一个像过程一样的接口，叫做系统调用
用户程序经常需要向内核请求服务，比如读一个文件（read）、创建一个新的进程（fork）、加载一个新的程序（execve)，或者终止当前进程（exit)。为了允许对这些内核服务的受控的访问，处理器提供了一条特殊的 "syscall n" 指令，当用户程序想要请求 n 号系统调用服务时，可以执行这条指令，看下图：
执行 syscall 指令会导致一个到异常处理程序的陷阱，这个处理程序解析参数，并调用适当的内核程序，当陷阱处理程序执行完，返回时，也是将控制返回到下一条指令（即执行下一条指令 Inext），这个是外部中断是一样的
从程序员的角度来看，系统调用和普通的函数调用是一样的。然而，它们的实现非常不同。普通的函数运行在用户态中，用户态限制了函数可以执行的指令的类型，而且它们只能访问与调用函数相同的栈。系统调用运行在内核态中，内核态允许系统调用执行特权指令，并访问定义在内核中的栈（即内核栈）

故障

陷阱是有意的内部异常，那么故障就是无意的内部异常，就是说当 CPU 执行一条指令时，有时会产生异常，有时却又不会产生异常，比如执行除法指令时，如果除数是 0 的话，就会产生除 0 异常，如果除数非 0 的话，就不会产生异常
故障由错误情况引起，它可能能够被故障处理程序修正。当故障发生时，处理器将控制转移给故障处理程序。如果处理程序能够修正这个错误情况，它就将控制返回到引起故障的指令，从而重新执行它。否则，处理程序返回到内核中的 abort 例程，abort 例程会终止引起故障的应用程序。下图概述了一个故障的处理
一个经典的故障示例是缺页异常，当指令引用一个虚拟地址，而与该地址相对应的物理页面不在内存中，因此必须从磁盘中取出时，就会发生故障。一个页面就是虚拟内存的一个连续的块（典型的是 4KB)。缺页处理程序从磁盘加载适当的页面，然后将控制返回给引起故障的指令。当指令再次执行时，相应的物理页面已经驻留在内存中了，指令就可以没有故障地运行完成了
对于故障处理程序执行完，返回到当前的指令 Icurr 重新执行，还是返回到下一条指令 Inext，这个取决于故障的类型，如果是缺页异常的话，返回到当前发生缺页异常的指令 Icurr 重新执行；如果是非法操作码异常的话，那么肯定是返回到下一条指令 Inext 执行；如果是除 0 异常的话，可以是返回到 Icurr、也可以是返回到 Inext

终止

终止是不可恢复的致命错误造成的结果，通常是一些硬件错误，比如 DRAM 或者 SRAM 位被损坏时发生的奇偶错误。终止处理程序从不将控制返回给应用程序
