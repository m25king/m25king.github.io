内核态和用户态

CPU 既可以执行应用程序的指令，也可以执行操作系统内核中的指令，一般而言，在 CPU 中，用一个寄存器（一般是标志寄存器）中的一个位，也就是模式位，来区分现在 CPU 执行的是应用程序的指令，还是执行内核的指令
  • 当模式位等于 0 时，表示当前 CPU 执行的是内核中的指令，我们将这种状态称为内核态
  • 当模式位等于 1 时，表示当前 CPU 执行的是应用程序中的指令，我们将这种状态称为用户态
那么，这样区分内核态和用户态两种工作模式，有什么用呢？这样区分的好处是，可以对计算机系统起到保护作用。在一台计算机中，指令集包含了这台计算机可以执行的所有的指令，如果 CPU 处于内核态的话，可以执行所有的指令，而如果 CPU 处于用户态的话，只能执行部分的指令，看下图
除了用户态可以执行的指令，其他指令称为特权指令，这些指令用于控制计算的，这些指令可以直接操作硬件，比如这里的 in 和 out 指令可以直接访问磁盘的，这样做的好处很明显，如果应用程序也可以执行特权指令的话，那么我随便写一个程序，就去控制计算器，占用着硬件不放，这样导致其他用户的应用程序就运行不了了，这样是很不安全的
再比如，中断管理中的关中断指令也是特权指令，如果应用程序可以随便的执行关中断指令的话，然后又忘了开中断的话，那么整个计算机就崩溃了，输入键盘以及鼠标点击，系统都不会响应你了，所以说，如果这些特权指令应用程序执行的话，是很危险的
以后你需要区分哪些程序指令是运行在用户态，哪些程序指令运行在内核态，这个其实很好区分，如果执行的是操作系统内核的程序指令，那么 CPU 肯定是处于内核态。那什么时候会去执行内核的程序指令呢？无非就是应用程序发起系统调用时，此时需要从用户态切换到内核态，然后执行内核中的系统调用服务程序，当系统调用服务程序结束了，可能需要从内核态切回到用户态；还有就是，CPU 执行指令时发生了异常，需要去执行内核中的异常处理程序，以及外部 I/O 设备发起了中断，也需要去执行内核中的中断处理程序
那么当发生了异常或者中断，是需要从用户态切换到内核态吗？这个不一定，要不要切换，取决于发生异常或者中断时，CPU 是否处于用户态
假设现在 CPU 处于用户态，正在执行应用程序 A 中的一个 div 除法指令，发生了除 0 异常，此时需要从用户态切换到内核态，去执行除 0 异常服务程序，当除 0 异常服务程序执行完，可能需要切回到用户态，继续执行应用程序 A 的程序指令，如果这个时候，键盘输入数据，发起一个中断，此时需要从用户态切换到内核态，去执行内核中的键盘中断服务程序，当键盘中断服务程序执行完，可能切回到用户态，继续执行应用程序
当应用程序执行系统调用指令，进行系统调用时，从用户态切换到内核态，然后执行内核中的系统调用服务程序，比如写磁盘程序，假设现在发生了一个鼠标中断，因为现在处于内核态，所以，就不需要切换了，直接去执行鼠标中断服务程序，当鼠标中断服务程序执行完，返回到写磁盘程序，因为都是处于内核态，所以也不需要切换

所以说，当发生异常和中断时，CPU 处于用户态，则需要切换到内核态，如果 CPU 处于内核态，就不需要切换了；因为中断是随时都可能发生的，不管 CPU 处于用户态在执行应用程序的指令，还是 CPU 处于内核态在执行内核的程序指令，中断随时都可能发生，你可以想想以下，鼠标点击、键盘输入这些中断，是不是随时都可能发生，也就是说，CPU 在执行程序时，随时都可能被中断打断
不过，在内核中，有很多程序函数是不能被中断打断的，我们将这种不能被中断打断的程序函数称为原语，比如，当 CPU 执行内核中的创建进程的函数，此时即使有中断发生，也不能去响应中断，因为这个创建进程的操作是原子的，要么全部执行完，要么不执行，中间不能被中断打断，你想哈，如果创建进程被打断的话，相当于进程是个半成本，这个是不允许的，原语的执行是 "一气呵成" 的，在执行过程中不会被任何其他进程或中断打断

特权指令 vs 非特权指令

特权指令： 只能在内核态（管态 / 核心态）执行的指令，其核心特征是直接影响系统全局状态、硬件资源或其他进程，用户态执行会触发异常 ；非特权指令： 可在用户态执行的指令，其核心特征是仅操作进程自身资源，不影响系统全局状态，对其他进程透明

以下是快速判断的小技巧：
  • 看影响范围：如果指令会影响整个系统（比如停机、改时钟、关中断），一定是特权指令；如果只影响进程自己（比如改局部变量、算加减），就是非特权指令  
  • 看操作对象：直接操作硬件资源（I/O 端口、中断控制器、时钟芯片）的指令，都是特权指令；操作进程私有资源（寄存器、栈、虚拟内存）的指令，用户态可执行  
  • 看权限限制：凡是需要 "内核权限" 才能执行的操作，比如修改页表、调度进程，都属于特权指令，用户态执行会被 CPU 拦截
