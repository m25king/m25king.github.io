下图是前面可重定位目标文件 main1.o 的 ELF 头，ELF 头以一个 16 字节的序列开始（下图的 Magic 字段），这个序列描述了生成该文件的系统的字的大小和字节顺序，比如下图的 main1.o 就是在 64 位系统中生成的，其字节存储顺序采用的是小端序（下图 little endian），并且采用补码表示整数（下图 2's complement 表示补码）
ELF 头剩下的部分包含帮助链接器语法分析和解释目标文件的信息，比如链接器根据 ELF 头中的 Type 字段为 REL 的话，就知道这是一个可重定位目标文件，还可以根据 Machine 字段知道机器使用的指令集是 X86-64；还可以根据字段 Size of this header 得到上图的 ELT 头的大小是 64 字节

节（section）

.text 节

.text 节，保存了已编译程序的机器代码，可以通过  objdump -Dj .text main1.o 来查看可重定位文件 main1.o 中的 .text 节中保存的机器代码：

.data 节

.data 节，保存了已初始化的全局和静态 C 变量，可以通过命令  objdump -Dj .data main1.o 来查看可重定位文件 main1.o 中的 .data 节中保存的 C 变量：
上图的 array、arr_p 都是已经初始化的全局变量，m 和 b 都是已经初始化的静态变量（其中 b 是在函数中定义的静态本地变量）

.bss 节

.bss 节，保存了未初始化的静态变量，以及初始化为 0 的全局或静态变量，可以通过命令  objdump -Dj .bss main1.o 来查看可重定位文件 main1.o 中的 .bss 节中保存的 C 变量：
上图 main 函数中定义的静态变量 m 就是一个未初始化的静态 C 变量，在上图中，变量 c 属于未初始化的全局变量，它不会放在可重定位目标文件的 .bss 节中，它实际上被放在一个名为 COMMON 的伪节中，了解即可。在目标文件中，这个 .bss 节是不占据实际的磁盘空间，它仅仅是一个占位符，你从下面图就可以看出 .bss 不占任何的空间，.bss 的起始文件偏移量和下面的 .rodata 节的起始文件偏移量是一样的，.bss 节后面括号中的 4B 表示的是保存在 .bss 中的变量的在程序运行时需要占用内存大小，比如上图的 m 是 int 类型，在程序运行时需要 4B 的内存
从上可以看到，.data 节保存了已初始化的全局和静态 C 变量，.bss 节保存了未初始化的静态变量以及初始化为 0 的全局或静态变量，这里区分已初始化和未初始化的目的就是为了节省目标文件占用的磁盘空间，对于未初始化的变量（或者初始化为 0 的变量）不需要占据任何实际磁盘空间，仅仅只是一个占位符而已，只有在程序运行时，才会给这些变量分配内存，并初始化为 0

.rodata 节

.rodata 节，保存了只读数据，比如字符串。可以通过命令  objdump -sj .rodata main1.o 来查看可重定位文件 main1.o 中的 .rodata 节中保存只读数据：
上图中 printf 第一个参数就是字符串，这种只读字符串就会保存在 .rodata 节中

.symtab 节

.symtab 节，保存了符号表，存放程序模块中定义和引用的符号，这些符号都是链接器管理的，下图就是可重定位目标文件 main1.o 的符号表：
链接器根据 .symtab 节中的符号表可以定位每个符号在可重定位目标文件中的位置，看上图的 Ndx 字段表示节的序号，你看符号 array、m、arr_p 以及 b.2191 都是位于 3 号节中，你看上面的节头部表可以知道 3 号节就是 .data 节，也就是说，array、m、arr_p 以及 b.2191 都是位于 .data 节中，然后链接器再根据上面的 Value 字段可以定位符号在 .data 节中偏移，根据上面的 Size 字段可以知道这个符号对应变量所占的空间，比如上面符号 m（上图第 7 行代码的 m） 的 Value 值是 0x8，它的 Size 值是 4，那么符号 m 对应的变量的值就保存在 .data 节偏移量为 0x8 的位置，这个变量的值的大小是 4B（变量 m 是 int 类型）
看下图，我们使用 objdump -sj .data main1.o 来查看 .data 节中保存的数据内容，你看偏移为 0x8 的位置的 4 个字节 0a000000（十六进制） 就是变量 m 的值（也就是十进制的 10，注意，这里采用的是小端序，所以 m 的最低有效字节 0x0a 放在低地址）
链接器可以根据上面的符号表来定位每一个符号对应变量在 .data 中保存的值，比如 array 在 .data 节中的偏移是 0，而且 array 包含了 2 个 int 类型的元素，其大小是 8B，所以，在上面 .data 节中的前 4 个字节 01000000（十六进制，对应十进制的 1）就是 array[0] 的值，往后的 4 个字节 02000000（十六进制，对应十进制的 2）就是 array[1] 的值
再比如 arr_p 在 .data 节的偏移是 0x10，因为是一个指针，其大小是 8B，所以，在偏移量为 0x10 处的 8 个字节 00000000 00000000 就是 arr_p 变量的内容，可以看到这种全局指针在可重定位目标文件中还没有初始化（其值是 0），这种全局指针会在链接阶段初始化（经过重定位后再初始化），这个我们下一小节再来看。因为 arr_p 指针占 8B，为了满足内存对齐的要求，arr_p 的起始地址必须是 8 的倍数，因此，在上图，这个 arr_p 的起始偏移必须是 0x10（即十进制的 16），因为 16 是 8 的倍数，那么偏移量为 16 的前 4 个字节就是为了内存对齐而填充的字节了
再比如符号表中的符号 b.2191，它对应着在 main 函数中定义的静态 int 类型的变量 b，它在 .data 的偏移量是 0x18，大小是 4B，那么在 .data 节中，起始偏移为 0x18 的 4 个字节 04000000（对应十进制的 4）就是变量 b 的值。上面我们分析了链接器如何根据符号表找到每个符号变量在 .data 节中保存的数据，当然，连接器也可以根据同样的方法找到其他任何节中保存的数据
