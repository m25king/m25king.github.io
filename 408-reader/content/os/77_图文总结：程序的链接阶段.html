符号解析

目标文件定义和引用符号，每个符号对应于一个函数、一个全局变量或一个静态变量，符号解析的目的是将每个符号引用正好和一个符号定义关联起来，看下图：
看上面的 main1.o 的符号表中，可以看到有 3 个符号引用（sum、shared 和 printf），其中 printf 是在 C 标准库的可重定位目标文件中定义的（上面没有截图），sum 和 shared 两个符号是在 sum1.o 中定义的，看上面 sum1.o 的符号表可以看到
  • 符号 sum 是保存在 1 号节（即 .text 节）中偏移量为 0 的位置，它的 Type 是 FUNC，表示 sum 是一个函数，其包含指令的大小是 69B
  • 符号 shared 是保存在 2 号节（即 .data 节）中偏移量为 0 的位置，它的 Type 是 OBJECT，Bind 是 GLOBAL，表示 shared 是一个全局变量，它的大小是 4B（shared 是 int 类型）
链接器会读取 main1.o 中的符号表和 sum1.o 中的符号表，并且将 main1.o 中的符号引用和 sum1.o 中的符号定义关联起来，并且将符号写到可执行目标文件 prog 的符号表中（上图只截取了一部分 prog 的符号表），你看，在可执行目标文件 prog 的符号表中存在 sum 和 shared 这两个符号，其中：
  • sum 是函数，包含 69B 的指令，链接器也为 sum 函数分配了虚拟内存地址，其起始虚拟地址是 0x00000000004005a3
  • shared 是全局变量，大小是 4B，链接器也为 shared 分配了虚拟内存地址，其起始虚拟地址是 0000000000601054

分配虚拟内存地址

编译器和汇编器生成从地址 0 开始（这个地址可以理解成文件偏移量）的代码和数据节。链接器通过把每个符号定义与一个内存位置关联起来（其实就是分配虚拟地址），从而重定位这些节，然后修改所有对这些符号的引用，使得它们指向这个内存位置。我们来详细解释下，首先是来看分配内存地址
当执行完 gcc main1.o sum1.o -o prog1 后，得到的可执行目标文件 prog1 也是一个 ELF 格式的文件， 此时链接器会读取 2 个可重定位目标文件 main1.o 和 sum1.o，首先将多个可重定目标文件中的相同的节进行合并，下图的可执行目标文件 prog1 也包含了很多节，不过下图只给出了我们需要关心的节在可执行目标文件中的偏移位置和大小，可以看到可重定位目标文件中的相同节进行合并，比如 main1.o 的 .text 节和 sum1.o 的 .text 节进行合并到 prog1 的 .text 节中：
上图的可执行目标文件 prog1 的大小 = prog1 的节头部表的偏移 0x1A68 + 节头部表的大小 1920B = 8680B，在 prog1 中多了很多的节（一共有 30 个节），其中 .init 节保存了一个名为 _init 的小函数对应的指令，程序的初始化代码会调用这个函数，其他的 .text、.rodata、.data、.bss、.symtab 这些节和可重定位目标文件中对应的节是相似的

所以说，在可执行目标文件中的 .bss 节保存的是未初始化的（或者初始化值为 0）全局变量和静态变量
接下来，链接器为可执行目标文件 prog1 中的程序指令和数据分配虚拟内存地址（64 位系统分配的是 64 位虚拟地址），可执行目标文件的连续的片被映射到连续的虚拟内存段，这种映射关系被记录在段头部表（上图 prog1 中的第 2 个区域）中，以下是 prog1 的段头部表的内容：
我们主要关心 Type 为 LOAD 的两个条目即可，第 1 条 LOAD 类型的条目中，链接器将虚拟地址段 0x0000000000400000 ~ 0x0000000000400803 分配给可执行目标文件 prog1 的前 804 个字节（每个字节一个地址），包括了 ELF 头、段头部表、.init 节、.text 节和 .rodata 节（看下图），这一个段称为代码段，这一段主要是包含了程序指令（.text 和 .init）和只读数据（.rodata），所以这个段的权限（看上图的 Flags 字段）是可读（R）和可执行（E）两个权限，指令代码是可读可执行的，代码段中的指令和数据都是只能读不能修改的，所以也会称为只读代码段
上面第 2 条 LOAD 类型的条目，链接器将虚拟地址段 0x0000000000600E10 ~ 0x0000000000601067 分配给从文件偏移 0x0E10 ~ 0x1057 这一文件段保存的数据，这个段包括了 .data、.bss 等节，这些节中保存的是程序变量对应的值，而且这些变量的值是可以修改的，因此这个段的权限是可读可写（RW），我们将这个段称为数据段，从上面可以看到数据段在磁盘文件中的大小是 0x248 字节，但是如果加载到内存中的话，其内存大小是 0x258 字节，这是因为 .bss 中的 16B 的数据是不会保存在可执行目标文件中，而当数据段加载到内存中时，会将 .bss 中的变量的值初始化为 16B 的 0
在执行 prog1 之前，都是需要将对应可执行目标文件中的代码段和数据段都加载到内存中，所以，需要为这两个段中的指令和数据分配虚拟内存地址，而可执行目标文件中其他的节（比如 .comment、.symtab 等）和节头部表都不需要加载到内存中，所以不需要为他们分配虚拟内存地址

我们可以通过命令 objdump -sj .data prog1 来查看 prog1 中的 .data 节的指令，看下图，.data 的第一个数据的虚拟内存地址就是 0x601030

重定位

既然链接器给可执行目标文件中的代码段和数据段都重新分配了虚拟内存地址，那么在代码段和数据段中的每条指令和每个数据都有自己对应的虚拟内存地址，接下来链接器就需要根据可重定位目标文件中的重定位条目将 .text 节和 .data 节中符号修改成对应的虚拟内存地址
首先，链接器可以查看 prog1 的符号表，得到符号 array 的起始虚拟内存地址是 0x601038（看下图），在 main1.c 中，array 是全局变量，它的数据保存在数据段（ .data 节）中，上面可以看到数据段的起始虚拟内存地址是 0x0000000000600E10，所以 array 的起始虚拟内存地址肯定是大于数据段的起始虚拟地址的
再来看下图是 main1.o 中的 .text 节相关的重定位条目，其中第一个条目就是关于符号 array 的重定位了，其重定位的位置是在 main1.o 的偏移量（Offset）为 0x3a 的位置上，链接器根据这个重定位条目，会直接将 main1.o 中偏移为 0x3a 的 4 个字节直接修改为符号 array 的起始虚拟内存地址 0x601038（看下图，注意是小端序），这就是链接器的重定位功能
再比如，链接器可以查看 prog1 的符号表，得到符号 sum 的起始虚拟内存地址是 0x4005a3（看下图），sum 是函数，它的指令保存在代码段（ .text 节）中，上面可以看到代码段的起始虚拟内存地址是 0x0000000000400000，所以 sum 函数的起始虚拟内存地址肯定是大于代码段的起始虚拟地址的
再来看下图是 main1.o 中的 .text 节相关的重定位条目，其中第二个条目就是关于符号 sum 的重定位了，其重定位的位置是在 main1.o 的偏移量（Offset）为 0x3f 的位置上，链接器根据这个重定位条目，直接将 main1.o 中偏移为 0x3f 的 4 个字节直接修改为 0x00000033（看下图）
你可能会好奇，这里为什么不直接修改为 sum 函数的起始虚拟内存地址 0x4005a3 呢？这个其实很好理解，因为 X86 的 callq 指令采用的是相对寻址，这个 0x00000033 是相对于 PC 的偏移量，callq 的目的内存地址 = PC + 偏移量 = 紧挨着 callq 指令的下一条指令的内存地址 0x400570 + 0x00000033 = 0x4005a3，这个就是 sum 函数的起始虚拟内存地址
再来看 .data 节中的可重定位条目，看下图，只有 1 条，就是取全局变量 array 的地址时产生的，在可重定位目标文件中还没有虚拟内存地址，所以取不到 array 的地址，因此，在 main1.o 中的偏移为 0x10 位置的 8 个字节都是 0，也就是说指针 arr_p 的值是 0
在链接器为 array 分配了虚拟内存地址 0x601038 后，就需要对 .data 中的 arr_p 进行重定位了，也就是将 prog1 中的 .data 节中的 arr_p 的值直接修改为 array 的地址 0x601038（注意，上图是小端存储），这就是 .data 节中的重定位

总结

一旦链接器完成了符号解析这一步，就把代码中的每个符号引用和正好一个符号定义（即它的一个输入可重定位目标文件中的一个符号表条目）关联起来。此时，链接器就知道它的输入可重定位目标文件中的代码段和数据段的确切大小。现在就可以开始重定位步骤了，在这个步骤中，将合并输入可重定位目标文件，并为每个符号分配运行时虚拟内存地址。重定位由两步组成：
①  重定位节和符号定义。在这一步中，链接器将所有相同类型的节合并为同一类型的新的聚合节。例如，来自所有输入模块的 .data 节被全部合并成一个节，这个节成为输出的可执行目标文件的 .data 节。然后，链接器将运行时内存地址赋给新的聚合节，赋给输入可重定位目标文件定义的每个节，以及赋给输入可重定位目标文件定义的每个符号。当这一步完成时，程序中的每条指令和全局变量都有唯一的运行时虚拟内存地址了
② 重定位节中的符号引用。在这一步中，链接器修改代码段和数据段中对每个符号的引用，使得它们指向正确的运行时虚拟内存地址。要执行这一步，链接器依赖于可重定位目标文件中称为重定位条目
经过链接器的链接阶段后，就得到一个可执行目标文件 prog1，以下是这个可执行目标文件的 ELT 头：
当在 shell 中执行 ./prog1 的时候，内核中的加载器会将这个可执行目标文件中的代码段和数据段从磁盘中复制到内存中，然后通过跳转到程序的第一条指令或入口点来运行该程序，在 ELF 头中的 Entry point address 字段对应的值 0x400440 就是这个程序要执行的第一条指令的虚拟内存地址，当程序启动时，会将 0x400440 送到 PC 中，然后 CPU 中的 MMU 会将这个虚拟内存地址 0x400440 转换成物理地址（这个后面会讲），然后拿到物理地址去主存中拿到对应的指令，CPU 开始执行程序的第一条指令，这样，prog1 程序便开始执行了
