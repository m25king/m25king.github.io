在计算机系统中，I/O 系统主要用于控制外设与内存、外设与 CPU 之间进行数据交换，包括 I/O 硬件（比如外部设备及其接口、I/O 控制部件等）和 I/O 软件（比如驱动程序、中断处理程序等），对于 I/O 硬件我们已经在计组第七章详细学习过，这一章我们主要学习 I/O 软件
上一章我们通过机械磁盘或固态硬盘这种外存设备，学习了文件这个抽象的概念，我们也知道了所有的 I/O 设备都可以看成是一个文件，每个 I/O 设备在操作系统中都有一个文件名，通过这个文件名，应用程序就可以通过系统调用 open、read、write 等来访问对应的 I/O 设备，这样可以方便用户使用 I/O 设备，接下来，我们来就来看下 I/O 系统的六大功能

功能一：能够隐藏 I/O 设备的细节

I/O 设备的类型非常多，且彼此间在很多方面都存在差异，如它们接收和产生数据的速度、数据传输方向、数据粒度、数据的表示形式以及可靠性等方面。为了对这些千差万别的 I/O 设备进行控制，通常会为它们配置相应的设备控制器。这是一种硬件设备，其中包含若干个用于存放控制命令和参数的寄存器。用户通过这些命令和参数，可以控制 I/O 设备执行所要求的操作
显然，对于不同的 I/O 设备，需要有不同的命令和参数。例如，在对磁盘进行操作时，不仅要给出本次是读命令还是写命令，还要给出源数据或目标数据的位置，包括磁盘的盘面号、磁道号和扇区号。由此可见，要求程序员或用户编写直接面向这些 I/O 设备的程序是极其困难的。因此，I/O 系统必须通过对 I/O 设备加以适当的抽象（比如将 I/O 设备看成文件），以隐藏 I/O 设备的实现细节，仅向上层进程提供少量的、抽象的读/写命令，如 read、write 等系统调用

功能二：够保证设备无关性

隐藏物理设备的细节，在早期的 OS 中就已实现，它可以方便用户对设备进行使用。保证设备无关性这一功能，是在较晚时才实现的，且是在隐藏 I/O 设备细节的基础上实现的
一方面，用户不仅可以使用抽象的 I/O 命令，还可以使用抽象的逻辑设备名（其实就是文件名）来使用设备，例如，当用户要输出打印时，他只须提供 (读或) 写的命令 (用于提出对 I/O 设备的要求) 和抽象的逻辑设备名，如 /dev/printer 这个文件路径名，而不必指明具体是哪一台打印机
另一方面，也可以有效地提高 OS 的可移植性和易适应性。对于 OS 本身而言，应允许在不需要将整个 OS 进行重新编译的情况下增添新的设备驱动程序，以方便新的 I/O 设备安装。如在 Windows 系统中，系统可以为新的 I/O 设备自动寻找和安装设备驱动程序，从而做到即插即用
隐藏 I/O 设备的细节的核心目标是屏蔽设备的底层操作差异，给用户提供统一、简单的操作接口；它解决的是 "不同设备怎么用" 的问题，比如，用户要读数据，只需要调用read()，不用关心磁盘是用磁道号 / 扇区号寻址，还是打印机需要控制字间距、走纸命令
隐藏 I/O 设备的细节是靠抽象接口 + 控制器封装实现：
  • 向上层提供统一的系统调用（read/write/open/close），所有设备都用同一套接口
  • 底层通过设备控制器接收抽象命令，再翻译成硬件能理解的具体信号，把细节藏起来

设备无关性的核心目标是让应用程序不依赖于具体的物理设备型号，可在不同设备间通用；解决的是 "同一类设备用哪个" 的问题，比如，程序里写的是 /dev/printer 这个逻辑设备名，系统会自动映射到当前连接的任意一台打印机，不用为每台打印机写一个版本的程序

设备无关性靠逻辑设备名映射实现：
  • 操作系统为设备分配抽象的逻辑名（如/dev/sda、/dev/printer）
  • 程序只使用逻辑名，由系统在运行时映射到具体的物理设备，屏蔽了硬件差异
设备无关性建立在隐藏设备细节的基础上，是更高一层的抽象

功能三：能够提高 CPU 和 I/O 设备的利用率

在一般的系统中，许多 I/O 设备间是相互独立的，能够并行操作，CPU 与设备之间也能并行操作。因此，I/O 系统的第三方面功能是尽可能地让处理机（即 CPU）和 I/O 设备并行操作，以提高它们的利用率。为此，一方面要求处理机能快速响应用户的 I/O 请求，使 I/O 设备能够尽快运行起来；另一方面要求尽量减少在每个 I/O 设备运行时处理机的干预时间。在本章中将介绍许多有助于实现该目标的方法，下面可以提高 CPU 和 I/O 设备的利用率的技术实现，我们在后续会一一学习的
首先，比如缓冲（Buffering）技术利用内存中的缓冲区暂存数据，解决 CPU 与 I/O 设备速度不匹配的问题，让设备读写和 CPU 处理能并行进行
  • 单缓冲：设备和 CPU 交替使用缓冲区，初步缓解速度差
  • 双缓冲 / 多缓冲：设备填充一个缓冲区时，CPU 处理另一个，实现真正的并行
  • 缓冲池：系统统一管理多个缓冲区，动态分配给不同进程 / 设备，进一步提升效率
其次，再比如实现中断驱动 I/O 技术，设备完成 I/O 操作后主动向 CPU 发中断信号，CPU 无需轮询等待，平时可以处理其他任务，仅在中断到来时响应，避免了 CPU 空等设备的低效状态 ；再比如实现 DMA 技术，让 I/O 设备直接和内存交换数据，不需要 CPU 全程干预，CPU 只需在传输开始和结束时做少量初始化 / 收尾工作，传输过程完全由 DMA 控制器控制，大幅减少 CPU 占用；再比如实现 I/O 通道技术， 引入专门的 I/O 处理器（通道）来管理 I/O 操作，CPU 只需发出 I/O 指令，具体的设备控制、数据传输都由通道完成，相当于把 I/O 的工作从 CPU "卸载" 出去，实现 CPU 和 I/O 设备的高度并行
最后，比如实现磁盘调度算法，针对磁盘这类块设备，通过优化请求顺序减少磁头移动时间，提升设备吞吐量，同时也减少 CPU 的等待时间

功能四：能够对 I/O 设备进行控制

对 I/O 设备进行控制是设备驱动程序（属于 I/O 软件）的功能之一。目前对 I/O 设备有 4 种控制方式：① 轮询的可编程 I/O 方式（即查询方式）；② 中断的可编程 I/O 方式；③ 直接存储器访问(direct memory access, DMA)方式；④ I/O通道方式
应采用何种控制方式，与 I/O 设备的传输速率、传输的数据单位等因素有关。例如针对打印机、键盘等低速设备，由于它们传输数据的基本单位是字节 (或字)，故应采用中断的可编程 I/O 方式；而针对磁盘、光盘等高速设备，由于它们传输数据的基本单位是数据块，故应采用 DMA 方式，以提高系统的利用率。此外，I/O 通道方式的引入，使得对 I/O 操作的组织和数据的传输，都能独立进行而无需 CPU 的干预。为了给上层软件和用户提供方便，显然 I/O 软件也应屏蔽掉这种差异，向上层软件和用户提供统一的操作接口

功能五：能够确保对设备的正确共享

根据设备的共享属性，可将系统中的设备分为两类
① 独占设备，进程应互斥地访问此类设备，即系统一旦把此类设备分配给某进程后，便由该进程独占，直至用完释放。典型的独占设备有打印机、磁带机等。系统在对独占设备进行分配时，还应考虑分配的安全性
② 共享设备，是指在一段时间内允许多个进程同时访问的设备。典型的共享设备是磁盘，当有多个进程对磁盘执行读/写操作时，操作可以交叉进行而不会影响到读/写的正确性

功能六：能够处理错误

大多数的设备都包括了较多的机械和电气部分，运行时容易出现错误和故障
从处理的角度看，可以将错误分为临时性错误和持久性错误。对于临时性错误，可通过重试操作来纠正它；只有在发生了持久性错误时，才需要向上层报告。例如，在磁盘传输数据过程中发生错误，系统并不认为磁盘已发生了故障，而是可以重新传输，一直重传多次后仍然有错，才会认为磁盘发生了故障
由于多数错误是与设备紧密相关的，因此对于错误的处理，应该尽可能地在接近硬件的层面上进行，即低层软件能够解决的错误就不向上层报告，因此高层也就不能感知。只有低层软件解决不了的错误才向上层报告，请求上层软件解决
