目录是一个特殊的文件，在传统的文件系统中，目录的内容就是 FCB 的数组（有序集合），每一条记录（目录项）就是一个完整的 FCB，所以：文件目录项 = 文件控制块，这个说法在传统模型里是成立的，因为现代文件系统（比如 Linux 的 ext 系列、UNIX 文件系统）引入了索引节点（inode），把「文件名」和「文件元数据」分离开：
  • 磁盘上的目录项：现在只包含「文件名 + inode 号」这两个字段，不再包含完整的 FCB 信息
  • 文件的元数据：全部存放在 inode 中，一个文件对应一个 inode（相当于现代版的 FCB）


这个时候，目录项不再是完整的 FCB，只是一个 “文件名到 inode 号” 的映射，所以说，严格意义上来讲【文件控制块就是文件目录项】是错误的，即 I 错误


II 错误，文件控制块是在文件创建时就建立并存储在磁盘上的，open 系统调用只是将其读入内存，并在内存中建立对应的打开文件表项，而非新建 FCB 本身


III 错误，文件和 FCB 是一一对应的，一个文件只有一个 FCB


IV 正确。FCB 的核心组成就是这三类信息：

  • 基本信息：文件名、文件大小、物理位置等

  • 存取控制信息：文件权限、所有者等

  • 使用信息：创建时间、修改时间、访问计数等



文件系统中打开 (open) 系统调用的主要操作是 ( )

A.把文件元数据 (FCB 或 inode) 从辅存读到内存
B.把磁盘文件系统的控制管理信息从辅存读到内存
C.把文件的 FAT 表信息从辅存读到内存
D.把文件从辅存读到内存

A 正确：open 系统调用的核心操作，就是把文件的元数据（FCB 或 inode）从磁盘（辅存）读到内存中，为后续的读写操作做准备。这些元数据包含了文件的大小、权限、数据块位置等关键信息，是操作系统管理文件的基础


B 错误：磁盘文件系统的控制管理信息（如超级块、空闲块位图等）是在文件系统挂载时就已经读入内存的，不是每次调用 open 时才读取的


C 错误：FAT 表（文件分配表）通常是在文件系统挂载时一次性读入内存的，不是为单个文件open操作读取的


D 错误：open 系统调用不会把整个文件从磁盘读到内存。它只是打开文件、建立文件描述符；真正读取文件内容是由 read 系统调用完成的，read 会根据 open 建立的文件描述符来读这个文件盘块数据

文件已被打开后，对文件的访问采用 ( )

A.文件符号名
B.从根目录开始的路径名
C.从当前目录开始的路径名
D.文件描述符

当文件被 open() 系统调用成功打开后，操作系统会为进程返回一个文件描述符（File Descriptor, fd）。后续所有对该文件的读写操作（如 read()、write()、lseek()）都需要通过这个文件描述符来进行，本题选 D


文件描述符是一个进程内唯一的整数，它直接关联到进程的打开文件表项（其实就是进程打开文件表的下标），通过它可以快速找到文件的状态信息、读写指针和内存 inode，效率远高于每次都解析路径


文件符号名、绝对路径名、相对路径名，都只是在打开文件时用来定位文件的方式，一旦文件被成功打开，后续访问就不再需要这些路径信息了

当用户请求操作系统删除一个当前未被任何进程打开的文件时，操作系统会执行一系列操作来完成此任务。下列操作中，哪一项是操作系统在执行文件删除过程中不会执行的是 ( )

A.释放该文件内容所占用的全部磁盘块
B.清除该文件在其父目录中的目录项
C.回收该文件对应的文件控制块 (FCB) 或索引节点 (inode) 所占用的空间
D.格式化该文件曾经占用的磁盘扇区以清除数据

A 正确：操作系统会释放文件占用的所有磁盘块，将这些块标记为空闲，供后续文件使用


B 正确：文件的父目录中会清除该文件对应的目录项（文件名 + inode 号的映射），这样用户就无法再通过路径访问到该文件了


C 正确：文件对应的 FCB 或 inode 会被回收，它占用的空间会被标记为空闲，可以被新文件复用


D 错误：删除文件时，操作系统不会格式化磁盘扇区或主动清除数据内容。它只是修改文件系统的元数据（目录项、inode、空闲块位图等），标记这些扇区为 “空闲”。只有当新数据写入这些扇区时，原文件占用扇区的数据才会被覆盖


操作系统一般不会立即去物理地擦除或格式化这些磁盘扇区中的数据内容。这样做开销很大，会显著降低删除操作的效率。数据的物理清除通常需要专门的安全删除工具或在后续磁盘块被重新分配给新文件并写入新数据时才会被覆盖

下列关于 remove() 系统调用的说法中，错误的是 ( )

A.根据指定路径找到 inode 后，查看其存取控制信息看删除操作是否允许，若非法则删除失败
B.若允许删除文件，查看 inode 里的访问计数，若大于 1，则该计数值 -1；若等于 1，则释放该文件所占用磁盘块后释放该 inode 所占空间
C.若该文件系统采用位示图管理空闲空间，则释放该文件所占用磁盘块只需要将对应的 bit 值设为 0 即可
D.删除该文件所在目录中对应的目录项
A 正确：remove() 在执行删除前，会先检查文件的权限信息（存取控制信息），判断调用者是否有删除权限。如果权限不足，删除操作会直接失败

B 错误：inode 中记录的是硬链接计数（或者称为引用计数，而非 “访问计数”）。当删除一个文件时：
  1. 先将硬链接计数减 1；
  2. 若减 1 后计数变为 0，才会释放文件占用的磁盘块和 inode 空间；
  3. 若计数仍大于 0，说明还有其他硬链接指向该文件，此时只会删除当前目录项，不会释放磁盘块和 inode

C 正确：位示图管理空闲空间时，每个磁盘块对应一位，1 表示已占用，0 表示空闲。释放磁盘块时，只需将对应的位设为 0 即可

D 正确：remove() 系统调用会删除文件所在目录中对应的目录项（文件名与 inode 的映射）

remove() 系统调用的完整执行流程：

  1. 解析路径，找到文件对应的目录项和 inode；

  2. 检查调用者是否有删除权限；

  3. 删除该文件对应的目录项；

  4. 将 inode 的硬链接计数减 1；

  5. 若链接计数变为 0：释放文件占用的磁盘块，并回收 inode 空间


下列关于索引节点的叙述中，错误的是 ( ) 

A.每个文件都对应一个唯一的索引节点，其中包含了文件的所有者、访问权限、时间戳以及指向文件数据块的指针等信息
B.引入索引节点后，文件目录项中通常只包含文件名和该文件对应的索引节点号，而不包含文件的其他元数据
C.当一个文件被多个硬链接指向时，系统会为每个硬链接创建一个独立的索引节点，但这些索引节点会指向相同的物理数据块
D.索引节点本身存储在磁盘上，当文件被访问时，其对应的索引节点会被加载到内存中以便快速存取

A 正确，每个文件对应一个唯一的索引节点（inode），inode 中存储了文件的元数据，包括所有者、访问权限、时间戳、文件大小，以及指向数据块的指针等信息


B 正确，引入 inode 后，文件目录项不再存储完整的元数据，只包含文件名和对应的 inode 号，元数据统一存储在 inode 中。这种设计实现了文件名与元数据的分离，也为文件共享提供了支持


C 错误，硬链接的本质是多个目录项指向同一个 inode，而不是为每个硬链接创建独立的 inode。多个硬链接共享同一个 inode，因此也共享同一份元数据和物理数据块。系统会在 inode 中维护一个硬链接计数，记录指向它的目录项数量


D 正确，inode 本身存储在磁盘上，当文件被访问时，操作系统会将对应的 inode 加载到内存中，后续读写操作就可以直接通过内存中的 inode 快速定位数据块，无需反复读取磁盘，减少磁盘 I/O 次数

下列文件信息中并未包含在文件对应的磁盘索引节点中的是 ( )

A.文件的链接计数
B.文件在磁盘中的物理位置
C.文件的读写指针
D.文件的访问权限
A 正确：文件的链接计数（硬链接数）是 inode 的重要组成部分，记录了有多少个目录项指向这个 inode

B 正确：件在磁盘中的物理位置由 inode 中的数据块指针（直接 / 间接指针）记录，是定位文件数据的关键信息

C 错误：文件的读写指针（文件偏移量）是进程打开文件时维护的动态状态信息，保存在进程的用户级打开文件表中，不属于磁盘上的 inode。多个进程打开同一个文件时，会有各自独立的读写指针

D 正确：文件的访问权限（rwx 权限位、所有者、所属组）是 inode 中存储的元数据之一，决定了用户对文件的访问控制

下面不属于文件索引节点 (inode) 的特征的是 ( )

A.维护了对应文件的逻辑结构
B.可以被目录系统中的多个文件共享使用
C.在磁盘中保存和在内存中使用时具有不同的属性
D.保存了部分与文件权限相关的信息
A 错误：文件的逻辑结构是用户视角下的文件结构，与操作系统的组织与保存无关，只与文件提供者有关，因此不可能在inode中有所体现，本题选 A

B 正确：inode 可以被多个硬链接共享，多个目录项可以指向同一个 inode，这正是硬链接的工作原理


C 正确：磁盘上的 inode 和内存中的 inode 属性不同：

  • 磁盘 inode：存储文件的静态元数据（权限、大小、链接数、数据块指针等）

  • 内存 inode：除了复制磁盘 inode 的内容，还会增加访问计数、锁状态、链表指针等动态管理信息


D 正确：inode 中明确保存了文件的访问权限信息（如 rwx 权限位、所有者、所属组等），这是文件权限控制的基础

各进程读取打开文件的起始位置被记录在 ( )

A.外存索引节点中
B.系统级打开文件表中
C.用户级打开文件表中
D.文件对应的目录项中

A 错误：外存索引节点（磁盘 inode）存储的是文件的静态元数据，如权限、大小、数据块指针等，不记录进程的读写位置


B 错误：系统级打开文件表（文件表）是系统全局维护的，记录文件的状态信息（如引用计数、文件指针等），它的文件指针是被多个进程共享的，不会记录每个进程独立的读取起始位置


C 正确：用户级打开文件表（进程打开文件表）是每个进程私有的，表中的每个表项包含文件描述符和指向系统级文件表的指针，而每个进程独立的读写指针（读取起始位置）正是记录在这里的


D 错误：文件对应的目录项只包含文件名和 inode 号，不存储任何读写位置信息

当文件被打开时，需要将磁盘索引节点拷贝到内存的索引节点，下列属于内存索引节点中有而磁盘索引节点中没有的内容是 ( ) 

A.访问计数值
B.文件物理地址
C.文件长度
D.文件类型

访问计数值表示的意义是，每当有一个进程要访问此索引节点，访问计数值加 1，访问结束时减 1，它属于内存索引节点中特有的内容


磁盘索引节点：是指存放在磁盘上的索引节点。每个文件有一个唯一的磁盘索引节点，主要包括以下内容：

  • 文件主标识符，拥有该文件的个人或小组的标识符

  • 文件类型，包括普通文件、目录文件或特别文件

  • 文件存取权限，各类用户对该文件的存取权限

  • 文件物理地址，采用索引分配时，每个索引节点中含有 13 个地址项，即 iaddr(0)~iaddr(12)，它们以直接或间接方式给出数据文件所在盘块的编号

  • 文件长度，指以字节为单位的文件长度

  • 文件链接计数，在本文件系统中所有指向该文件的文件名的指针计数

  • 文件存取时间，本文件最近被进程存取、修改的时间及索引节点最近被修改的时间。

内存索引节点：是指存放在内存中的索引节点。当文件被打开时，要将磁盘索引节点复制到内存的索引节点中，便于以后使用。在内存索引节点中增加了以下内容：

  • 索引节点号，用于标识内存索引节点

  • 状态，指示 inode 是否上锁或被修改

  • 访问计数，每当有一进程要访问此 inode 时，计数加 1，访问结束减 1，其实就是系统级打开文件表中的引用计数

  • 逻辑设备号，文件所属文件系统的逻辑设备号，其实就是文件所在磁盘分区的设备文件名

  • 链接指针，我们知道内存中的 inode 都是放在系统级打开文件表中的，而系统级打开文件表实际上就是一个哈希表，可以快速根据 inode 编号找到对应的内存 inode，因此，每个内存 inode 里的这个链接指针，就是用来把自己挂到哈希表对应桶位的链表上的

I.错误。read 系统调用需要的参数是 read(int fd, void *buf, size_t count)，必须打开文件获得 fd 后才能对文件执行读写和关闭操作，因此不需要文件名，需要的是文件描述符；读写指针位于进程打开文件表中，除了文件描述符 fd 和期待读取的字节数（count）以外，还需要指定读入用户空间缓冲区的指针 buf

II 正确。假设进程 P1 执行 read() 系统调用，由于该文件的数据不在内存，因此需要通过磁盘 I/O，一般使用 DMA 传输磁盘数据到内存，P1 执行磁盘驱动程序在对 DMA 控制器设置完传送参数后，便会主动阻塞自己，随后调度程序根据调度策略选择执行另一个进程 P2，进程 P2 执行的过程中， DMA 正在将指定读写区域数据所在磁盘块依次读入内核缓冲区（也就是文件的内核缓冲区），DMA 传输数据完成后，DMA 控制器便会发出 DMA 结束中断请求，CPU 响应该中断请求之后，在该中断服务程序中唤醒进程 P1，如果进程 P1 优先级比当前进程优先级高且为抢占式调度，那么在中断返回过程中，便会触发调度让进程 P1 上处理机执行

III 错误，read() 不会直接从磁盘读到用户空间，而是先读到内核缓冲区（其实就是页缓存（page cache）），再根据读写指针和读写字节数将所需数据从内核缓冲区复制到用户空间的缓冲区 buf 中。这是为了利用缓存机制，减少磁盘 I/O 次数

IV 错误，磁盘 I/O 是以块（扇区 / 簇）为单位进行的，即使只读取文件的一部分，也需要读取整个磁盘块到缓存中，可能会读入后续无关的数据（预读机制也会提前读取附近的块）

V 错误，read() 会读取能读到的所有数据，并返回实际读取的字节数（小于请求的字节数），而不是返回 -1。只有发生错误时（如权限不足、文件不存在）才会返回 -1

因此，只有 II 是正确的，本题选 C

D.若文件内容在内存缓冲区中被修改过但尚未写回磁盘，则执行 "写回(flush)" 操作
A 会执行：close() 会移除进程 P 的用户打开文件表中与文件 F 关联的表项，释放文件描述符

B 会执行：因为只有进程 P 打开了文件 F，关闭后内存 inode 的访问计数变为 0，系统会将其从内存中移除（即将内存中的 inode 写到磁盘的 inode 中，然后释放内存中的 inode）

C 不会执行：close() 操作不会清零磁盘上的数据块内容。它只会修改内存中的元数据（如打开文件表、inode 访问计数），不会擦除磁盘上的实际数据。清零数据块是删除文件时才会涉及的操作，而且即使删除文件，也不会主动清零数据，只是标记为空闲，本题选 C

D 会执行：如果文件内容在内核缓存（页面缓存）中被修改但尚未写回磁盘，close() 会触发 flush 操作，将脏数据写回磁盘，确保数据持久化

若多个进程共享同一个文件 F，则下列叙述错误的是 ( )

A.各进程可以用 “读” 或 “写” 方式打开文件 F
B.在系统打开文件表中有多个表项包含 F 的属性，每个表项对应一个打开文件的进程
C.各进程的用户打开文件表中关于 F 的表项内容可能不同
D.进程关闭 F 时，系统删除相应的用户打开文件表项，若此时无其他进程打开 F，则系统删除 F 在系统打开文件表中的表项

A 正确：多个进程可以以读、写等不同模式打开同一个文件，只要文件权限和系统的文件共享机制允许即可


B 错误：系统打开文件表（全局文件表）中，同一个文件只会对应一个表项，而不是每个进程一个表项，所有打开该文件的进程，其用户打开文件表项都会指向这同一个系统表项，本题选 B


C 正确：每个进程的用户打开文件表项是独立的，包含各自的文件描述符、访问模式、读写指针、指向系统表项的指针，因此表项内容可能不同


D 正确：进程关闭文件时，会删除自身的用户打开文件表项；当系统打开文件表项的引用计数变为 0（即没有其他进程打开该文件）时，系统会删除该表项

关闭文件操作的主要工作是 ( )。

A.将文件的最新信息从内存写回磁盘
B.将文件当前的控制信息从内存写回磁盘
C.将位示图从内存写回磁盘
D.将超级块当前的信息从内存写回磁盘

关闭文件操作的核心工作，是把文件在内存中的控制信息（如 inode、文件状态、修改时间等元数据）写回磁盘，确保文件系统记录与磁盘数据一致，同时释放内存中的文件 inode 占用的内存资源


A 错误：文件数据的写回通常由系统的缓冲机制异步完成，或通过flush操作主动触发，不是关闭文件的主要工作，关闭文件时也会将文件数据写回到磁盘，但这个不是文件关闭的主要作用


B 正确：关闭文件时，系统会将文件的控制信息（元数据）写回磁盘，并释放文件描述符 / 打开文件表项


C 错误：位示图是磁盘空闲块的管理结构，与单个文件的关闭操作无关


D 错误：超级块是文件系统的全局信息，不会因单个文件的关闭而写回

若多个进程共享同一个文件 F，进程 P1 使用 close() 系统调用关闭文件 F，则下列叙述中，正确的是 ( )

A.根据文件描述符 fd 找到系统打开文件表中对应表项并删除
B.根据文件描述符 fd 找到进程 P1 的进程打开文件表中对应表项并删除
C.释放内存中该文件的 inode
D.把超级块的当前信息从内存写回磁盘
A 错误：多个进程共享同一个文件 F 时，系统打开文件表中只会存在一个对应 F 的表项，不会因为 P1 关闭文件就删除它，只有当所有进程都关闭文件时才会删除系统表项，而且也不是根据 fd 去系统级打开文件表中查找，而是根据 inode 号去系统级打开文件表中查找对应的表项

B 正确：close() 首先根据文件描述符 fd，找到进程 P1 私有的用户打开文件表中的对应表项并删除 / 标记为无效，释放该进程的文件描述符资源

C 错误：内存中的 inode 只有在所有进程都关闭文件 F（系统打开文件表的引用计数变为 0）时，才会被释放。仅 P1 关闭文件，不会触发 inode 的释放

D 错误：close() 不会主动写回超级块信息到磁盘。超级块的更新通常由文件系统挂载 / 卸载操作或特定的同步系统调用（如 sync()）触发，与单个进程的 close() 无关

【14-29】在一个文件被用户进程首次打开的过程中，操作系统需要做的是（ ）

【24-29】下列系统调用的实现中，包含文件按名查找功能的是 ( )。

A.open()
B.read()
C.write()
D.close()
以 open("/fs/a.txt") 为例来复习下系统调用 open 的执行流程：
  1. 根据根目录的 inode 号 2 去整个系统的打开文件表中找到根目录对应的 inode
  2. 然后根据 inode 中的盘块号，找到根目录的所有目录项的数据（一般缓存在目录项缓存中），在根目录中按照文件名查找目录 fs 对应的 inode 号
  3. 根据目录 fs 对应的 inode 号去整个系统的打开文件表中找到对应的 inode
  4. 然后根据 inode 中的盘块号，找到 fs 目录的所有目录项的数据（如果不在目录项缓存，就去磁盘加载到目录项缓存），然后按照文件名查找文件 a.txt 对应的 inode 号
  5. 根据 a.txt 的 inode 号去整个系统的打开文件表中找到对应的 inode，如果找不到的话，则根据 inode 号去磁盘加载到内存
  6. 给 a.txt 文件分配一个数据缓冲区，用于读写数据

  7. 将 a.txt 文件对应的 inode 维护到整个系统的打开文件表中

  8. 在进程的打开文件中分配一个空闲的 fd，这个 fd 所在的元素中的指针指向在整个系统的打开文件表中的 a.txt 对应的表项

  9. 将文件描述符 fd 返回给应用程序


这样文件打开完成，可以看到，上面从第 1 步到第 5 步就是根据文件名 a.txt 去文件系统中查找对应的文件，所以 open 系统调用包含了文件按名查找功能，本题选 A


接下来的 read、write 和 close 系统调用，都是直接根据 fd 来操作文件的，不包含文件按名查找功能
