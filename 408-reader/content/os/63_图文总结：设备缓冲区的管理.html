基本所有的 I/O 设备都会有自己的内核缓冲区，那么 I/O 系统的独立性软件就需要考虑如何高效的管理这些缓冲区，缓冲区管理的主要功能是组织好这些缓冲区，并提供获得和释放缓冲区的手段，可以这么说，这些缓冲区都是 I/O 设备的驱动程序在用，但是这些缓冲区是由独立性软件来管理的
根据 I/O 设备和 CPU 之间缓冲区的数量，可以将缓冲区分为单缓冲区、双缓冲区、环形缓冲区等

单缓冲区

在单缓冲区情况下，每当用户进程发出一个 I/O 请求时，OS 便会在内存中为之分配一缓冲区，如下图所示
在块设备输入时，假定从 I/O 设备把一块数据输入内核缓冲区的时间为 T，OS 将该内核缓冲区中的数据传送到工作缓冲区（即工作区）的时间为 M，而 CPU 对这一块数据进行处理（计算）的时间为 C，其中 T 和 C 是可以并行的，因为将 I/O 设备（比如磁盘）中的块数据传输到内核缓冲区一般是由 DMA 完成的，而将内核缓冲区的数据拷贝到工作缓冲区是由 CPU 完成，DMA 和 CPU 完全可以并行运行，看下图：
看上图（a），当 T > C 时，系统对每块数据的处理时间为 T + M（除了最后一块，最后一块需要的时间是 T + M + C），上面处理 3 块需要的时间 (T + M) * 3 + C
再看上图（b），当 T < C 时，系统对每块数据的处理时间为 M + C（除了第一块，第一块需要的时间是 T + M + C），上面处理 3 个数据块时间：(M + C) * 3 + T
在采用单缓冲区的情况下，如果题目问你处理一个数据块的平均时间，那么你可以回答是 max(T, C) + M
如果题目问你的是连续处理 n 块数据的总时间，那么你需要区分：
  • 如果 T > C，那么总时间是 n * (T + M) + C
  • 如果 T < C，那么总时间是 T + n * (M + C)
在字符设备输入数据时，缓冲区用于暂存用户输入的一行数据，在输入期间，用户进程被挂起以等待数据输入完毕；在输出时，用户进程将一行数据输入缓冲区后，继续进行处理。当用户进程已有第二行数据输出时，如果第一行数据尚未被提取完毕，则此时用户进程应阻塞
由于缓冲区是共享资源，生产者与消费者在使用缓冲区时必须互斥。如果消费者尚未取走缓冲区中的数据，则即使生产者又生产出新的数据，也无法将它送入缓冲区，此时生产者需要等待。如果为生产者与消费者设置了两个缓冲区，便能解决这一问题

双缓冲区

为了加快输入和输出速度，提高设备利用率，人们又引入了双缓冲区机制，也称为缓冲对换。在设备输入数据时，先将数据送入第一缓冲区，装满后便转向第二缓冲区。此时 OS 可以从第一缓冲区中移出数据，并送入用户进程（看下图），接着由 CPU 对数据进行计算
在块设备输入时，假定从 I/O 设备把一块数据输入内核缓冲区的时间为 T，OS 将该内核缓冲区中的数据传送到工作缓冲区（即工作区）的时间为 M，而 CPU 对这一块数据进行处理（计算）的时间为 C，因为 T 是 DMA 花费的时间，而 M + C 都是 CPU 花费的时间，所以 T 和 M + C 是可以并行的
看上图（a），首先 DMA 传输第一个块到缓存区 1 花费了时间 T，然后 CPU 花费 M 的时间将缓冲区 1 的数据块拷贝到工作区，并且对数据块进行计算花费时间 C，在 CPU 工作期间（M + C），DMA 可以并行将第二个块从 I/O 设备传输到缓存区 2，因为 T > M + C，所以在 CPU 处理完第一个数据块时，DMA 还没有传输完第二个数据块；当 DMA 传输完第二个数据块，接下来 CPU 就可以搬运和处理第二个数据块（M + C），而 DMA 同时并行的将第三个数据块传输到缓存区 1；当 DMA 传输完第三个数据块，接下来，CPU 就可以搬运和处理第三个数据块（M + C），如果没有第四个数据块的话，就此结束，此时，系统处理 3 个数据块的总时间 = 3 * T + (M + C)，这种情况下，可使块设备连续输入数据块
看上图（b），因为 T < M + C，所以，系统处理 3 个数据块的总时间 = T + 3 * (M + C)，这种情况下，可使 CPU 不必等待设备输入
在采用双缓冲区的情况下，如果题目问你处理一个数据块的平均时间，那么你可以回答是 max(T, M + C)
如果题目问你的是连续处理 n 块数据的总时间，那么你需要区分：
  • 如果 T > M + C，那么总时间是 n * T + (M + C)
  • 如果 T < M + C，那么总时间是 T + n * (M + C)

对于字符设备，在行输入方式下，若采用双缓冲区，则通常能消除用户的等待时间，即用户在输入完第一行数据后，在 CPU 执行第一行中的命令时，用户可以继续向第二缓冲区输入下一行数据
当两台主机使用网络通信时，如果只设置单缓冲区的话，那么，它们之间，在任意时刻，只能实现单方向的数据传输
比如上图左边，只允许从 A 发送数据到 B，因为 B 只有 1 个缓冲区，此时收到了 A 发送过来的数据，放在 B 的缓冲区，那么就不能将 B 要发送的数据放到缓冲区，所以此时，B 不能给 A 发送数据
要实现同时双向传输的话，那么必须两台机器都要配置双缓冲区，分别是发送缓冲区和接收缓冲区（看上图右边），这样，就可以实现同时双向传输

环形缓冲区

当输入与输出的速度基本匹配时，采用双缓冲区能获得较好的效果，可使生产者和消费者基本上实现并行操作。但若两者的速度相差甚远，则双缓冲区的效果不会太理想，不过可以随着缓冲区数量的增加而使情况有所改善。因此，又引入了多缓冲区机制，可将多个缓冲区组成环形缓冲区的形式，来看下环形缓冲区的组成

首先，在环形缓冲区中包含多个缓冲区，各缓冲区的大小相同（看下图）。作为输入的多缓冲区可分为 3 种类型：用于装输入数据的空缓冲区 R、已装满数据的缓冲区 G、计算进程正在使用的现行工作缓冲区 C
在环形缓冲区中还包含多个指针，作为输入的缓冲区可设置 3 个指针（看上图）：用于指示计算进程下次可用缓冲区 G 的指针 Nextg，用于指示输入进程下次可用空缓冲区 R 的指针 Nexti，以及用于指示计算进程正在使用的缓冲区 C 的指针 Current。计算进程和输入进程可利用下面两个过程来使用环形缓冲区：
① 获取缓冲 GetBuf 过程：当计算进程要使用缓冲区中的数据时，可调用 Getbuf 过程。该过程将由指针 Nextg所指示的缓冲区提供给进程使用，相应地，须把它改为现行工作缓冲区，并令 Current 指针指向该缓冲区的第一个单元，同时将 Nextg 移向下一个可用缓冲区 G。类似地，每当输入进程要使用空缓冲区来装入数据时，也调用 Getbuf 过程，由该过程将指针 Nexti 所指示的缓冲区提供给输入进程使用，同时将 Nexti 指针移向下一个空缓冲区 R
② 释放缓冲 Releasebuf 过程：当计算进程把 C 缓冲区中的数据提取完毕时，便调用 Releasebuf 过程，将缓冲区 C 释放。此时，把该缓冲区由当前（现行）工作缓冲区 C 改为空缓冲区 R。类似地，当输入进程把缓冲区装满时，也应调用 Releasebuf 过程，将该缓冲区释放，并将其改为可用缓冲区 G
设备独立性软件中的缓冲区管理，必须要考虑进程间的同步问题。使用输入循环缓冲，可使输入进程和计算进程并行执行。相应地，指针 Nexti 和指针 Nextg 将不断地沿着顺时针方向移动，这样就可能出现下述两种情况：
① Nexti 指针追赶上 Nextg 指针。这意味着输入进程输入数据的速度大于计算进程处理数据的速度，已把全部可用的空缓冲区装满，再无缓冲区可用。此时，输入进程应阻塞，直到计算进程把某个缓冲区中的数据全部提取完，使之成为空缓冲区 R，并调用 Releasebuf 过程将它释放后，才可将输入进程唤醒。这种情况被称为 "系统受计算限制"
② Nextg 指针追赶上 Nexti 指针。这意味着输入数据的速度小于计算进程处理数据的速度，使装有输入数据的缓冲区都被抽空，再无装有数据的缓冲区供计算进程提取数据。这时，计算进程只能阻塞，直至输入进程又装满某个缓冲区，并调用 Releasebuf 过程将它释放后，才可将计算进程唤醒。这种情况被称为 "系统受 I/O 限制"
