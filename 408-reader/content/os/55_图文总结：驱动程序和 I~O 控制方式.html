我们在计组第 7 章有详细讲解 I/O 设备的 3 种控制方式，分别是程序查询控制，中断控制方式，以及 DMA 控制方式，实际上，还有一种方式就是通道控制，这些 I/O 控制方式的实现是离不开设备驱动程序，我们一一来看

程序查询控制

假设现在应用程序 A 需要打印 a、b、c 这 3 个字母（看下图），通过系统调用陷入内核，系统调用服务程序首先通过 copy_from_user 函数将应用程序缓冲区 buffer 中需要打印的数据，拷贝到内核的缓冲区 p 中，然后再系统调用服务程序中调用字符设备接口，将打印数据的命令传递给字符设备管理，字符设备管理找到打印机的驱动程序后，就将打印数据的命令传递给打印机驱动程序
此时主机采用程序查询的方式来控制打印机设备，那么在打印机驱动程序中有一段代码（看上图右下角的伪代码），它的作用就是控制打印机设备来打印 3 个字母，遍历每个字母，对于每个要打印的字母：
  • ① 首先，拿到打印机控制器中的状态寄存器中的状态，判断是否是就绪状态，如果不是的话，就继续轮训查询状态，一直到打印机就绪状态为止
  • ② 然后，将当前字母，发送到打印机控制器的数据寄存器中
  • ③ 最后，发送打印命令到命令寄存器中，打印字母，这个时候的将打印机设置为忙碌状态
这种就是程序查询控制 I/O 设备，在设备驱动程序中不断的轮询设备的状态，如果设备状态是忙碌的，那么 CPU 等待，否则，就启动设备执行设备操作

中断控制方式

继续以打印机为例，同样是应用程序 A 让打印机打印 a、b、c 这 3 个字符，陷入到内核态，然后将这 3 个字符拷贝到内核的缓冲区 p 中，接下来打印 I/O 请求经过 I/O 系统接口，再经过设备无关性软件，到达打印机驱动程序
在打印机驱动程序中包含上图左边的这样一段伪代码，其功能是：
  • ① 首先是开中断，保证 CPU 可以响应中断
  • ② 然后轮询查看打印机控制器的状态寄存器，如果状态不是就绪 ready，就一直轮询
  • ③ 如果状态是就绪的话，就将第 1 个字符发送到打印机控制器的数据寄存器中
  • ④ 发送打印命令到命令寄存器，启动打印机开始打印第一个字符
  • ⑤ 在打印第一个字符的同时，当前的进程执行 scheduler()，阻塞在这里，不往下执行了，这个 scheduler 就是内核中进程调度的程序，它会调度其他程序使用 CPU 来执行
当第一个字符打印完了，打印机控制器给 CPU 发送中断信号，然后去执行打印机中断服务程序，而在打印机中断服务程序中，有上图右下角这么一段打印机中断处理程序，其功能是：
  • ① 首先判断 count 是否等于 0，如果等于 0，说明没有需要打印的数据，那么通过 unblock_user() 唤醒阻塞的当前进程，继续执行当前进程
  • ② 如果 count 不等于 0，则继续将下一个字符送到打印机数据寄存器，然后发送打印命令，打印下一个字符，然后 count--，i++，表示正在打印一个数据
  • 接下来，通过 acknowledge_interrupt() 来通知打印机控制器，说当前中断处理完了，允许系统继续处理后续中断
  • 最后从中断返回，执行完中断处理程序
所以说，在中断控制方式的时候，当前运行的程序或者说进程，有可能会在驱动程序这边阻塞，执行完了后，再将结果告诉应用程序，这样就使用中断控制方式，完成了一次 I/O 请求。看下图是单重中断的流程

DMA 控制方式

我们以磁盘为例，为了支持 DMA，除了有磁盘控制器之外，还需要 DMA 控制器，这两者可以集成在一起，也可以分开，我们这里假设是集成在一起的（看下图），在磁盘控制器和 DMA 控制器中都会有一些寄存器，也就是 I/O 端口，磁盘驱动程序和磁盘中断服务程序，就是通过这些寄存器来和 DMA 控制器或者磁盘控制器交互的
在磁盘控制器中，有命令寄存器、磁头号寄存器、磁道号寄存器、起始扇区号寄存器、扇区数寄存器、状态寄存器、数据缓冲寄存器，每个寄存器都有自己的地址；在 DMA 控制器中，有内存数据地址寄存器、磁盘控制器数据缓冲寄存器地址，就是指向磁盘控制器中的这个数据缓冲寄存器，数据都是传输到这个数据缓冲器中；在 DMA 控制器中，还有传输总字节数寄存器、传输方向寄存器，这些寄存器也是 I/O 端口，都会有自己的端口地址（注意哈，这些我们都不用去记忆，有个大概得印象即可）
假设现在应用程序 A，需要将 1KB 的数据块写到磁盘中，应用程序 A 发起磁盘写的 I/O 请求（看下图），陷入内核，执行系统调用程序的时候，将用户态的数据拷贝到内核缓冲区 p 中，如果是写文件的话，就需要调用文件系统相关的功能，找到文件的 inode，然后计算数据需要写到磁盘中盘块的盘块号；接下来文件系统调用块设备的 I/O 系统的接口，请求来到设备无关性软件，这里会将盘块号转换为逻辑扇区号，并且找到对应的磁盘设备，将 I/O 请求转发给对应的磁盘驱动程序
上图的 2 段伪代码都是磁盘驱动程序中的，在磁盘驱动程序中，首先，将磁盘控制器需要的数据计算出来，就是根据逻辑扇区号，计算出磁头号、磁道号、其实扇区号等数据，然后发送给磁盘控制器相应的寄存器中，执行磁盘驱动程序会做下面的 4 件事情：
  • ① 将写命令发送到磁盘控制器的命令寄存器，还有磁头号、磁道号、起始扇区号、以及写入扇区数量等送到对应的寄存器中
  • ② 接下来，等待磁盘控制器的状态为就绪为止，此时磁盘控制器控制磁盘完成相应的操作（主要完成扇区定位，即寻道）
  • ③ 设置 DMA 控制器，就是磁盘驱动程序将 DMA 控制器需要的数据，发送到对应的寄存器中，比如，要传输的数据在内存中的起始地址，然后指定数据要传输到磁盘控制器的数据寄存器，然后是要传输的总字节数，然后再设置传输方向，这里是从内存传输数据到磁盘设备
  • ④ 最后启动 DMA 传输，然后当前进程，需要在这里阻塞，不往下执行了，内核会调度其他的进程来使用 CPU，也就是说，DMA 控制器在传输数据的同时，CPU 在执行其他进程的指令，使得 I/O 和 CPU 并行执行
当数据传输完成后，DMA 控制器会向 CPU 发送 DMA 结束中断信号，然后 CPU 去执行 DMA 结束中断服务程序
在 DMA 结束中断服务程序中（上图右下角的 3 行伪代码），就是唤醒因为执行磁盘 I/O 的而被阻塞的这个进程，然后告诉 DMA 控制器，说当前中断处理完了，然后从中断返回后，CPU 可能就可以执行应用程序 A 剩下的程序了，将磁盘 I/O 的结果告诉应用程序 A
虽然 DMA 方式比起中断方式来已经显著地减少了 CPU 的干预，中断方式以字 (节) 为单位的进行干预，而 DMA 减少到以数据块为单位的进行干预，不过，在 DMA 控制 I/O 方式中，CPU 每发出一条 I/O 指令，也只能去读 (或写) 一个连续的数据块，而当我们需要一次去读多个数据块且将它们分别传送到不同的内存区域，或者相反时，则须由 CPU 分别发出多条 I/O 指令及进行多次中断处理才能完成，比如，现在要将内存中 3 个不连续的数据块，通过 DMA 写入到磁盘，需要 3 次 DMA 传输，也就是说要设置 3 次 DMA 和磁盘控制器的参数，然后还需要 3 次 DMA 结束中断处理，而接下来我们要讲的 I/O 通道控制，则可以在这种情况下，进一步减少 CPU 的干预

通道控制

看下图，现在 CPU 通过存储器总线和内存相连，然后再通过通道和 I/O 总线相连，在 I/O 总线上挂了很多的 I/O 设备，现在假设需要将起始内存地址为 813 的 80 个字节、起始内存地址为 1034 的 140 个字节、起始内存地址为 2000 的 60 个字节，写到磁盘中，如果使用 DMA 传输的话，就需要 3 次 DMA 传输，而使用通道传输的话，只需要 1 次即可
首先磁盘驱动程序构造 3 条通道程序指令，然后将这个 3 条通道程序指令，发送给通道，然后当前进程阻塞，内核调度其他进程使用 CPU，然后通道一条一条执行这 3 条指令，在通道执行执行指令的时候，CPU 可以执行其他的应用程序，比如，通道现在执行第一条指令，将 813 位置的 80 字节写到磁盘中，第 2 条指令，将 1034 位置的 140 字节写到磁盘中，第 3 条指令将 2000 位置的 60 字节写到磁盘中；当通道执行完所有的指令，发出一个中断信号，然后 CPU 执行中断处理程序，这里可能就是将阻塞的进程唤醒
可以这么说，通道就是一个微型的处理器，可以执行相应通道指令，这些通道指令，就形成了通道程序，通道是通过执行通道程序并与设备控制器共同实现对 I/O 设备的控制的，这样，通道就可以减少 CPU 的干预，减少到对一组数据块的读 (或写) 及有关的控制和管理为单位的干预
通道程序是由一系列通道指令 (或称为通道命令) 所构成的。通道指令与一般的机器指令不同，在它的每条指令中都包含 5 个字段：
  • ① 操作码：它规定了指令所执行的操作，如读、写、控制等操作
  • ② 内存地址：标明字符送入内存 (读操作) 和从内存取出 (写操作) 时的内存首址
  • ③ 计数：表示本条指令所要读 (或写) 数据的字节数
  • ④ 通道程序结束位 P：用于表示通道程序是否结束，P = 1 表示本条指令是通道程序的最后一条指令
  • ⑤ 记录结束标志 R：R = 0 表示本通道指令与下一条指令所处理的数据是同属于一个记录；R = 1 表示这是处理某记录的最后一条指令
