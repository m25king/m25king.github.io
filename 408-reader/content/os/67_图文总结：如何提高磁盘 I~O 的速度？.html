对于一个基于磁盘的文件系统的性能，至关重要的一个方面就是对文件的访问速度，为了提高对文件的访问速度，可以从以下三方面着手：
  1. 改进文件的目录结构以及检索目录的方法来减少对目录的查找时间
  2. 选取好的文件物理存储结构（连续结构、链式结构还是索引结构），以提高对文件的访问速度
  3. 提高磁盘的 I/O 速度，就是能将文件中的数据快速的从磁盘传送到内存中，或者相反

对于上面的第 1 点和第 2 点，我们已经在前面的第二章详细的讲解了，接下来，我们主要来介绍如何提高磁盘的 I/O 速度。提高磁盘的 I/O 速度有以下方法：
  • 使用磁盘高速缓存
  • 使用合适的 I/O 调度算法
  • 提前读和延迟写
  • 优化物理块的分配
  • RAID 技术

一、磁盘高速缓存（Disk Cache）

我们在计组中讲过高速缓存 Cache，是指在内存和 CPU 之间所增设的一个小容量高速存储器。而在这里所要介绍的磁盘高速缓存，是指在内存中为磁盘盘块设置的一个内存区域，在在这块内存区域中保存了某些盘块的副本，如下图：
上图中的文件 A 使用 10、14、20 号盘块存储数据，其中 14 号和 20 号盘块的数据缓存在磁盘高速缓存中。当应用程序要读取文件 A 的第二个盘块中的数据，那么先去磁盘高速缓存中查看是否已经缓存了 14 号盘块，如果在高速缓存中，便可从磁盘高速缓存中去获取，这样就省去了启动磁盘操作，可使本次访问速度提高几个数量级
如果要访问的盘块不在缓存中，才需要启动磁盘将所需要的盘块内容读入，并把所需盘块内容送给磁盘高速缓存，以便以后又需要访问该盘块的数据时，便可直接从高速缓存中提取
在这里你可能在脑海里会有若干个问题：
  • 第一个问题：内核是如何根据盘块号就知道对应的盘块是不是在磁盘高速缓存中？
  • 第二个问题：磁盘高速缓存的容量大小肯定是有限的，如何在有限容量的内存区域，高效的缓存很多盘块？
  • 第三个问题：如果应用程序修改了缓存中盘块的数据，那么缓存中的盘块数据和磁盘中盘块的数据就不一致了，这又如何是好？
对于第一个问题，以我们现在的知识储备，你可能还不能理解，因为这里涉及到了内存相关的知识，涉及到了内存映射，所以，在这里我们不要去追究这个，我们将在后面的虚拟内存章节再去深究
对于第二个问题，因为磁盘高速缓存容量有限，所以缓存会装满盘块数据，这个时候，就需要将其中某些盘块的数据先换出到磁盘中（也就是写到磁盘中，然后再缓存中释放这些盘块占用的内存空间），那么要将哪一些盘块换出呢？这里就涉及到置换算法了
对于置换算法，我们在计组中学习 CPU 高速缓存的时候，也涉及过集中置换算法，比如随机置换、LRU 置换算法等，在磁盘高速缓存中，比较常用的置换算法是 LRU，就是将最近最久未被访问的盘块换出到磁盘中，这里，我们了解到这里就可以了
对于第三个问题，缓存中的盘块数据和磁盘中的盘块数据可能会不一致，一般采用周期性写回到磁盘的做法，在 Linux 操作系统中，专门有一个后台 update 程序，它会周期性的将磁盘高速缓存中所有的盘块强制性的写回到磁盘中，一般这个周期是 30s 左右，这里，我们了解到这里就可以了

二、使用合适的 I/O 调度算法

磁盘 I/O 调度是操作系统对磁盘读写请求的处理顺序进行优化的机制。由于磁盘是机械存储设备（如传统 HDD 有物理磁头和盘片），磁头移动到目标位置需要时间（寻道时间），盘片旋转到目标扇区也需要时间（旋转延迟），这两个时间是磁盘 I/O 的主要开销
调度算法通过合理安排请求的执行顺序，减少磁头不必要的移动和等待，从而提高磁盘读写效率。简单来说，就像快递员规划送货路线：如果随机按订单顺序送货，可能绕很多路；但按区域顺路规划，就能节省时间，来看一个具体的例子
比如，现在有 3 个磁盘 I/O 请求，它们分别要访问 3 个盘块，这 3 个盘块的起始扇区所在的磁道分别是 1、9、2，假设现在磁头所在的磁道就是 1 号，如果按照 1、9、2 的顺序访问磁盘的话，需要移动 (9 - 1) + (9 - 2) = 15 个磁道，但是，如果我们将这三个磁盘 I/O 请求的顺序换成 1、2、9 的话，那么只需要移动 (2 - 1) + (9 - 2) = 8 个磁道，可以看到经过调整磁盘 I/O 处理的顺序，寻道时间变短了很多，这样就会提升磁盘 I/O 的性能

三、提前读和延迟写

如果是采用顺序访问方式对文件进行访问，便可以预知下一次要读的盘块。此时可采取预先读方式，即在读当前块的同时，还要求将下一个盘块 (提前读的块) 中的数据也读入缓冲区中。这样，当下一次要读该盘块中的数据时，由于该数据已被提前读入缓冲区，因而此时便可直接从缓冲区中取得下一盘块的数据，而不须再去启动磁盘 I/O,从而大大减少了读数据的时间，有效地提高了磁盘 I/O 的速度
延迟写是指缓冲区去盘块 A 中的数据本应立即写回磁盘，但考虑到该盘块 A 中的数据可能会在不久之后再被本进程或其它进程访问 (共享资源)，因而并不立即将该盘块 A 中的数据写入磁盘。只有当缓冲区快满了的时候，才将这个盘块 A 写到磁盘中。只要该盘块 A 仍在缓冲区中，任何访问该数据的进程，都可直接读出其中的数据而不必访问磁盘。这样，又可进一步减少磁盘的 I/O 时间

四、优化物理块的分布

在采用链接组织和索引组织方式时，可以将一个文件分散在磁盘的任意位置，但如果安排得过于分散，会增加磁头的移动距离。例如，将文件的第一个盘块安排在最里的一条磁道上，而把第二个盘块安排在最外的一条磁道上，这样，在读完第一个盘块后转去读第二个盘块时，磁头要从最里的磁道移到最外的磁道上。如果我们将这两个数据块安排在属于同一条磁道的两个盘块上，显然会由于消除了磁头在磁道间的移动，而大大提高对这两个盘块的访问速度
对文件盘块位置的优化，应在为文件分配盘块时进行。如果系统中的空白存储空间是采用位图方式表示时，要将同属于一个文件的盘块安排在同一条磁道上或相邻的磁道上是十分容易的事。这时，只要从位图中找到一片相邻的多个空闲盘块即可。但当系统采用线性表 (链) 法来组织空闲存储空间时，要为一文件分配多个相邻接的盘块就要困难一些。此时，我们可以将在同一条磁道上的若干个盘块组成一簇，例如，一簇包括 4 个盘块，在分配存储空间时，以簇为单位进行分配。这样就可以保证在访问这几个盘块时，不必移动磁头或者仅移动一条磁道的距离，从而减少了磁头的平均移动距离
优化物理块的分布除了可以减少平均寻道时间，还可以减少平均旋转时间，我们来看一个具体的例子，假设有 4 个记录（A、B、C、D）被存放在磁盘的某个磁道上，该磁道被划分成 4 块，每块存放 1 个记录，其布局如下图所示
现在要顺序处理这些记录。假定磁盘转速为 20ms/r，处理程序每次从磁盘读出一个记录后要花 5ms 对其进行处理，若磁头现在处于首个逻辑记录的始点位置，则请问：
（1）处理程序处理完这 4 个记录所花费的时间是多少？
（2）按最优化分布重新安排这 4 个逻辑记录，写出记录的安排顺序，并计算处理所需要的时间
对于第（1）问，因为磁盘旋转速度为 20ms/r，磁道划分为 4 块，每块存放一个记录，所以读出 1 个记录需要花费的时间是 20ms / 4 = 5ms，当花费 5ms 读出 A 记录后，现在 CPU 需要 5ms 的时候来处理这个 A 记录，因此处理 A 记录总共需要的时间是 5ms + 5ms = 10ms
在 CPU 处理 A 记录的同时，磁头往前旋转了 5ms，此时磁头来到了记录 C 所在的盘块，现在磁头需要再旋转 15ms（经过 C、D 和 A 所在的盘块）才可以来到 B 记录，然后再花费 5ms 读取 B 记录到内存缓冲区，然后 CPU 再花费 5ms 计算处理 B 记录，所以顺序读取并处理 B 记录花费的总时间是 15ms + 5ms + 5ms = 25ms
在 CPU 处理 B 记录的同时，磁头往前旋转了 5ms，此时磁头来到了记录 D 所在的盘块，现在磁头需要再旋转 15ms（经过 D、A 和 B 所在的盘块）才可以来到 C 记录，然后再花费 5ms 读取 C 记录到内存缓冲区，然后 CPU 再花费 5ms 计算处理 C 记录，所以顺序读取并处理 C 记录花费的总时间是 15ms + 5ms + 5ms = 25ms
在 CPU 处理 C 记录的同时，磁头往前旋转了 5ms，此时磁头来到了记录 A 所在的盘块，现在磁头需要再旋转 15ms（经过 A、B 和 C 所在的盘块）才可以来到 D 记录，然后再花费 5ms 读取 D 记录到内存缓冲区，然后 CPU 再花费 5ms 计算处理 D 记录，所以顺序读取并处理 D 记录花费的总时间是 15ms + 5ms + 5ms = 25ms
所以顺序处理程序处理完这 4 个记录所花费的时间是 10ms + 25ms + 25ms + 25ms = 85ms。从上面我们可以看出，记录在连续的挨着的物理块中存储，在 CPU 处理计算一个记录的时候，磁头刚好会划过下一个需要处理计算的记录所在盘块，接下来读取下一个需要处理的记录盘块时，磁头需要重新旋转一圈才可以找到，这样增加了很多的旋转时间，我们可以通过优化记录占用的物理块分布来减少平均旋转时间
对于第（2）问，我们可以这样优化，看下图，将 A、C、B、D 记录分别保存在相同磁道的 1、2、3、4 号盘块中
现在花费 5ms 从磁盘中读取记录 A，然后 CPU 花费 5ms 处理计算记录 A（处理 A 总共付费 5ms + 5ms = 10ms），同时磁头经过 5ms 旋转到了保存了记录 B 的 3 号盘块，可以直接读取记录 B（花费 5ms），然后 CPU 花费 5ms 处理计算记录 B（处理记录 B 总共花费 5ms + 5ms = 10ms），同时磁头经过 5ms 来到了记录 A 所在的 1 号盘块，需要再经过 5ms 的旋转，磁头才可以到达接下来需要处理的记录 C 的 2 号盘块，然后 5ms 读取记录 C，CPU 经过 5ms 处理记录 C（处理 C 总共花费 5ms + 5ms + 5ms = 15ms），同时磁头经过 5ms 来到了记录 D 所在的 4 号盘块，直接 5ms 读取记录 D，CPU 花费 5ms 处理计算记录 D（处理 D 总共花费 5ms + 5ms = 10ms），所以，这种情况下顺序处理 4 个记录总共花费时间是 10ms + 10ms + 15ms + 10ms = 45ms，这个远远小于上面没有优化物理块的分布情况下的处理时间
