我们如果写一个 C 语言程序，要想运行的话，肯定有 main 函数，对吧，然后将含有 main 函数的 C 程序，编译成指令，然后可以直接运行，而操作系统主要也是由 C 语言实现的，编译后，也就是一堆的指令和数据，而操作系统中没有 main 函数，那么操作系统是从哪里开始执行的呢？
我们知道，在计算机启动之前，操作系统的指令和数据是存放在磁盘中的，当开机时，操作系统的指令和数据会被加载到内存中，然后经过操作系统的一些初始化操作之后，操作系统就常驻在内存中，我们也可以将其称为内核程序，如果没有任何应用程序的执行，没有任何的事件发生的话，CPU 就一直执行操作系统中的一个空指令，也就是 nop 指令，此时操作系统就静静地在这里等待某个事件的发生，什么事件呢？
比如，当你从键盘中输入字符，会给 CPU 发送一个中断信号，然后让 CPU 区执行键盘中断服务程序，而这个键盘中断服务程序就属于操作系统中的一部分，它存储在内存中，将 PC 设置为中断服务程序中的首条指令的地址，然后开始执行键盘中断服务程序中的指令，那么这种键盘输入字符就属于一个事件。再比如，你点击以下鼠标，也会给 CPU 发送一个中断信号，然后让 CPU 区执行鼠标中断服务程序中的指令，这种点击鼠标也属于一个事件
很明显，一台计算机上会有很多的 I/O 设备，每个 I/O 设备都有可能发出中断，那么在操作系统中都会有对应的中断服务程序，这些外部中断都属于一个事件。再比如，计算机系统中有一个时钟，它会周期性的发出时钟中断，当 CPU 捕捉到了时钟中断，CPU 会去执行时钟中断服务程序，时钟中断可以实现时间分片技术，这样就可以实现分时系统，在时钟中断服务程序中，会更新系统时间，实现进程的调度，以及处理一些定时任务
除了外部中断是操作系统等待的事件之外，还有内部异常也是事件，比如，当 CPU 执行除法指令的时候，出现了除 0 异常，那么 CPU 会跳转去执行内核中的除 0 异常服务程序，再比如未定义指令异常、缺页异常等内部异常都属于一个事件
可以这么说，现代操作系统就是事件驱动的，如果计算机中没有任何事件发生的话，那么 CPU 执行 nop 空操作指令，操作系统静静的在那里等待事件的发生，一旦某个中断或者异常事件发生了，CPU 就去执行操作系统中相应的中断或者异常服务程序
实际上还有一类事件，就是系统调用，系统调用也属于内部异常，比如，现在计算机系统上除了运行着操作系统之外，还运行着一个应用程序 A，如果此时应用程序 A 需要将数据写到磁盘中（看下图），也就是说需要访问磁盘
我们前面说过，操作系统管理者 I/O 设备，包括磁盘，所以，访问磁盘时需要经过操作系统，那么，这个时候，应用程序 A 就需要调用内核中的写磁盘的程序，来访问磁盘，这里应用程序 A 调用内核中的写磁盘程序的过程，就属于一个系统调用的过程，也就说，如果发生了系统调用的话，也是会去执行内核中的程序指令的，对于系统调用，我们稍后会详细的讲
从上面可以看出，操作系统内核其实就是由很多的异常/中断服务程序和系统调用服务程序组成的，我们再学习操作系统，其实就是再学习各种各样的异常、中断和系统调用服务程序而已
