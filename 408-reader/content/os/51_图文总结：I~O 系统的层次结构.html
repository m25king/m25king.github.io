I/O 系统由 I/O 软件和 I/O 设备（硬件）等组成。I/O 软件涉及的面很宽，向下与硬件密切关联，向上又与文件系统、虚拟存储器系统和用户直接交互，它们都需要 I/O 系统来实现 I/O 操作。为使复杂的 I/O 软件能具有清晰的结构、更好的可移植性和易适应性，目前已普遍采用具有层次结构的 I/O 系统，该结构是将 I/O 系统中的设备管理模块分为若干个层次，每层都是利用其下层提供的服务来完成 I/O 功能中的某些子功能的，并且会屏蔽这些功能实现的细节，向上层提供服务
通常把 I/O软件组织成 4 个层次，它们包含于下图所示的 I/O 系统的层次结构中，图中的箭头表示 I/O 的控制流
用户层软件，用于提供与用户交互的接口，用户可直接调用该层所提供的与 I/O 操作有关的库函数或者系统调用对设备进行操作
设备独立性软件（也称为与设备无关的 I/O 软件），用于实现用户程序与设备驱动程序的统一接口、设备命名、设备保护以及设备的分配与释放等，同时为设备管理和数据传输提供必要的存储空间，对于上图设备独立软件的功能（映射、保护、分块、缓冲、分配）在后续我们会一一学习
设备驱动程序，与硬件直接相关，用于执行系统对 I/O 设备发出的操作指令，换言之，是驱动 I/O 设备工作的驱动程序
中断处理程序，用于保存被中断进程的 CPU 现场环境，保存完成后转入相应的中断处理程序处理中断，处理完成后再恢复被中断进程的 CPU 现场环境，最后返回被中断进程
对于用户层软件和中断处理程序很好理解，但是对于设备独立性软件和设备驱动程序可能你还不太理解，接下来，我们就以前面第二章学习过的磁盘文件系统来详细解释下什么是设备驱动程序，什么是设备独立性软件

什么是驱动程序？

看下图，有一个 I/O 设备 - 磁盘，这个磁盘对应的设备文件是 /dev/vda，磁盘通过磁盘控制器，在通过 I/O 总线和主机相连，磁盘被分成了 4 个分区，假设在分区 2 上创建了我们在上一章实现的简单文件系统，并且挂载到了根目录上，盘块大小 4KB，此时在内核中的挂载表（看下图）中，就有一项记录，在根目录下挂载了磁盘分区 /dev/vda2 的文件系统 VSFS

在文件系统中还有一个系统级打开文件表，维护着整个系统中打开的文件，下图 inode 号为 1 的是根目录的 inode，根目录的所有目录项存放在 23 号盘块中，目前根目录的所有目录项缓存在目录项缓存中；上图 inode 号为 9 的是文件 /a.txt 的 inode，包括文件属性以及数据块所在盘块的盘块号，这个文件的数据保存在 40 号和 48 号盘块中
上图在用户态运行着一个应用程序 A，在内核中维护着这个应用程序对应的 PCB，在 PCB 中有个指针指向这个进程打开的文件表，假设这个进程已经打开了 /a.txt 这个文件，其对应的文件描述符是 0， 读写指针是 0，文件指针指向系统级打开文件表第二个表项，同时在通用层为 /a.txt 文件分配了对应的 I/O 内核缓冲区
现在应用程序 A 发起一个磁盘 I/O，执行 read(0, buff, 4096)，读取文件描述符为 0 的文件 4KB 的数据，文件描述符为 0 的文件，其实就是这个 /a.txt 文件，因为现在文件 /a.txt 的读写指针是 0，然后要读取 4KB 的数据，所以应用程序 A 是想读取 /a.txt 文件中的前 4KB 的数据，来看下这个 read 的步骤
首先找到应用程序 A 的 PCB，然后通过文件描述符 0，找到打开的文件的 inode，在 /a.txt 的 inode 中存放了存放数据的盘块的盘块号 40 和 48，应用程序需要读取前 4KB 的数据，也就是要读取 40 号盘块中的数据，先去通用层的盘块缓存中查找 40 号盘块，如果找不到，再去磁盘中读取 40 号盘块，接下来通用层要计算 40 号盘块对应的逻辑扇区号
因为 a.txt 是在根目录下，而根目录上挂载的是 /dev/vda2 上的文件系统（查挂载表得到），所以文件 a.txt 中的数据肯定是存储在 /dev/vda2 这个设备上，即 40 号盘块，位于磁盘分区 2 上，我们知道文件系统中还有一个超级块，文件系统挂载时，会将这个超级块加载到内存中，在超级块中可以拿到磁盘扇区大小（假设是 512 字节）和分区 2 的起始扇区号（假设是 1000），然后在通用层就可以通过下面的公式计算得到分区 2 中的  40 号盘块的逻辑扇区号是 1320
接下来需要计算这个逻辑扇区号，对应磁盘的磁头号、磁道号以及扇区号，也就是说需要计算 1320 号逻辑扇区对应的物理扇区地址，要计算物理扇区地址，需要知道这个磁盘设备包含的盘片数、每个盘片有多少磁道，每个磁道有多少扇区，而磁盘设备的这些信息一般是由对应的磁盘驱动程序维护的，当操作系统启动时，磁盘驱动程序会去查询对应的磁盘设备的状态信息，所以只能在磁盘驱动程序中来计算逻辑扇区号对应的物理扇区地址（看下图的磁盘驱动程序）
假设这个磁盘有 4 个盘片，每个盘片 200 个磁道，每个磁道有 300 个扇区，假设采用盘面优先分配，那么磁头号 =  ⌊1320 / (200 * 300)⌋ = 0，磁道号 =  ⌊ (1320 % (200 * 300)) / 300⌋ = 4，扇区号 = (1320 % (200 * 300)) % 300 = 150，因此逻辑扇区号 1320 对应的磁盘物理地址是（磁头号 = 0，磁道号 = 4，扇区号 = 120）
接下来将这个物理扇区地址发给磁盘控制器的 DAR 寄存器（看下图），用于寻道、旋转，定位数据，这里采用 DMA 传输数据，所以还需要设置 DMA 的一些参数，比如，从文件 /a.txt 读出来的数据需要暂存在上图的 I/O 内核缓冲区中，那么就需要告诉 DMA 数据传送目的主存地址（将主存地址设置到下图的 AR 寄存器中），还有就是要读取多大的数据（即设置下图的 WC 寄存器）
这些计算机磁盘扇区物理地址以及设置磁盘控制器中的寄存器的值都是由 CPU 执行磁盘驱动程序来实现的，接下来，当前进程就阻塞在驱动程序这里，也就是挂在这里，等待 DMA 将数据传输完，当 DMA 数据传输结束，会发出一个 DMA 结束的中断信号，然后 CPU 执行 DMA 结束的中断服务程序，在中断服务程序中，通知进程，数据已经放到相应的 I/O 内核缓冲区，接下来进程继续执行，将内核缓冲区的数据块，先缓存到盘块缓存中，然后再拷贝到用户态对应的缓冲区中，这样就完成了一次磁盘 I/O

什么是独立性软件？

上面的磁盘驱动程序和磁盘的中断服务程序是和具体的磁盘设备有关的，你看磁盘驱动程序，需要知道磁盘的物理结构（盘面、磁道、扇区），对吧，如果存储设备是固态硬盘的话，就不是这种物理结构，那么如何理解上面的通用块层呢？
我们现在将底层的硬件换成了固态硬盘，它和固态硬盘控制器连接，假设不用 DMA 功能，而是通过中断传输数据，同样，也是在分区 2 上创建了 VSFS 文件系统，挂载到了根目录，只不过这时的设备名称是 /dev/sda2（看下图的挂载表）
我们知道固态硬盘的结构和机械磁盘的结构完全不同，但是我们还是要将分区 2 的 40 号盘块对应的逻辑扇区号计算出来，注意，这里也可以称为逻辑扇区号，也可以称为逻辑页号，我们知道固态硬盘的单位是页，这个页也可以称为扇区，一个意思，但是，将逻辑扇区号计算固态硬盘的物理地址的逻辑肯定和磁盘驱动程序计算逻辑不一样，现在假设从文件系统超级块中，拿到固态硬盘的页大小是 4KB，分区 2 从 100 号页开始，那么可以通过下面公式计算得到逻辑扇区号就是 140
接下来，执行固态硬盘对应的驱动程序，来计算 140 号逻辑扇区对应的物理地址，这个逻辑还是很复杂的，我们就不具体深究了，总之这里肯定和机械磁盘的不一样，这里还需要根据固态硬盘的磨损策略来计算，我们假设对应的物理地址是 280，接下来，就将 280 发给固态硬盘控制器，然后发出读命令，当前进程就挂在固态硬盘驱动程序这里，此时固态硬盘正在准备数据，准备好了，发出中断信号，然后 CPU 执行对应的固态硬盘中断服务程序，中断服务程序将数据读入到指定的 I/O 内核缓冲区，数据传输完后，会通知当前进程，让它继续执行，将数据放到缓存，并且拷贝到应用程序缓冲区，这样就完成了一次 I/O
这里的固态硬盘的驱动程序，执行和固态硬盘这个设备有关的一些逻辑，并且和固态硬盘的控制器进行通信，除了驱动程序，这个中断服务程序也是和设备有关的，而通用层和设备无关，所以可以称为通用块层，这种和设备无关的程序，也称为设备独立性软件，上面的通用层属于设备独立性软件，上面的文件系统也属于设备独立性软件，这些软件都是与具体设备无关的
